# 基模团队预训练岗位面试问题清单

本清单面向文本与代码基模的预训练研究、算法和工程岗位，兼顾多语言、长上下文与大规模训练。问题按从目标定义到训练验收的顺序组织；题号固定，便于后续逐题讨论。场景中的模型规模、算力和数据量都是面试假设。

## 1. 目标、训练任务与实验设计

- **Q01** 团队要训练一个同时服务中文、英文和代码场景的基础模型。你会在开训前如何定义成功标准、资源边界和必须固定的评测集？
- **Q02** 给定长短不一且含 padding 的 token 序列，你会如何定义自回归预训练的标签、损失归一化方式与有效训练 token 数？如何检查实现与定义一致？
- **Q03** 一个已完成通用预训练的基模需要增强医学知识和医学问答能力；团队拿到医学文章、术语表和问答记录。你会如何安排继续预训练与监督微调，并验证各阶段的边际价值？
- **Q04** 两次实验同时更换了数据、tokenizer 和模型结构，第二次指标更好。你会怎样重新设计实验，判断收益来自哪里？
- **Q05** 你会如何设置预训练过程中的验证语料、任务评测频率和模型选择规则，以便及时发现退化，同时避免反复对同一公开基准调参？

## 2. 数据构建、筛选与配比

- **Q06** 在训练 token 预算固定、目标覆盖中文、英文、代码和数学的条件下，你会怎样制定数据来源计划，并记录每类数据的来源与使用限制？
- **Q07** 从多来源语料中抽取固定长度训练窗口时，按文档等概率、按已分词 token 等概率，以及按压缩文件字节数分配预算，会产生怎样不同的曝光分布？你会如何选择？
- **Q08** 你拿到已经下载的 Pile 压缩分片，只有两天时间做第一轮小规模训练。你会优先进行哪些数据审计，产出哪些统计与样本？
- **Q09** 同一套清洗规则使网页文本看起来更整齐，却损害了代码和论文语料。你会如何定位问题并重新设计处理流程？
- **Q10** 你会如何决定精确去重、文档近重复去重和片段去重各自的粒度、阈值与作用范围？如何处理跨训练和评估集的重叠？
- **Q11** 更强的去重提高了平均评测分数，却降低了低资源语言和长尾知识表现。你会如何判断这个结果是否值得接受？
- **Q12** 一个网页质量分类器筛掉了 70% 的文档，但下游能力没有改善。你会如何调查分类器、数据分布和训练实验？
- **Q13** 某个语料源的训练损失很低。你会如何判断是否应该提高它的采样权重？
- **Q14** 一小批高质量数学文本会被反复采到，而另一批质量一般的新文本几乎没有重复。你会如何比较两种选择的边际价值？
- **Q15** 你会在什么情况下使用随训练进度变化的数据混合比例？如何设计实验，判断动态配比是否优于固定配比？
- **Q16** 团队计划加入教师模型生成的代码和数学内容。你会如何确定生成规范、核验方式、加入比例与退出条件？
- **Q17** 公开基准题可能散落在网页、代码仓库和合成文本中。你会如何在训练前建立去污染流程，并评估误删与漏检？
- **Q18** 数据源包含个人信息、密钥或权利状态不明确的内容。你会怎样制定保留、遮盖、删除及追溯规则？
- **Q19** 训练已过半，团队发现某批代码文件大量重复同一触发短语，怀疑存在数据投毒。你会如何查证其训练曝光、评估模型行为并决定处置？

## 3. Tokenizer 与训练样本组织

- **Q20** 如果 tokenizer 也由团队自己训练，你会如何选择词表训练样本，并评估它对不同语言、代码和数学文本的影响？
- **Q21** 在总训练算力固定时，把词表从 32K 扩大到 128K 可能改变哪些训练与推理成本？你会用什么实验决定是否扩表？
- **Q22** 两个模型使用不同 tokenizer，在同一份文本上的平均 token loss 分别为 1.8 和 2.0。你会如何比较它们的语言建模能力，并说明这些数字能支持何种结论？
- **Q23** 相同内容的中文技术文档平均比英文版本多用 2.5 倍 token，代码中的缩进和数字也被异常切碎。你会如何判断 tokenizer 是否是能力瓶颈？
- **Q24** 训练进行到一半，团队发现现有 tokenizer 对目标语言切分很差。你会比较哪些补救方案，以及如何估计改动的代价？
- **Q25** 为提高训练效率，你把多个文档打包进同一个序列。你会如何处理文档边界、损失计算、注意力行为与可复现的数据顺序？

## 4. 模型结构与上下文长度

- **Q26** 在相同训练 FLOPs 下，你会如何比较稠密模型与 MoE 模型，并把推理成本、路由行为和实际集群效率纳入决策？
- **Q27** 为目标模型选择 MHA、GQA 或 MQA 时，你会比较哪些训练、长上下文和部署指标？
- **Q28** 计划将模型的有效上下文从 4K 扩展到 32K。你会怎样设计位置表示、训练长度分布和验证方案？
- **Q29** 模型通过了长上下文“针插入”测试，却无法稳定完成长文档问答。你会如何定位两种结果之间的能力差距？
- **Q30** 对代码预训练，团队想加入 fill-in-the-middle 目标。你会如何设计与标准下一 token 训练的对照实验？
- **Q31** 在每步 token 数不变的情况下，把序列长度从 4K 提高到 32K，训练显存、吞吐和样本分布会如何变化？你会怎样衡量收益是否抵得过成本？
- **Q32** 在参数量和训练 FLOPs 大致相同的 Transformer 配置中，你会如何比较深度、宽度、归一化与初始化方案对质量和稳定性的影响？

## 5. 规模规律、优化与数值稳定性

- **Q33** 给定固定训练 FLOPs、可用数据量和推理成本目标，你会如何选择模型参数量与训练 token 数？
- **Q34** 假设训练一个 70B 参数模型、使用 1T token。请自行设定 GPU 型号、卡数、单卡持续有效 FLOP/s 和故障开销，估算理论计算量、总 GPU 小时与实际墙钟时间；哪些假设最影响结果？
- **Q35** 只有少量小模型实验结果时，你会如何预测某个数据或架构改动在目标规模上的收益，并表达外推的不确定性？
- **Q36** 在总训练 token 预算不变的条件下，团队把梯度累积步数提高八倍，其他 batch 组成不变。你会如何判断新的全局 batch 是否需要改变优化配置？
- **Q37** 第 12 万步出现全局 loss spike，而少数 rank 的本地 loss 或梯度监控更早异常。你会怎样定位最早的故障并决定是否回滚？
- **Q38** 团队想引入 FP8 混合精度训练以提高吞吐。你会如何验证速度收益、数值稳定性和最终模型质量？
- **Q39** 小规模实验得到一套学习率预热与衰减、权重衰减和梯度裁剪配置。你会如何验证它迁移到目标规模后仍然合适？

## 6. 分布式训练、性能与可靠性

- **Q40** 一次训练使用 64 张 GPU，张量并行度为 4，流水线并行度为 2；每个数据并行副本的微批次为 2 条 4096-token 序列，梯度累积 8 次。全局 batch 有多少输入 token？
- **Q41** 你有 8 个节点、每节点 8 张 80GB GPU，节点内互连快于节点间网络，计划训练 8K 上下文的 70B 稠密模型。你会先确认哪些额外约束，再提出并行映射与预期瓶颈？
- **Q42** 在 BF16 权重与梯度、FP32 主权重与 AdamW 状态的训练配置下，你会怎样估算参数相关显存与每卡显存需求？计算前还需要确认什么？
- **Q43** 监控工具报告 GPU busy 比例接近 100%，但模型 FLOPs 利用率很低。你会先采集哪些证据来定位瓶颈？
- **Q44** 模型、精度、序列长度和全局 batch 保持不变，GPU 数量从 64 增至 256，端到端 token 吞吐只提高了 1.8 倍。你会怎样拆解扩展效率损失？
- **Q45** 训练数据总量达数百 TB，必须从远端存储流式读取。你会如何设计并验证一条可扩展、可复现、不会长期让 GPU 等待数据的读取管线？
- **Q46** 一个能够可靠恢复预训练的 checkpoint 应包含哪些状态？你会如何确认恢复后没有重复或跳过训练数据？
- **Q47** 一次同步 checkpoint 会阻塞训练 8 分钟，这项任务平均每 48 小时需要故障恢复一次。你会如何决定保存间隔并估算相应成本？
- **Q48** 分布式 checkpoint 写到一半时某节点失效。你会如何确保下次恢复读取的是同一步的完整状态？
- **Q49** 平均 step 时间正常，但 step 耗时的 P99 持续上升，最终频繁出现 collective timeout。你会怎样确定性能退化的根因？

## 7. 评测、归因与异常诊断

- **Q50** 训练损失持续下降，通用能力评测却停滞甚至下降。你会建立怎样的诊断路径与最小对照实验？
- **Q51** 英文评测提升、中文评测下降。你会收集哪些证据，并设计什么实验来定位原因？
- **Q52** 加入大量代码后，代码验证损失降低，但代码生成任务几乎没有改善。你会如何设计下一轮实验？
- **Q53** 某次数据更新后，一个公开 benchmark 的分数突然大幅上升。你会怎样建立证据链、界定受影响的检查点和指标，并决定该结果是否仍可使用？
- **Q54** 加入合成数学数据后，训练损失改善，但真实数学任务表现下降。你会收集什么证据，并怎样决定下一步实验？
- **Q55** 相同配置的两次大规模训练得到明显不同的损失曲线。你会怎样界定可接受的随机波动，并追查不可复现的来源？
- **Q56** 某项系统优化使吞吐提高 20%，但相同 token 数下验证损失变差。你会如何判断是否真的发生了训练语义变化？
- **Q57** 两个基础模型中，A 的预训练验证损失更低，但在同一套后训练流程后，B 的任务表现更好。你会如何设计调查？

## 8. 负责人级综合场景

- **Q58** 团队有 256 张 80GB GPU、六周训练窗口和约 1T 已获准使用的中英文及代码 token；在 4K 输入、512 token 输出、并发 32 的服务负载下，新模型每百万输出 token 消耗的 GPU 秒不得超过现有 7B 基线的两倍。你会如何制定从小规模试验到完整预训练的方案与阶段性决策点？
- **Q59** 训练运行到一半时，项目可用算力突然减少 30%。你会如何重新分配剩余预算，并判断哪些原定目标仍然可信？
- **Q60** 某个数据源被确认没有训练授权，而当前模型在前半程已经读到它；审计要求最终发布模型及其继承的 checkpoint 均未使用该来源。你会如何处理正在运行的任务、已有 checkpoint 与后续验收？
- **Q61** 在同预算、同 tokenizer、同一评测集与服务负载的试验中，路线 A 的验证损失低 3%、中文指标高 2 分，但服务时延高 30%；路线 B 的代码指标高 3 分、推理成本低 20%，这些任务指标在重复评测中的标准差约为 1 分。你会如何组织最终决策，并选择下一项实验？
