# 大语言模型预训练方法论与注意事项：基于 2024–2026 权威技术报告的系统调研

> **导读**：本文是一份面向大模型训练学习者与工程实践者的系统化调研，全部结论以 2024–2026 年间公开发布的 arXiv 技术报告、官方模型卡与系统性综述为资料基准，关键数字均回溯至一手原文核对。全文共 12 章：第 1 章给出预训练的目标定位、成本口径与多阶段范式全景，后续章节分别深入数据工程、架构与训练目标、超参与 scaling law、长上下文、工程稳定性等专题。阅读时请注意：前沿实验室对外披露的所有训练数字都带有口径限定（tokenizer、参数计数、成本范围），引用或比较前须先对齐口径。各章注意事项分散于第 2、3 章末节，全书共性误区与开训清单集中于第 11 章。

## 1. 预训练全景：目标、成本账本与多阶段范式

### 1.1 预训练在 LLM 生命周期中的位置

#### 1.1.1 预训练决定知识、语言与表征能力的主体；后训练改变能力可调用性与行为分布——两者优化不同分布上的目标

一个大语言模型的生命周期可划分为预训练（pre-training）、中训练（mid-training，见 1.2.2）与后训练（post-training，含监督微调 SFT 与强化学习对齐）三个阶段，三者在不同的数据分布上优化不同的目标。预训练以万亿级 token 的网页、书籍、代码语料为分布，用下一 token 预测（next-token prediction）目标把人类知识的统计结构压入模型权重——模型的知识储备、多语言能力、推理与代码的潜在表征都在这一阶段形成主体。后训练则在规模小数个数量级的指令与偏好数据分布上，改变这些已有能力的"可调用性"与输出行为分布，而非重新注入知识。这一分工的工程含义是：后训练无法弥补预训练阶段缺失的知识与表征，数据质量、配比与阶段课程等预训练决策决定了模型能力的上限。2025 年 10 月的首个中训练系统综述将三者的关系形式化为：预训练追求广度，中训练在预训练与 SFT 之间做数据分布调整、学习率调度与长上下文扩展，后训练负责行为对齐[^1^]。需要限定的是，上述"上限"一说仅在"后训练无法向模型注入新知识"的意义上成立：后训练对能力可调用性与行为分布的改造同样能改变实测表现的天花板——同一预训练底座经不同 SFT/RL 配方调出的基准表现可以有显著差距，故"上限"指知识与表征储备的上限，而非可观测分数的上限[^1^]。

#### 1.1.2 成本账本口径：DeepSeek-V3 全程 278.8 万 H800 GPU 小时（预训练 266.4 万），"预训练占 90%"不是普适常数，且不含失败实验与数据处理成本

DeepSeek-V3 是目前成本披露最完整的旗舰模型：全程训练 278.8 万 H800 GPU 小时，其中预训练 266.4 万（约 95.5%）、长上下文扩展 11.9 万、后训练仅 0.5 万；按每 GPU 小时 2 美元的租赁价折算约 557.6 万美元，相当于每 1T token 约 18 万 H800 小时[^2^]。这组数字支撑了"预训练占成本九成以上"的流行说法，但使用时必须注明三重口径：其一，该比例依赖具体模型的阶段划分——V3 把长上下文扩展单列，若并入广义预训练则占比更高，而 OLMo 2 的中训练占训练 FLOPs 的 5–10%，各家结构不同使"90%"不是普适常数[^3^]；其二，DeepSeek 在报告中明确声明该成本"不含前期研究与消融实验"（excluding the costs associated with prior research and ablation experiments），媒体叙事常省略此限定[^2^]；其三，GPU 小时跨硬件型号不可直接比价——作为对照，Llama 3 405B 官方模型卡披露训练累计 3,084 万 H100 GPU 小时（700W TDP，8,930 吨 CO₂ 当量），约为 V3 的 11 倍，但 dense 与 MoE 架构、H100 与 H800 的有效算力差异使两者不构成直接效率对比[^4^]。数据处理管线的人力与算力开销同样不在上述账本内。

### 1.2 从单阶段到多阶段课程的总趋势

#### 1.2.1 范式演变：LLaMA 1 固定配比 → Llama 3 scaling law 指导配比+退火 → Qwen3 三阶段；2024 年后前沿模型几乎全部多阶段化

2023 年前后的早期开源旗舰（如 LLaMA 1）采用"单一数据配比从头训到底"的单阶段范式；2024–2026 年的前沿模型几乎全部放弃了这一做法，转向"通用预训练 → 高质量退火/中训练 → 长上下文扩展"的多阶段课程（curriculum），预训练的"配方"从一张静态配比表演变为一份分阶段日程表[^1^]。演变的中间节点是 Llama 3（2024-07）：其 15T+ token（405B 为 15.6T）的初始预训练配比（约 50% 通用知识 / 25% 数学与推理 / 17% 代码 / 8% 多语言）由知识分类器与小模型 scaling law（尺度定律）实验确定，训练中动态调整，并在最后 40M token 上将学习率线性退火至 0、上采样极高质量数据源、对退火期间的 checkpoint 做 Polyak 平均；长上下文则单独用 6 个阶段从 8K 渐进到 128K、约 800B token，每阶段须通过"短上下文评测完全恢复 + needle-in-a-haystack 满分"双判据才获准进入下一阶段[^5^]。Qwen3（2025-05）则把阶段划分显性化为三阶段：S1 超 30T token 通用阶段（4K 序列，119 种语言）→ S2 约 5T 更高质量 token（上调 STEM/代码/推理/合成数据占比，并加速学习率衰减）→ S3 数千亿 token 长上下文阶段（32K 序列，75% 为 16K–32K 文本；RoPE base 用 ABF 从 10,000 提到 1,000,000）[^6^]。其理念是"先学广、再学深、最后学长"，比第一天就全数据超长上下文混训更省算力[^1^][^6^]。

多阶段化的动因是数万亿 token 噪声网页数据的边际收益递减：模型在推理、代码、长文任务上停滞，而退火阶段同时做两件事——学习率向 0 衰减以降低梯度方差、稳定收敛到良好极小值，数据分布切换到高质量精选/合成数据以提高每个 token 的边际价值[^1^]。需要注意退火收益存在规模依赖：Llama 3 的实验显示退火混入 GSM8K/MATH 训练集可使 8B 模型在对应验证集提升 24.0%/6.4%，但 405B 模型上收益可忽略[^5^]；而 OLMo 2 在 7B–32B 规模上中训练均带来约 10 分的平均提升[^3^]。两个结果并不直接矛盾——前者是混入基准同分布训练集的极端情形，后者是"预训练末 vs 中训练末"的整体干预——但共同提示：预训练越充分，退火的边际收益越小。此外，Qwen3 官方只给出 S3 的"hundreds of billions"量级，"约 500B"是综述的估计值，引用时应注意区分[^1^][^6^]。

#### 1.2.2 中训练独立化：OLMo 2/3 Dolmino、InternLM 2.5、Phi-4 中训练

退火阶段的学术化命名标志着范式固化。OLMo 2 报告明确说明"mid-training"一词采自 Phi 团队（Abdin et al. 2024）与 OpenAI（2024）的用法[^3^]，2025 年综述将其正式定义为介于大规模预训练与 SFT 之间的独立阶段[^1^]。代表性实践包括：

- **OLMo 2**（2024-12）：第二阶段中训练仅占 5–10% 训练 FLOPs，使用 Dolmino 混合（上采样最高质网页 + 精选非网页源 + 合成数学数据），学习率线性衰减到 0；7B 模型做 3 次 50B token 退火（不同数据顺序）后对权重做平均（souping）。效果是显著的：7B 平均开发集分数提升 10.6 分，GSM8K 从 24.1 升至 67.5，中训练后的 7B 超过仅做预训练的 13B[^3^]。
- **OLMo 3**（2025-12）将全流程开放为三段式 model flow：5.9T token Dolma 3 预训练 → 100B token Dolmino 中训练（从约 2.2T 高质量池采样，含合成数学、指令数据、元推理轨迹）→ 50B token Longmino 长上下文扩展至 65K[^7^]。
- **InternLM 2.5**（2025）：其中训练阶段沿用前代确立的三阶段课程——约 90% 步数用 ≤4K 数据，约 9% 步数做长上下文训练（其中 50% 仍为短文本以防短上下文能力退化，RoPE base 从 50,000 提到 1,000,000），第三阶段做能力专项增强[^8^]。
- **Phi-4**（2024-12）：14B 模型约 10T token 预训练后，中训练专做上下文扩展（4K→16K，共 250B token，混合为 30% 新筛长上下文数据 + 70% 预训练 recall token），消融发现原生长文数据优于人工拼接的长样本，最大学习率较预训练降低 10 倍[^9^]。

这些案例共同沉淀出阶段分工的通用模板：通用预训练求广度（网页为主，占 90% 以上 FLOPs）→ 中训练求深度（高质量/STEM/代码/合成数据，占 5–10% FLOPs，典型规模 50B–500B token）→ 长上下文扩展单独成段。续训阶段的学习率不应重启高位：DeepSeek-V3 的两阶段 YaRN 扩展直接使用与预训练末对齐的 7.3×10⁻⁶，Phi-4 则主动将峰值学习率降 10 倍[^2^][^9^]。

下表汇总五个代表性模型的预训练配方要点，作为后续各章深入讨论的对照基准。token 量为各报告口径（依赖各自 tokenizer，不可直接互比）。

| 模型（报告时间） | 总参/激活参数 | 架构 | 预训练 token 量 | 阶段结构 | 训练精度 | 特色技术 |
|---|---|---|---|---|---|---|
| Llama 3 405B（2024-07） | 405B / 405B | Dense | 15T+（多语；405B 为 15.6T） [^5^] | 初始预训练（配比约 50/25/17/8，动态调整）→ 预训练末 40M token 退火 → 6 阶段长上下文续训 8K→128K（约 800B） [^5^] | BF16（梯度 FP32 累加） [^5^] | scaling law 指导配比；batch 4M→8M→16M 爬坡；退火兼作数据质量评估工具；Polyak 平均 [^5^] |
| DeepSeek-V3（2024-12） | 671B / 37B | MoE（MLA） | 14.8T（"in our tokenizer"口径） [^2^] | 单阶段主体预训练（4K）→ 两阶段 YaRN 扩展 4K→32K→128K（各 1,000 步） [^2^] | FP8（E4M3）混合精度 [^2^] | 细粒度 FP8 量化 + FP32 提升累加；DualPipe；扩展阶段 LR 与预训练末对齐 [^2^] |
| Qwen3（2025-05） | 235B / 22B（旗舰） | MoE | 36T，119 种语言 [^6^] | 三阶段：30T+ 通用（4K）→ 5T 高质量（加速 LR 衰减）→ 数百亿 token 长上下文（32K） [^6^] | BF16 混合精度 | RoPE ABF（10K→1M）；推理期 YaRN + Dual Chunk Attention 4 倍外推 [^6^] |
| Kimi K2（2025-07） | 1.04T / 32B | MoE（MLA，384 专家 top-8 + 1 共享） | 15.5T [^10^] | 主体预训练 → 长上下文扩展（400B@4K + 60B@32K + YaRN 至 128K） [^10^] | BF16 混合精度 | MuonClip 优化器（Muon + QK-Clip，τ=100）；全程零 loss spike（厂商自报） [^10^] |
| OLMo 2（2024-12） | 7B / 13B / 32B | Dense | 7B：3.9T（OLMo 2 Mix 1124） [^3^] | 两阶段：预训练（≥90% FLOPs）→ Dolmino 中训练（5–10% FLOPs，LR 线性退到 0） [^3^] | BF16 混合精度 | 多次退火 + 权重平均（souping）；microannealing 低成本评估数据源；数据与配方全开放 [^3^] |

**解读**：横向对比可见三条结构性趋势。其一，旗舰规模全面倒向 MoE——五个模型中三个为稀疏激活架构，激活参数仅约为总参的 3%–10%（Qwen3 235B/22B≈9.4%、DeepSeek-V3 37B/671B≈5.5%、Kimi K2 32B/1.04T≈3.2%），以约 1/33（K2）到 1/18（V3）的激活占比换取更大的参数容量，dense 仅保留在 405B 以下的规模段；其二，token 预算持续通胀，从 OLMo 2 的 3.9T 到 Qwen3 的 36T 相差近一个数量级，但由于各家 tokenizer 压缩率不同（DeepSeek-V3 明确标注"in our tokenizer"），这些数字不构成严格意义上的训练量排序；其三，阶段结构高度趋同而细节分化——所有模型都把长上下文扩展拆为独立阶段且只占总算力的 1–5%，但在退火是否显性成段（Llama 3 的 40M token 收尾 vs Qwen3 的 5T S2 阶段）、精度路线（V3 激进 FP8 vs 其余 BF16 默认）、开放程度（OLMo 2 全开放 vs 其余不披露配比百分比）上差异显著。表中 Kimi K2 的"零 loss spike"与 DeepSeek-V3 的 FP8 误差数据均为厂商自报（归因限制见 9.3.2 节）[^2^][^10^]；Qwen3 与 Kimi K2、OLMo 2 的精度一栏为行业默认的 BF16 混合精度设置，调研材料未逐项核对到原文表述。

## 2. 数据工程 I：来源构成、清洗与质量过滤

预训练数据工程可拆成三层决策：来源构成（拿什么数据、各占多少）、清洗（如何把原始抓取变成可用文本）、质量过滤（留下的子集按什么标准选）。本章按此顺序展开，依据 Llama 3、FineWeb、DCLM、Nemotron-CC 等公开技术报告与数据集论文；去重算法的参数细节与基准去污染在第 3 章展开，本章只交代它们在流水线中的位置与作用。

### 2.1 数据来源构成与配比实况

#### 2.1.1 公开配比的稀缺样本与一处流传甚广的误传

主流预训练语料的来源类型可归纳为七类：网页（Common Crawl 系）、代码（GitHub/The Stack）、书籍、论文（arXiv 等）、百科（Wikipedia）、论坛/对话（Reddit、StackExchange）与合成数据[^5^][^11^]。但真正公开各类占比百分比的头部模型只有 Llama 3：其最终配比约为 50% 通用知识、25% 数学与推理、17% 代码、8% 多语言；该配比由两个工具共同确定——先用知识分类器把网页文档归类并降采样网络上过度代表的类别（如艺术与娱乐），再用小模型 scaling law（尺度定律）实验扫描候选配比[^5^]。其余厂商仅披露规模与语种数，配比本身已成为不公开的配方资产。

关于早期模型，社区长期流传"Gopher 训练数据约 40% 是书籍"的说法，与一手来源不符：Chinchilla 论文附录 Table A1 给出的 MassiveText 配比为 MassiveWeb 45%（Gopher 原版 48%）、Books 30%（原版 27%）、C4 10%、News 10%、GitHub 4%（原版 3%）、Wikipedia 1%（原版 2%）——书籍占比实为 27%–30%[^12^]。开源侧的复现数据同样说明配比数字只是配方的一小部分：RedPajama-V1 严格按 LLaMA-1 的公开描述复现出 1.2T token（Common Crawl 878B、C4 175B、GitHub 59B、arXiv 28B、Books 26B、Wikipedia 24B、StackExchange 20B），但训出的 7B 模型与原版 LLaMA-7B 仍有差距，论文作者明确指出"暗示原配方中某些关键细节缺失"[^11^]；AI2 的 Dolma（3T token）则以 Common Crawl 约 2.28T token（占比约 74.5%）为绝对主体，代码、论文、书籍等其余来源合计约四分之一[^13^]。换言之，来源分类、过滤强度与分类器定义等隐性细节，才是各家配比的真正差异所在。

#### 2.1.2 规模演进：从万亿级到 30T 量级

下表汇总 2022–2026 年代表性模型与语料的规模及构成要点：

| 模型 / 语料 | 发布时间 | 预训练 token 规模 | 已公开的构成要点 |
|---|---|---|---|
| Chinchilla / Gopher（MassiveText） | 2022 | 1.4T（Chinchilla 训练量） | Books 占 30%/27%，非传闻的 40% [^12^] |
| Llama 3 | 2024-07 | 15T+（405B 为 15.6T） | 50% 通用 / 25% 数学推理 / 17% 代码 / 8% 多语言 [^5^] |
| Qwen2.5 | 2024-12 | 18T | 由前代 7T 扩展，依靠数据过滤与配比调整 [^14^] |
| DeepSeek-V3 | 2024-12 | 14.8T | 提高数学与编程占比，扩展中英之外的多语言 [^2^] |
| Qwen3 | 2025-05 | 36T | 119 种语言；含 VL 模型从 PDF 识别及模型合成的数万亿 token [^6^] |
| Ling-2.5-1T | 2026-02 | 29T | 从前代 20T 扩展；1T 总参 / 63B 激活 [^15^] |

从 2022 年的约 1.4T 到 2025–2026 年的 30T 量级，名义规模增长约 20 倍，但增长的结构已经改变：新增 token 越来越多地来自"生产"而非"抓取"——Qwen3 用 Qwen2.5-VL 对 PDF 类文档做文字识别、再由 Qwen2.5 精修获得数万亿 token，另用 Qwen2.5/Math/Coder 合成教科书、问答、指令与代码类文本数万亿 token[^6^]。阅读此类数字需先确认口径：token 计数依赖具体分词器，DeepSeek-V3 明确标注其规模为"14.8T tokens in our tokenizer"[^2^]，同一文本在不同分词器下的 token 数可以有显著差异，跨模型比较前必须声明口径；此外"总规模"掩盖了唯一 token 数（去重后）与合成占比两个更重要的指标，后两者将在 2.3 节与第 3 章进一步讨论。

### 2.2 网页数据清洗流水线

#### 2.2.1 通用流水线：从 WARC 到可训练语料

综合 FineWeb、DCLM、Nemotron-CC 三条经消融验证的流水线，可归纳出共同骨架：从 WARC 原始 HTML 自提取正文 → URL/域名过滤 → 语言识别与过滤 → 启发式规则粗筛 → 模糊/精确去重 → 分类器精筛 → 发布前 PII 匿名化。各环节的代表性实现如下表：

| 环节 | FineWeb（15T）[^16^] | DCLM [^17^] | Nemotron-CC（6.3T）[^18^] | CCNet（2020）[^19^] |
|---|---|---|---|---|
| 正文提取 | trafilatura（优于官方 WET） | resiliparse（与 trafilatura 相当，快约 8 倍） | justext（高质量 token 产出 +28.6%） | 自建解析 |
| 语言过滤 | fastText，英文分数 ≥0.65 | fastText（英文） | fastText（英文） | fastText 语言识别 |
| 启发式 | MassiveText 式 + 改造版 C4 规则 + 3 条自定义（合计再删约 22%） | RefinedWeb 式 | 高质量分桶禁用启发式（避免误删 18.1% 好数据） | — |
| 去重 | 逐快照 MinHash（36T→20T） | Bloom filter（与 MinHash 效果相当，更易扩展） | 全局模糊去重 + 精确子串去重 | 段落级哈希去重 |
| 质量精筛 | 主数据集不用分类器；Edu 子集用蒸馏回归器 | fastText 分类器保留 top-10% | 三分类器集成取最大分 | KenLM 困惑度过滤 |
| PII 处理 | 发布版正则匿名化邮箱与公网 IP | 保留 WARC 映射以便响应删除请求 | — | — |

三条流水线对提取器的选择看似矛盾——FineWeb 选 trafilatura、DCLM 选 resiliparse、Nemotron-CC 选 justext——实则优化目标不同（精度、速度、高质量产出量），而一致结论是不要使用 Common Crawl 官方 WET 文本：DCLM 测得 resiliparse 与 trafilatura 相对 WET 至少带来 2.5 个 Core 分的提升[^17^]。去重粒度上，FineWeb 逐快照去重与 Nemotron-CC 全局去重方向相反，但各有明确的训练视界动机，该冲突的完整证据在第 3 章并列呈现。FineWeb 的另一个教训是启发式规则必须逐条消融：C4 的"行尾标点"规则单条会删除约 30% 的数据，FineWeb 据此将其移除[^16^]。

#### 2.2.2 完整性检查与文本规范化

清洗与去重的先后顺序有硬性约束：归一化必须先于去重。CCNet 在计算段落哈希前先对文本做小写、数字替换为零、标点移除等归一化[^19^]；若顺序颠倒，页眉页脚等模板噪声会使同正文的文档被判为不重复。

Unicode 规范化建议以 NFC（Normalization Form Canonical Composition）为默认：它只做 canonical 等价的合并，不改变文本语义。NFKC/NFKD 会额外做兼容性分解，把连字 ﬁ 折成 fi、上标 ² 折成 2、全角字符折成半角，属于有损变换[^20^]。因此 NFKC 只应作用于"用于匹配与去重的键副本"，不应无条件写回正式语料——数学符号、日文半角片假名等被折叠后不可恢复。URL 规范化同理：作为去重与统计的键时，建议统一协议与主机名大小写、去除默认端口、跟踪参数（utm_* 等）与 fragment，使同一正文的多个入口收敛为一个键。

工程上应同时保留 raw 与 canonical 两份数据：原始 WARC/HTML 与清洗后文本并存。DCLM-Pool 保留了与 WARC 记录的一一映射，以便响应 Common Crawl 的删除请求并支撑审计与复现[^17^]；FineWeb 也只在公开发布版上施加 PII 匿名化，内部分析使用未匿名化的副本[^16^]。只留清洗后单份数据的代价是：任何归一化规则的误判都无法回滚。

### 2.3 质量过滤方法论

#### 2.3.1 启发式规则 vs 模型打分

两类方法在实践中是叠加而非替代关系：启发式做粗粒度剔除，分类器做精细选择。DCLM 的控制实验将"基于模型的过滤"确认为构建高质量训练集的关键因素，其最优方案是一个 fastText 二分类器——正例取 OpenHermes-2.5 指令数据与 ELI5 高分帖，负例取 RefinedWeb 随机采样，按得分保留 top-10%——该组合胜过 PageRank、SemDedup、BGE 嵌入线性分类器、AskLLM 与困惑度过滤等全部备选[^17^]。关键变量是正例而非模型本身：不同的过滤模型/正例组合使 7B 规模的 MMLU 在 35%–44% 之间波动；OH-2.5+ELI5 正例比传统的 Wikipedia/书籍正例高 3.5 个 Core 百分点；DCLM 还报告"人类质量判断对识别高质量训练数据价值有限"[^17^]。用 DCLM-baseline 训练的 7B 模型在 2.6T token 后达到 64% MMLU（5-shot），比此前开放数据 SOTA MAP-Neo 高 6.6 个百分点且少用 40% 算力[^17^]。

2024 年后的主流范式是"大模型标注 → 蒸馏小打分器"。FineWeb-Edu 用 Llama-3-70B-Instruct 对约 46 万个网页打 0–5 的教育价值分（additive scale，聚焦中小学知识），再蒸馏为 Snowflake-arctic-embed-m 嵌入上的线性回归器（阈值 ≥3 时验证集 F1=82%）；花 6000 个 H100 GPU 小时把 15T 过滤到 1.3T，下游 MMLU 相对提升约 12%、ARC 约 24%[^16^]。Nemotron-CC 进一步把单一分类器换成集成：两个 FineWeb-Edu 式回归器（分别由 Mistral-8x22B 与 Nemotron-340B 标注）加 DCLM fastText，取三者最大分，将高质量 token 占比从 9% 提升到 25%[^18^]。Llama 3 的方案介于两者之间：fastText 识别"可能被 Wikipedia 引用"的文本，再用 Llama 2 生成的质量标签训练 DistilRoberta 分类器，并为数学/推理/代码单独建领域召回管线[^5^]。

需要同时呈现反面证据：2025 年"data-quality illusion"研究质疑了分类器质量过滤（classifier-based quality filtering, CQF）的基本假设——"训练数据应像 Wikipedia/书籍"未必改善下游表现[^21^]；DCLM 自己也发现，在已经强过滤的数据上再混入 Wikipedia/书籍等"高质量源"反而平均降低 1.6 个 Core 分[^17^]。分类器过滤有效，但"什么是高质量"并无先验答案。

#### 2.3.2 毒性 / PII / 隐私过滤的分层处理

公开实践呈现清晰的分层结构，各层阈值刻意保守。域名级粗滤：FineWeb 用 UT1 黑名单过滤成人内容域名[^16^]，Llama 3 过滤"可能含不安全内容或大量 PII 的网站"、按 Meta 安全标准评为有害的域名与成人内容域名，多语言数据同样施加[^5^]。分类器级句子过滤：Dolma 在 Jigsaw Toxic Comments 数据上自训 hate 与 NSFW 两个 fastText 分类器，删除得分超阈值的句子（约 1.01% 数据被标记），官方说明刻意选择很高阈值（>60% 有害概率）以避免误删非正式内容[^13^][^22^]。正则级 PII 掩码：Dolma 用正则掩码邮箱、电话与 IP，含 6 个及以上 PII 的页面整篇删除（占 0.11%）[^13^]；FineWeb 在发布版用正则匿名化邮箱与公网 IP[^16^]。两层免责说明值得引用：FineWeb 数据集卡坦承"最终数据集中仍可能存在相当数量有毒或有害文档"[^16^]——过滤是减损而非根除；Orion-14B 甚至刻意保留少量有害文本，理由是"完全移除有害文本可能导致模型无法识别和适当响应有害信息"[^23^]（单一模型报告，非主流共识，仅供参照）。

### 2.4 注意事项

1. **启发式规则会误删高质量内容，阈值须自行标定。** Nemotron-CC 测得其启发式过滤流水线误删了 18.1% 的高质量 token，因此对分类器判为高质量的分桶禁用启发式[^18^]；FineWeb 的经验是每条规则单独消融，C4 的"行尾标点"规则单条即会删除约 30% 数据[^16^]。选阈值应依据高/低质量对照样本的分布直方图系统取点，而非照搬旧配置。更一般地，每个过滤决策都应以小规模消融验证：FineWeb 为每个步骤训练 1.71B 消融模型（累计 70+ 个模型、约 8 万 H100 GPU 小时）[^16^]，DCLM 证明 400M 规模的数据排序与 7B 规模高度相关（r≈0.89–0.92），小规模迭代是可行的[^17^]。
2. **困惑度过滤对低资源语言有系统性偏差。** 以 Wikipedia 为参考训练的语言模型困惑度过滤，会保留"像 Wikipedia"的文本分布，系统性滤掉语言识别不可靠或参考语料过小的方言与低资源语言[^24^][^25^]。FineWeb2 的对策是按语言独立标定过滤阈值、用 GlotLID 做大覆盖语言识别，将流水线扩展到 1000+ 语言[^26^]；直接把英语流水线的阈值平移到其他语言是已知会失败的做法。
3. **"高质量"没有共识定义，分类器高分不等于下游有用。** "data-quality illusion"动摇了"像 Wikipedia/书籍即高质量"的假设[^21^]；DCLM 发现人类质量标注对筛选训练数据价值有限[^17^]；Nemotron 3 Nano 报告质量分类器会给无信息量的机器译文（日常对话、广告）打高分，需追加一轮 LLM 过滤再删 10.6% 的 token[^27^]。操作上，"高质量"只能以"小规模训练 + 下游基准"作操作化定义，并警惕过滤引入的分布偏移——FineWeb-Edu 的分类器系统性地改变了语料的主题分布[^16^]，过滤后应评估对目标域的覆盖，必要时回补专门语料。

## 3. 数据工程 II：去重与基准去污染

第 2 章的清洗解决的是"单篇文档内部的脏"，本章处理的是"文档之间的重复"与"训练集和评测集之间的泄漏"。这两个问题共享同一条底层逻辑：重复与污染都会让模型把容量花在记忆而非泛化上，并污染评估信号。不同的是，去重（deduplication）是训练者为自己做的，去污染（decontamination）是为评估可信度做的——二者的目标函数不同，工程取舍也随之分化，本章将两处存在立场分歧的"冲突区"并列呈现双方证据。

### 3.1 分层去重栈

#### 3.1.1 URL → exact hash → 段落级 → MinHash/LSH（FineWeb 黄金配置：词级 5-gram、112 hash、14×8 band、~0.75 Jaccard）→ 子串去重 → 语义去重（SemDeDup/D4 文本侧收益有限）

工业界的大规模语料管线已经形成由粗到细的多层去重栈，原则是"最便宜的先执行，逐层缩小后续昂贵算法的输入规模"，且去重必须放在文本归一化与清洗之后——页眉页脚等模板噪声会让正文相同的两篇文档在哈希层面被判为不同，直接击穿模糊去重 [^28^]。

| 层级 | 方法 | 代表配置 | 代表系统 | 成本与局限 |
|---|---|---|---|---|
| URL 去重 | 规范化 URL 精确匹配 | 去除同一 URL 的重复抓取 | 各 Common Crawl 管线通用 | 成本最低，最先执行；不处理跨 URL 镜像内容 |
| 文档级 exact 哈希 | MD5/SHA 或 Bloom filter | 文档级 + 段落级两档 | Dolma（Bloom filter）[^13^] | 只删逐字相同；Bloom filter 有可控假阳性 |
| MinHash/LSH 模糊近重复 | 词级 5-gram shingle，112 个哈希函数分 14 band × 8 hash，传递聚类（transitive clustering）后每簇随机保留一篇 | FineWeb（36T→20T token）[^16^] | 有效 Jaccard 阈值 ≈(1/b)^(1/r)，参数即阈值；对前置归一化高度敏感 [^28^] |
| exact 子串去重 | 全语料构建后缀数组（suffix array），删除 ≥50 token 的逐字重复子串 | Lee et al. 提出；RefinedWeb、MADLAD-400 采用；OLMo 3 以自研 Rust 工具 Duplodocus 分布式执行 | 后缀数组构建开销大；删除子串会破坏文档完整性 [^29^][^30^][^7^] |
| 语义去重 | 预训练模型 embedding → k-means 聚类 → 簇内余弦相似度超阈值判重，保留离簇心最远样本 | SemDeDup（LAION k=50,000）、D4（去重后重聚类 + 多样化剪枝）[^31^][^32^] | 文本侧收益有限（C4 仅省 10–15% 计算），FineWeb/Nemotron-CC/Dolma 3 均未将其列为标准步骤 |

这张栈表的两个要点容易被忽视。其一，MinHash/LSH 的"阈值"并非独立超参数，而是由 band 数 $b$ 与每 band 哈希数 $r$ 隐式决定（近似阈值 $(1/b)^{1/r}$）：FineWeb 的 14×8 配置针对 Jaccard 相似度约 0.75 设计，理论检出率在 Jaccard 0.5 时约 5%、0.75 时约 77%、0.9 时约 99.96% [^16^][^33^]。阈值每下调一档，误删"同主题但内容不同"文档的风险显著上升，这是中文工程实践中被反复报告的教训 [^34^]。其二，栈的末端——语义去重——在多模态场景收益巨大（SemDeDup 在 LAION-440M 上删 50% 数据几乎不掉点，训练提速约 2×；D4 在 6.7B OPT 上省约 20% 训练步且下游 16 任务平均 +2%），但在纯文本大规模预训练中收益迄今有限，且存在放大公平性偏差的风险报告，因此 2024 年后的主流文本语料均未采用 [^31^][^32^]。

#### 3.1.2 粒度之争：FineWeb 每快照独立去重（全局去重反转质量）vs Nemotron-CC 全局模糊去重——目标函数差异（冲突区，并列双方证据）

去重栈之上的一个更根本的问题是：在多大范围内判重？这里存在一组尚未收敛的对立实践。

FineWeb 对 96 个 Common Crawl 快照**各自独立**做 MinHash 去重，而非全局跨快照去重。其消融显示全局去重只带来很小的下游提升且远逊于 RefinedWeb 的做法；对最老快照（2013-48）的个案分析发现，全局去重最终保留的 10% 数据质量反而**低于**被删除的 90%——老内容跨快照近重复极多，全局判重下幸存的样本集中在广告、关键词堆砌等低质页面，即全局去重在最后一次快照中系统性地"上采样"了低质数据。FineWeb 的结论是"去重粒度会改变数据分布，去重并非天然有益" [^16^]。这一反直觉发现已被 2026 年的综述论文再次确认 [^35^]。

与之相反，Nemotron-CC 明确采用**全局**模糊去重，外加按快照 1/8 分片的 exact 子串去重。其动机是最大化唯一 token 量以支撑 15T token 的长 horizon 训练；Nemotron-CC 同时指出 FineWeb-Edu 与 DCLM 因只做分片近似去重，语料中仍含约 80% 模糊重复（分别仅约 0.2T/1T 唯一 token）[^18^]。

两种选择并不真正矛盾：FineWeb 优化的是短 horizon 下的数据质量（全局去重的质量反转陷阱在此为净负收益），Nemotron-CC 优化的是长 horizon 下的唯一 token 供给（此时每快照去重留下的跨快照重复等于浪费 epoch）。粒度决策必须先于算法决策：先确定训练 token 预算与计划 epoch 数，再决定判重范围 [^16^][^18^]。

### 3.2 重复数据的收益递减与记忆化

#### 3.2.1 Lee et al. 去重使逐字记忆降 10 倍；Muennighoff ≤4 epoch 近乎无损；Hernandez：0.1% 数据重复 100 次使 800M 退化为 400M 等效

去重的必要性最早由记忆化（memorization）研究量化。Lee et al.（ACL 2022）发现常见语料含巨量近重复——C4 中一句 61 词的英文句子重复超过 60,000 次；未去重模型在无 prompt 生成中有超过 1% 的输出逐字复制自训练集，而去重后记忆化输出下降约 10 倍，达到同等精度所需训练步数也更少，同时显著降低了 train-test overlap [^36^]。

重复数据"重复多少次才有害"存在两组看似张力十足的结论。Muennighoff et al.（NeurIPS 2023）训练 400 余个模型（10M–9B，最多 1500 epoch）拟合数据受限扩展律，发现**全量均匀**重复 ≤4 epoch 几乎无损（8.7B 模型 4 epoch 仅高 0.5% 验证 loss），数据重复的半衰期 $R_D^* \approx 15$，即约 16 epoch 后收益骤降，极端重复（44+ epoch）可致训练发散 [^37^]。Hernandez et al.（Anthropic, 2022）则给出强危害结论：即使 90% 数据唯一，仅把 0.1% 的数据重复 100 次即可使 800M 模型退化到 400M 模型的等效水平，机制上重复触发 epoch-wise double descent，记忆化吞噬模型容量并不成比例地破坏 induction heads 等泛化结构 [^38^]。两者并列后的可操作结论是：危害取决于重复的**频率分布**而非总量——均匀少量重复温和，小比例数据的高频重复危险，因此去重的重点应放在压平重复频率的长尾。顺带地，这一结论也支持用合成改写替代机械重复来制造"新鲜唯一 token"的做法：Nemotron-CC 将高质量文档 8 epoch 中的 4 epoch 换成 QA/蒸馏/知识抽取等合成变体，多数基准获得提升 [^18^]。

### 3.3 基准去污染

#### 3.3.1 n-gram 谱系：GPT-3 13-gram、Llama 3 8-gram+逐基准阈值（EPG）、PaLM 70% 8-gram；改写/翻译污染使 n-gram F1≈0，LLM Decontaminator F1 0.94+

基准去污染（decontamination）指从训练语料中识别并移除与评测基准重叠的内容，其事实标准是 n-gram 重叠检测，但各家的粒度与处置动作高度分散：

| 系统/工作 | 检测粒度与阈值 | 处置动作 | 已知问题 |
|---|---|---|---|
| GPT-3（2020） | 13-gram 碰撞（小写、空格分词、去标点） | 删除碰撞 13-gram 及前后 200 字符窗口；切分超 10 片则整篇删除；出现于 >10 篇文档的高频 13-gram 豁免 | 过滤代码有 bug，只部分生效，论文改用 clean 子集对比评估 [^39^] |
| GPT-2 | 8-gram | 过滤 | WebText 平均污染率 3.2% [^40^] |
| PaLM | 样本 ≥70% 的 8-gram 出现在训练集即判污染 | 过滤 | 比例阈值对长样本宽松 [^40^] |
| Llama-2 | >10 token 的 skip-gram（Token-Extend） | 分 clean/not clean/dirty 三档 | 分级标准主观 [^40^] |
| GPT-4 | 50 字符重叠 | 未公开细节 | 字符级对格式变化敏感 [^40^] |
| Dolma/Paloma | 13-token 段落级匹配 | 段落级删除，仅影响 <0.02% 文档 | 对代码评测放弃去污染 [^41^] |
| Llama 3（2024） | 8-gram 重叠率 + 逐基准阈值 $T_D$ | 不做过滤，做事后污染分析：按"clean 子集与全集分数差"（estimated performance gain, EPG）最大且显著原则逐基准选阈值 | MMLU/HumanEval/MBPP/MMLU-Pro 上方法失效（污染率过高无法估计增益）[^5^] |

谱系表揭示两个趋势。其一，阈值从未收敛：从 GPT-3 的 13-gram 到 Llama 3 的 8-gram，再到 GPT-4 退到字符级，说明"多长的重叠算污染"没有理论答案，只有经验选择；GPT-3 的 200 字符窗口与高频豁免等补丁，正是对"整篇删除一次碰撞会误伤长文档（如被维基引用一行的书）"这类假阳性的追认 [^39^]。其二，Llama 3 代表方法论转向：与其设定统一阈值，不如用 Singh et al.（2024）提出的 EPG 框架按基准经验地遴选检测方法与阈值——其测量显示污染影响高度异质，HellaSwag/PiQA 污染率高且增益大，NaturalQuestions 污染率 52% 却几乎无性能影响 [^5^][^42^]。谱系之外的根本局限是：改写、翻译、格式变化均可绕过一切表面匹配——对改写样本 n-gram 检测的 F1 约等于 0；LLM Decontaminator（embedding top-k 检索 + GPT-4 判定是否改写样本）在 MMLU/HumanEval 受控基准上把 F1 提升到 0.94–1.00，但成本显著更高 [^43^]。

#### 3.3.2 分层去污染流程与假阳性隔离区实践；Nemotron-CC 明确不去污染的理由与争议（冲突区）

综合上述证据，当前可辩护的实践是分层去污染流程：对每个待报告的基准先做 n-gram（8 或 13-gram）重叠检查并记录匹配跨度、文档 ID 与处置动作；对 MMLU、HumanEval 这类被反复转载改写的基准，叠加 embedding 检索 + LLM 判定的二级检测；对高频通用表达（法律模板、俗语）设出现频次豁免，对长文档采用窗口删除而非整篇删除，可疑但不确凿的样本放入隔离区（quarantine）而非直接删除，以降低假阳性损失 [^39^][^43^]。

但"是否必须去污染"本身是当前的冲突区，双方证据必须并列。一方是训练者视角：Nemotron-CC 明确不做去污染，理由是"尚无强共识且影响有争议"，并引用 DCLM 的发现——MMLU 在去污染后分数反而上升、污染更多的 FineWeb 在 MMLU 上反而更低，暗示对大模型长 horizon 训练而言污染的实际影响有限 [^18^]。另一方是评估者视角：改写级污染可让 13B 模型刷到 GPT-4 水平且 n-gram 完全检测不到 [^43^]，DCLM 因此不直接对语料去污染，而是发布去污染工具并要求所有 benchmark 提交披露 decontamination report [^17^]。调和的读法是：去污染对"训练集构建"或许是可选项，但对"评估可信度"是前提条件——二者不应对立。

### 3.4 注意事项

1. **污染的量级足以翻转模型排名**。LLM Decontaminator 论文证明：仅在改写版测试题上训练，13B 模型即可在 MMLU、GSM8K、HumanEval 上达到 GPT-4 水平，而 n-gram 检测对此完全失效 [^43^]。Inference-Time Decontamination（ITD）的实测显示，去除污染后 GSM8K 分数虚高 22.9%、MMLU 虚高 19.0%，Phi-3 与 Mistral 在 MMLU 上分别下降 6.7 和 3.6 个百分点 [^44^]。这意味着任何不带去污染报告的 benchmark 数字都不应被直接采信。
2. **去重参数即语义决策**：MinHash 的 band×row 配置隐式决定 Jaccard 阈值（$\approx(1/b)^{1/r}$），FineWeb 的 5-gram/112 hash/14×8（≈0.75）是经过下游消融验证的稳妥起点；阈值每降一档，"同主题不同内容"的误删风险显著上升 [^16^][^33^]。
3. **粒度先于算法**：短 horizon 求质量宜每快照独立去重（避免 FineWeb 发现的全局去重质量反转陷阱）；长 horizon 求唯一 token 量才考虑全局去重；多源合并时必须做跨源去重 [^16^][^18^]。
4. **重复按频率分布管理而非总量**：均匀重复 ≤4 epoch 基本无害，但小比例数据的高频重复危害不成比例，去重应优先压平重复频率长尾 [^37^][^38^]。
5. **逐基准验证去污染方法**：同一阈值在不同基准上从"有效"到"完全失效"不等（Llama 3：NaturalQuestions 52% 污染无增益，MMLU/HumanEval 上 8-gram 失效）；按 EPG 思路遴选方法与阈值，并随模型报告公开污染率、clean 子集分数与处置记录 [^5^][^42^]。
6. **警惕过强去重的信号**：整体缩减率异常高或某数据源被整体清空时，应抽检被删样本——FineWeb 的教训是被保留的一方未必是高质量的一方 [^16^]。

## 4. 数据配比、课程学习与合成数据

第 2–3 章解决了"用什么数据"的问题，本章回答三个后续问题：不同来源的数据按什么比例混合（配比，data mixture）、按什么顺序投喂（课程，curriculum），以及真实数据不够用或不够好时如何用模型自己生产数据（合成数据与蒸馏）。三者的共同底色是：配比与课程决策都依赖小规模代理实验，而代理实验结论只在有限条件下可迁移。

### 4.1 配比方法论谱系

#### 4.1.1 从人工比例到在线动态配比

配比问题最早的解法是多语言预训练时代的温度采样（temperature sampling）：对自然分布做幂律平滑 $P'(i) \propto P(i)^{\alpha}$（$\alpha \approx 0.3$–$0.7$，XLM/mT5 传统），上采样低资源语言、下采样高资源语言；域级配比（如 The Pile、LLaMA 的配比表）则长期依赖专家经验设定 [^45^]。此后的学术谱系沿四条路线演进：

- **数据选择路线**：DSIR 在 hashed n-gram 特征空间估计重要性权重 $w_i = p_{target}(z_i)/q_{raw}(z_i)$ 做重要性重采样，4.5 小时即可从 The Pile 选出 1 亿文档 [^46^]。
- **代理模型 + 优化路线**：DoReMi 先训 280M 参考模型，再用 Group DRO 最小化跨域最坏超额损失得到域权重，迁移到 30 倍大的 8B 模型后下游少样本精度平均提升 6.5 个百分点、达到基线精度少用 2.6 倍步数 [^47^]；DoGE 改用双层优化与"泛化估计"（验证域与训练域梯度内积），代理仅 82M，比 DoReMi 省约 3–4 倍计算，且支持域外目标泛化 [^48^]。
- **回归/预测路线**：RegMix 把配比选择当作回归任务——训 512 个 1M 参数小模型（各 1B token，合计约为主训练 2% 算力），用 LightGBM 拟合"配比→验证 loss"后在模拟空间搜索，预测出的配比在 1B 模型 25B token 上优于 64 个候选配比 [^49^]；Data Mixing Laws 发现验证 loss 是配比的指数形式可预测函数，据此优化的配比让 1B 模型达到默认配比需多训 48% 步数的效果 [^50^]；CLIMB 先在嵌入空间聚类（约 1000 簇剪枝合并为 20 簇）免除人工域标签，再做迭代式 bootstrap 搜索，其 1B 模型 400B token 配比超过 Llama-3.2-1B 达 2.0% [^51^]。
- **在线动态调整路线**：ODM 把配比当作多臂老虎机问题在线调整采样概率，少用 19% 迭代达到次优方法的最终困惑度 [^52^]；Aioli 将所有方法统一为"在方法特定的混合律（mixing law）下最小化平均 loss"，训练中在线估计混合律参数并动态调权 [^53^]。

下表汇总各路线代表方法的关键属性：

| 方法（年份） | 路线 | 代理成本 | 代表结果 | 主要局限 |
|---|---|---|---|---|
| 温度采样 / 人工比例 | 基线 | 无 | mT5 式低资源上采样 [^45^] | 依赖经验，无目标函数 |
| DSIR（2023） | 数据选择 | n-gram 特征，极低 | 4.5 小时选 1 亿文档；KL 缩减与下游精度相关 r=0.82 [^46^] | 只选数据，不给配比 |
| DoReMi / DoGE（2023/2024） | 代理 + 优化 | 280M / 82M 代理 | 下游 +6.5pp，2.6× 加速 [^47^][^48^] | 域权重存在多个局部最优；代理越大 DRO 权重质量反而下降 [^47^] |
| RegMix / Data Mixing Laws / CLIMB（2024–2025） | 回归/预测 | 512×1M 模型，约 2% 主训练算力 | 超人工配比；1B@400B 超 Llama-3.2-1B 2.0% [^49^][^50^][^51^] | rank invariance 仅验证至 1B；收益依赖评估指标选择 [^49^] |
| ODM / Aioli（2023/2024） | 在线动态 | 训练中在线估计 | 少 19% 迭代达同等 ppl；6/6 数据集平均优基线 0.27 ppl [^52^][^53^] | 收益幅度小（困惑度口径） |

这张谱系表揭示两个容易在单篇论文阅读中被忽略的事实。其一，代理成本沿谱系急剧下降：从 DoReMi 的 280M 参考模型 + DRO 训练，到 RegMix 用 1M 参数的"玩具模型"即可完成单域 loss 排序，说明配比搜索的瓶颈已从算力转向方法论（采多少个候选配比、用什么指标拟合）。其二，收益口径高度不统一——DoReMi 报下游准确率、Aioli 报困惑度、CLIMB 报基准平均分，三者不可横向比较。最关键的警示来自 Aioli 的统一实验：在其公平对比下，此前所有自动方法（含 DoReMi、ODM）无一能稳定跑赢简单的分层抽样（stratified sampling）基线，最多落后 6.9 个困惑度点，症结在于各方法对混合律参数的离线估计不准 [^53^]。因此工程纪律是：任何自动配比方法必须先与"按自然分布/分层抽样"对比再宣称收益。

#### 4.1.2 可迁移性：排序可迁移 ≠ 数值可迁移

"用小模型定配比、外推到大模型"范式的有效性取决于配比排序不随规模翻转（rank invariance）假设，证据是双向的，必须并列呈现。

**支持方（排序可迁移）**：RegMix 在 1M/60M/280M/1B 四个尺寸、1B–25B token 上测得配比排序的 Spearman 相关很高 [^49^]；DataDecide 在 25 个数据配方、4M–1B 规模上发现，单一 150M 小规模实验的排名能以约 80% 的正确率预测 1B 目标规模的最优数据配方，8 种 scaling law（尺度定律）外推方法均未超过这一"单尺度排名"基线；用连续似然指标（Correct Prob/Total Prob）替代离散准确率时，0.01% 的算力即可让 MMLU、HumanEval 等基准的决策正确率超过 80% [^54^]。Skill-It 在 125M 上学到的技能图亦可迁移到 1.3B 模型 [^55^]。

**反对方（数值不可迁移）**：AutoScale 证明最优配比的绝对值随训练规模系统性漂移——小规模实验确定的"最优"配比放大后不再最优，其机制是数据耗尽效应：小规模时高质量域尚有富余，大规模时高质量 token 被耗尽、配比必须向通用网页倾斜；该方法先在小规模定配比、再拟合"最优配比随规模"的预测器外推，在 774M 模型上收敛至少快 25% [^56^]。MDE 进一步发现迁移可靠性依赖评估指标：单域 loss 排名用小代理即可，但按多域聚合指标排序时，70M 代理和不足 6K 步的训练会显著失准，需要 280M×10K 步的代理才可靠 [^57^]。

两组证据并不真正矛盾，而是划定了精确的方法论边界：小模型给出的配比**排序**基本可信（约 80% 决策正确率），但**具体百分比数值**不可直接外推。实践上的调和方案是 Llama 3 的"小模型初筛 → 更大模型复核 → 多轮迭代"流程，而非一次外推 [^5^]。

### 4.2 课程学习与动态调整

#### 4.2.1 工业界三阶段课程成标配

2024–2026 年的旗舰模型几乎全部放弃"单一配比训到底"，转而采用三阶段课程：**通用网页占大头的主体阶段 → 上调 STEM/代码/推理/合成数据的知识密集阶段 → 长上下文阶段**。Qwen3 在约 36T token 上的课程为：通用知识主体阶段 → 上调 STEM、代码、推理与合成数据的高质量阶段 → 长上下文阶段（30T/5T 划分、75% 16K–32K 样本构成、ABF 10K→1M 等配方数字详见 8.2.2 节配方表）[^6^]；GLM-4.5 的 23T 预训练分两阶段，第二阶段上调 GitHub 源码与代码/数学/科学相关网页，最高质量分桶的网页训练超过 3.2 个 epoch [^58^]。具体百分比则被各家视为核心机密——除 Llama 3 公布约 50% 通用 / 25% 数学推理 / 17% 代码 / 8% 多语外，Qwen3、DeepSeek-V3、GLM-4.5 均未披露数字配比 [^5^]。

在阶段内部，头部团队还对中间 checkpoint 做监控并动态微调配比。Llama 3 在主体训练中已一次性"上调非英文数据、上采样数学数据、加入近期网页数据、下采样低质量子集"；更具方法论意义的是 Meta 把退火（annealing）当作数据源价值的评估工具：用小规模退火对照实验判断新数据源是否值得纳入，成本比逐数据集做 scaling law 实验低约一个数量级。该退火评估协议的标准配方详见 8.1.1 节 [^5^]。学术证据支持"阶段切换"这一粗粒度形式：首个针对 LLM 预训练的系统课程学习研究（200+ 模型、100B token）表明，easy→hard 的逐样本排序能加速早中期收敛（达基线少 18%–45% 步数），作为 warmup 后接随机采样有约 3.5% 的持续收益，但整体收益小于配比调整与质量筛选——这解释了工业界为何以"阶段切换"而非"逐样本排序"实现课程 [^59^]。

### 4.3 合成数据

#### 4.3.1 合成数据成为头部配方核心成分

Phi-4 是标志性案例：14B 模型约 10T token 的预训练混合中，纯合成数据占 40%、网页改写占 15%，过滤网页仅 15%、代码 20%、定向采购数据 10%；其合成池约 400B token、分 50 个大类，用多智能体提示、自我修订、指令反转等技术生成，并遵循多样性、细微性、准确性、思维链四原则 [^9^]。Qwen3 则用上一代模型做数据生产工具：用 Qwen2.5/Qwen2.5-Math/Qwen2.5-Coder 合成数万亿 token（教科书、问答、指令、代码片段，覆盖数十个领域），并用 Qwen2.5-VL 对海量 PDF 类文档做文字识别、再用 Qwen2.5 精炼（refine），又获得数万亿 token——多模态模型由此成为预训练语料的生产线 [^6^]。

#### 4.3.2 改写是最可扩展的合成数据类型

在各类合成数据中，改写/重述（rephrasing）的证据最扎实。WRAP 用指令微调模型把 C4 文档改写为"维基百科风"或"问答风"，与原文联合预训练后训练加速约 3 倍、Pile 各子集困惑度平均改善超过 10% [^60^]。Nemotron-CC 用分类器集成加合成改写构建 6.3T token 数据集，其支撑 8B 模型 15T token 长程训练并超过 Llama 3.1 8B（MMLU +5，ARC-C +3.1），全量数据与 DCLM 精度持平但唯一真实 token 多 4 倍 [^18^]。Kimi K2 的消融进一步量化了改写相对简单重复的优越性：SimpleQA 上 10 倍改写训练 1 epoch（28.94%）优于原文训练 10 epochs（23.76%），但每个语料最多改写 2 次 [^10^]。

#### 4.3.3 风险：模型坍缩之争与安全实践

合成数据的风险研究存在真实的学术分歧。Shumailov 等在《自然》（Nature）2024 年论文中证明，在替换式递归训练（每代只用上一代生成数据）下，分布尾部逐渐消失、模型退化为低方差输出，即模型坍缩（model collapse）[^61^]；Alemohammad 等称之为"自我消耗障碍"（MAD），断言没有每代注入新鲜真实数据则质量或多样性必然递减 [^62^]。反方 Gerstgrasser 等证明，只要**累积**（accumulate）真实数据与合成数据而非替换，坍缩不发生、测试误差有不随迭代增长的有限上界 [^63^]。但 Dohmatob 等给出了更严厉的理论警告：长尾分布下即使只混入 1% 合成数据也会改变缩放律、性能出现平台期，混真实数据只是推迟且需更多算力才能恢复 [^64^]。建设性共识来自 Feng 等：合成数据要支撑规模扩展必须经过验证/筛选（verification），工程重心应放在过滤环节而非纠结混合比例 [^65^]。

| 实践/证据（年份） | 规模与配比 | 报告的收益 | 风险与边界 |
|---|---|---|---|
| Phi-4 纯合成 + 改写（2024） | 合成 40% + 改写 15% [^9^] | Figure 2 消融：合成数据复用至 12 epoch 无过拟合、优于更多新鲜网页 token（MMLU）[^9^] | 纯合成训练的 13B 在知识基准 TQA 落后 14.8 分、幻觉增多；种子微小错误被管线放大 [^9^] |
| Qwen3 合成 + PDF 提取（2025） | 合成数万亿 token [^6^] | 36T 总预算、119 语言覆盖 | 依赖上一代模型质量，具体配比未公开 |

| Nemotron-CC（2024） | 6.3T（含 1.9T 合成改写） | 8B@15T 超 Llama 3.1 8B（MMLU +5）[^18^] | 作者承认未验证改写的事实准确性 |
| 模型坍缩理论线（2024） | 替换式递归训练 | — | 尾部消失、缩放律失效；累积式可避免但存争议 [^61^][^63^][^64^] |

综合上表可以看到一条清晰的不对称规律：合成数据利于推理与格式类能力，却系统性损害知识与事实能力，因此 Phi-4、Qwen3、Nemotron 的配方无一例外保留大量真实网页与书籍作为"知识锚点"——"合成数据可以替代网页数据"的说法与一线实践直接矛盾 [^9^]。另一条规律是收益与改写次数之间存在明确的拐点：K2 的"最多 2 次"、Phi-4 最终混合中合成池（290B 唯一 token）被复用 13.8 个 epoch 仍未见坍缩共同说明，**对同一批合成数据的多 epoch 复用**与**递归自我生成**是两个不同机制，前者安全后者危险，文献与实践中经常被混淆。安全实践可归纳为三件事：混合真实数据（累积而非替换）、生成后验证过滤（代码执行校验、多数投票、LLM 级复检）、多样性工程（多主题种子 × 多风格提示变体）。文献明确排除"X% 合成即安全"的通用数字 [^65^]。

### 4.4 蒸馏进入预训练

知识蒸馏（distillation）正从后训练技术前移为预训练目标本身。Gemma 2 的 2B/9B 模型在预训练阶段即以教师模型的 token 分布为目标替代标准 next-token 预测，训练量超过计算最优值 50 倍；消融显示 2B 模型 500B token 蒸馏版比从头训练版在三项基准平均 60.3 升至 67.7 [^66^]。Llama 3.2 的 1B/3B 模型同样在预训练阶段直接使用 Llama 3.1 8B/70B 的 logits 作为 token 级蒸馏目标，并结合剪枝恢复性能 [^67^]。需要区分两类机制：Gemma 2/Llama 3.2 是**分布级**的 logit 蒸馏（教师不产出文本，只产出概率分布），而 Phi 系早期工作是**文本级**合成（蒸馏 GPT-4 生成的文本）；Phi-4 报告刻意声明其在 STEM QA 上已显著超过教师模型，标志合成数据的角色从"模仿教师"升级为"生成教师没有的训练信号" [^9^]。对实践者的含义是：logit 蒸馏可在固定数据上模拟"超出可用 token 量的训练"，是小模型撬动大模型知识的杠杆，与文本级合成数据互补而非替代。

## 5. Tokenizer 与训练序列构造

Tokenizer（分词器）是预训练管线中最早被冻结、却最晚才被重视的设计决策：它决定了训练数据量的计量单位、上下文窗口的有效容量、多语言成本结构，甚至词表 merge 列表本身会泄露训练数据配比。本章分两部分：5.1 讨论 tokenizer 的算法、词表大小与口径纪律；5.2 讨论把 token 流组织成训练序列的构造决策。

### 5.1 Tokenizer 设计

#### 5.1.1 byte-level BPE 已成为事实标准

2024 年之后，主流旗舰 decoder-only 模型几乎一致收敛到 byte-level BPE（字节级字节对编码）：BPE（Byte Pair Encoding）是一种自底向上的贪心合并算法，byte-level 变体把全部 256 个 UTF-8 字节作为初始符号，因此原则上可编码任意文本。Llama 3 从 Llama 2 的 32K SentencePiece BPE 切换到 128K 的 tiktoken 风格 byte-level BPE，其中 100K 继承自 tiktoken、另增 28K 非英语 token；按 Meta 官方口径，同文本 token 数相对 Llama 2 最多减少约 15%，技术报告给出的英文样本压缩率则从 3.17 提升至 3.94 字符/token[^5^][^68^]。注意这两个数字度量对象不同（前者是基准文本的 token 计数，后者是英文样本的字符压缩率），引用时不可混用。DeepSeek-V3 同样采用 128K byte-level BPE，并明确"修改了 pretokenizer 与 tokenizer 训练数据以优化多语言压缩效率"[^2^]。主要例外是 Gemma/Gemini 系列，仍用 SentencePiece Unigram、词表 256K–262K[^69^]。

| 模型 | 算法 | 词表大小 | 备注 |
|---|---|---|---|
| Llama 2 | SentencePiece BPE | 32K | 2023 年代表性配置 [^5^] |
| Llama 3 | byte-level BPE（tiktoken 风格） | 128K | 100K 继承 + 28K 非英语；省约 15% token [^5^][^68^] |
| DeepSeek-V3 | byte-level BPE | 128K | pretokenizer 与训练数据面向多语言压缩优化 [^2^] |
| GPT-4o / o 系列 | byte-level BPE（o200k_base） | 约 200K | 约 39% 训练数据为非英语（逆向工程推断） [^69^][^70^] |
| Mistral Tekken | byte-level BPE（tiktoken 风格） | 约 131K | 代码压缩较前代好约 30%（二手口径） [^71^] |
| Gemma / Gemini | SentencePiece Unigram | 256K–262K | 主要例外 [^69^] |

从表中可见两条趋势：其一，算法层面 Unigram 与 BPE 的受控实验差异（Unigram 在 encoder/翻译规模上略优且支持 subword regularization）并未改变产业选择——确定性编码、速度与 tiktoken 生态兼容是 byte-level BPE 胜出的决定性因素，而非压缩率差距；其二，词表规模两年间从 32K 膨胀到 128K–262K 区间，且扩容方向普遍指向非英语与代码。一个独立的佐证是逆向工程研究：tokenizer 的 merge 列表会泄露其训练数据配比，GPT-4o 推断约 39% 非英语、Llama 3 约 48% 面向多语言[^70^]，说明头部实验室确实按目标分布训练 tokenizer。

byte fallback（字节回退）已是标配：未见字符回退为字节序列而非 `<unk>`，做到无信息损失、全覆盖，代价是稀有文字占用更多 token（GPT-SW3 采用 byte fallback 加 0.9999 字符覆盖率）[^72^]。前沿仍在演进：SuperBPE 允许跨空格的"superword" token，固定 200K 词表下平均减少 33% token，8B 从零预训练在 30 项任务上平均提升 4.0%（MMLU +8.2%），推理计算量降 27%[^73^]——证明"同一词表、更好的 token 设计"可以兼得压缩率与质量。

#### 5.1.2 词表大小的权衡

词表大小不是越大越好，而是随算力预算增长的标定量。NeurIPS 2024 的「Scaling Laws with Vocabulary」用 IsoFLOPs 分析、导数估计与损失参数化拟合三种独立方法收敛到同一结论：大模型需要更大词表，预测 Llama2-70B 的最优词表应不低于 216K（实际只有 32K）；在相同 2.3e21 FLOPs 预算下，仅将词表从 32K 提到 43K 就把 ARC-Challenge 从 29.1 提升到 32.0[^74^]。大词表的代价是线性的 embedding 与输出层参数（各为 $V \times d$，Llama-3-8B 的 embedding 约 $128256 \times 4096 \approx 5.25$ 亿参数），以及稀有 token 出现次数不足导致的 embedding 欠训练（SolidGoldMagikarp 类 glitch token 现象）[^75^]。

词表设计的另一面是跨语言公平性。Petrov et al.（NeurIPS 2023）对 17 个 tokenizer 的测量显示，同一内容翻译到不同语言后编码长度差最多可达 15 倍，在 ChatGPT/GPT-4 上 Dzongkha、Odia、Santali、Shan 等语言的成本是英语的 12 倍以上[^76^]；Ahia et al.（EMNLP 2023）进一步指出按 token 计费的 API 定价在语言维度上是累退的[^77^]。对训练侧的直接伤害由 Ali et al.（NAACL 2024 Findings）量化：24 个 2.6B 模型的对照实验表明，用英语中心 tokenizer 训练多语言 LLM 会造成严重下游退化与最高 68% 的额外训练成本；面向欧洲五大语言的多语言 tokenizer 需要约 3 倍于英语的词表[^78^]。

#### 5.1.3 口径纪律：先冻结，再核算

tokenizer 一旦冻结，整个项目生命周期的数据量、成本与上下文预算都以它的 token 为单位核算，因此纪律是：先在与预训练混合比例一致的代表性数据上训练并冻结 tokenizer，再谈 token 预算。tokenizer 训练语料若与预训练分布不一致，弱势语言与领域会被结构性过度切分，代价是训练成本（最高 +68%）与下游性能双输[^78^][^70^]。

跨模型引用"T tokens"时必须警惕口径：DeepSeek-V3 明确标注"14.8T tokens **in our tokenizer**"，Llama 3 报告 15T——两者因 tokenizer 不同不可直接比较[^2^][^5^]。token 不是稳定的长度单位：同一单词 antidisestablishmentarianism，Claude 切成 9 个 token，Gemini/Grok 只切 5 个[^79^]。同理，跨 tokenizer 比较 loss 或困惑度是比较不同单位的数字，正确做法是 bits-per-byte（BPB）等字节级归一化指标（Paloma 基准即用 BPB 使不同 tokenizer 模型的困惑度可横向比较）[^80^]。最后，pretokenizer 的细节会引入训练-推理偏差：DeepSeek-V3 的 pretokenizer 合并"标点+换行" token，会在无终止换行的多行 prompt（如 few-shot 评测）上产生 token boundary bias，缓解办法是训练时随机拆分一定比例的此类合并 token[^2^]。

### 5.2 序列构造

#### 5.2.1 文档拼接与跨文档注意力

序列构造的传统默认是 concatenate-then-split：全部文档以 `<EOS>` 间隔拼成超长流，再按上下文长度等切，token 利用率近 100%，代价是大量文档被拦腰截断[^81^]。围绕它的第一个关键决策是**是否屏蔽跨文档注意力**，此处存在真实的路线分歧，双方证据并列如下：

- **Llama 3（屏蔽方）**：在同一序列内使用阻止跨文档自注意力的 attention mask（block-diagonal mask），官方称该改动在标准预训练中影响有限，但在长序列 continued pre-training 中很重要[^5^]。工程上通过 FlashAttention-2 varlen API 实现，浪费 token 可从朴素 batching 的约 50% 降到 2% 以下[^82^]。
- **DeepSeek-V3（不屏蔽方）**：实现 document packing 保证文档完整性，但明确训练时不做 cross-sample attention masking[^2^]。

两种做法都在顶级模型上验证过：屏蔽更"干净"、避免跨文档污染且长上下文续训受益；不屏蔽实现简单、吞吐更高。选择应结合是否规划长上下文续训与基础设施对 varlen 注意力的支持度，不存在普适正确答案。

第二个决策是**如何减少截断**。Best-fit Packing（ICML 2024）把装箱问题（Best-Fit-Decreasing 启发式）用于文档打包，只保留超出上下文长度所必需的最小截断，消除其余全部截断，训练序列数仅增加 0.0006%–0.0028%（效率等同拼接法），换来阅读理解 +4.7%、上下文跟随 +16.8%、程序合成 +15.0%（Pass@100），封闭域幻觉最多降 58.3%[^83^]。其必要性的背景是：主流语料库的文档绝大多数短于 2K token，固定 8K 序列长度必然引入大量人为拼接边界[^84^]。

#### 5.2.2 FIM：rate 取多少存在真实分歧

FIM（fill-in-the-middle，中间填充）把文档重排为"前缀-后缀-中段"格式，让模型学习代码补全式的条件生成。此处同样存在冲突区，双方证据并列：

- **Bavarian et al.（2022，方法论文）**：FIM rate 高达 90% 也不损害从左到右能力（100% 才有退化），推荐 50%–90%，PSM 与 SPM 两种格式联合训练效果最好[^85^]。
- **DeepSeek 产品线（工程实践）**：DeepSeek-V3 通用基座采用 PSM 框架、文档级 pre-packing，FIM rate 仅 0.1；Coder-V2 产品线中 16B 用 0.5、236B 直接关闭 FIM[^2^][^86^]。

分歧的解释维度是模型定位与规模：通用基座只需保留少量 FIM 能力（0.1 档），代码专精模型才需要高 rate（0.5–0.9 档），不存在普适最优值。一个额外的记忆化风险：FIM 切分应按 epoch+seed 重新生成，避免同一文档以完全相同的 framing 重复出现[^87^]。

#### 5.2.3 确定性 shuffle、落盘格式与审计指标

数据顺序必须在给定 seed 下完全确定，且每个 epoch 使用不同置换。Smol Training Playbook 记录了一起真实事故：文档级做了 shuffle 但 batch 内序列顺序未打乱，导致训练中出现 loss 尖峰；修复方案是离线预 shuffle tokenized 序列，并为每个 epoch 使用不同 seed 以避免跨 epoch 重复的 shuffle 模式[^88^]。落盘格式的主流是预 tokenize 后以二进制 shard 存储——Mosaic StreamingDataset 的 MDS 格式（固定大小 blob + 显式 offset）、WebDataset 的 tar shard、Parquet shard，选型核心是确定性 shuffle、shard 级 worker 互斥分配与崩溃后精确续训（epoch/rank/shuffle 状态须入 checkpoint）[^89^]。

上线前的 tokenizer 审计以压缩率指标为一线筛查工具：**fertility**（token/word，越低越好）与 **bytes-per-token**（UTF-8 字节数/token，越高越好），应在多语言、代码、数学等语料类上分别测量；对无词边界语言，bytes-per-token 比 fertility 更稳健[^90^]。多语言公平性审计用 **TFR**（Token Fertility Ratio，目标语言 token 数 / 英语 token 数）与 **ECW**（有效上下文窗口 = 名义窗口 / 平均 TFR）折算弱势语言的实际可用上下文[^91^]。监控 byte-fallback 占比同样重要：Odia 等弱势文字在主流 tokenizer 上已进入"近 fallback 区"（Tekken 18.18、Llama-3.1 16.78 token/word，而专用 tokenizer 仅 4.13）[^92^]。最后一条警告：fertility 与 parity 等压缩指标并不总能预测下游性能，它们只能做筛查，最终裁决必须靠小规模对照训练[^78^]。

## 6. 模型架构与训练目标选择

第 5 章讨论了数据侧的最后组装，本章转向模型侧的三个核心决策：稠密（Dense）还是混合专家（Mixture-of-Experts，MoE）、注意力机制选哪种变体、以及主损失之外叠加哪些训练目标。这三类决策的共同决策变量是推理经济学：架构一旦冻结，每 token 的计算量（FLOPs）、KV cache 占用和显存驻留下限就被锁定，后续所有训练技巧都只能在既定成本框架内优化质量。本章基于 2024–2026 年各头部实验室公开的技术报告，梳理当前已收敛的"参考配方"与仍存在分歧的冲突区。

### 6.1 Dense vs MoE

#### 6.1.1 从 Llama 3 的"dense 求稳"到前沿收敛 fine-grained MoE

Llama 3（2024-07）是 dense 路线的最后一代旗舰：405B 稠密 Transformer，128 个 query head 配 8 个 KV head（GQA），预训练 15T+ tokens（405B 为 15.6T）。Meta 在论文中明确解释了不选 MoE 的理由——"为最大化训练稳定性（to maximize training stability），我们选择标准稠密 Transformer 架构而非混合专家模型"[^5^]。即在超大规模下，Meta 宁可放弃 MoE 的推理成本优势，也要换取训练流程的可控性。

这一立场在不到一年内被颠覆。2025 年 4 月 Llama 4 发布，Scout（109B 总参 / 17B 激活，16 experts）与 Maverick（400B / 17B，128 experts，dense/MoE 交替层）全面转向 MoE，均含 1 个常驻共享专家与 sigmoid 门控[^93^]。同期开源前沿已收敛到 fine-grained（细粒度专家划分）MoE：DeepSeek-V3（2024-12）确立参考设计——671B 总参 / 37B 激活，每层 256 个路由专家 + 1 个共享专家、top-8 路由，14.8T tokens 全程无不可恢复 loss spike（厂商自报）[^2^]；Qwen3（2025-05）走更激进稀疏路线，旗舰 235B-A22B 用 128 experts / top-8 且取消共享专家，并给出关键经验——相同数据下 MoE 只用 Qwen2.5 dense 约 1/10 的激活参数即可达到可比性能[^6^]；Kimi K2（2025-07）把稀疏度推到极致：1.04T 总参 / 32B 激活，激活率约 3%，为当时最稀疏的前沿 MoE[^10^]。

| 模型（发布时间） | 路线 | 总参 / 激活参数 | 专家配置 | 注意力 | 预训练 token 量 |
|---|---|---|---|---|---|
| Llama 3 405B（2024-07）[^5^] | Dense | 405B / 405B | 无 | GQA（128 Q / 8 KV head） | 15T+（405B 为 15.6T） |
| DeepSeek-V3（2024-12）[^2^] | fine-grained MoE | 671B / 37B（5.5%） | 256 routed + 1 shared，top-8 | MLA | 14.8T |
| Qwen3-235B-A22B（2025-05）[^6^] | fine-grained MoE | 235B / 22B（9.4%） | 128 routed，top-8，无 shared | GQA（64 / 4）+ QK-Norm | 36T |
| Kimi K2（2025-07）[^10^] | fine-grained MoE | 1.04T / 32B（约 3%） | 384 routed + 1 shared，top-8 | MLA（64 head） | 15.5T |
| Llama 4 Maverick（2025-04）[^93^] | MoE（dense/MoE 交替层） | 400B / 17B（4.3%） | 128 routed + 1 shared | GQA + iRoPE | 约 22T（官方口径） |

**表 1 解读**：从上表可见两条趋势。其一，激活率单调下降——从 DeepSeek-V3 的 5.5% 到 Kimi K2 的约 3%，前沿在"总参数扩容量、激活参数压成本"方向上一路推进；其二，2024 年中以后发布的新旗舰无一例外选择 MoE，dense 只保留在中小模型与稳定性敏感场景。一个值得注意的异常是 Llama 4：Maverick 激活参数（17B）反而低于 Scout 档位相邻模型，靠交替 dense 层保底稳定性，说明 Meta 转向 MoE 时仍带着 Llama 3 时代的谨慎。另需提醒口径问题：Llama 4 无正式同行评审技术报告，表中数字来自官方发布材料与模型卡的汇总[^93^]；"零 spike"类稳定性声明均为厂商自报、无第三方复现。路线选择的第一性依据不是"哪个架构更强"，而是每 token 推理成本与训练通信预算的权衡：2026 年 AMD 平台实测（arXiv:2603.10031）显示，每 token 激活参数量比总参数量更能预测推理吞吐——37B 激活的 DeepSeek V3.2 总吞吐与 405B 全激活的 Llama-3.1-405B 几乎持平（15,343 vs 15,944 tok/s），单位激活参数的吞吐效率高 10.6 倍[^94^]。

### 6.2 MoE 关键设计

#### 6.2.1 负载均衡：aux-loss-free 成新基线，但非唯一解

MoE 的核心训练难题是负载均衡：若路由长期偏向少数专家，其余专家得不到训练，容量被浪费。传统方案是辅助均衡损失（GShard/Switch 系），惩罚专家负载不均，但 DeepSeek-V3 报告明确指出"过大的辅助损失会损害模型性能"——本质是均衡目标与语言建模目标的梯度冲突[^2^]。

DeepSeek-V3 采用的 auxiliary-loss-free 方案（源自 Wang et al. 2024）成为新基线：给每个专家加偏置项 $b_i$，**只参与 top-K 路由选择、不进梯度、不影响门控权重**；每步结束按该 batch 的专家负载对 $b_i$ 增减 $\gamma$（超载则减、空闲则加），V3 大部分训练用 $\gamma=0.001$；消融显示其性能持续优于纯辅助损失方案，且专家特化程度更高[^2^][^95^]。一个常被忽略的细节是：V3 仍保留一个极小的互补 sequence-wise 均衡损失（$\alpha=0.0001$），只为防止单序列内的极端不均衡——"loss-free"不等于"完全无损失项"[^2^]。

冲突区需并列呈现：Qwen3 走了相反方向，保留 **global-batch 粒度的均衡损失**（损失统计跨整个全局 batch 而非单 micro-batch，梯度冲突被摊薄），反而取消了共享专家，同样取得 SOTA[^6^]。双方证据均为各自技术报告的一手数据，说明"辅助损失 vs loss-free"取决于损失统计粒度、系数调校与专家粒度，不存在可直接照搬的单一配方。

工程配套上还有两个已收敛的设计：其一，**node-limited routing**——DeepSeek-V3 限制每 token 最多发往 $M=4$ 个节点，把跨节点 all-to-all 流量压到 IB 带宽以内，配合 DualPipe 双向流水实现计算-通信近全重叠[^2^]；其二，**不丢 token（no token-dropping）**——V3 训练与推理均不使用 Switch 系的 capacity factor 截断，避免丢弃 token 带来的训练信号损失[^2^]。此外，结构惯例是前几层保持 dense FFN 再切 MoE（V3 前 3 层、K2 前 1 层），给早期残差流稳定的特征空间[^2^][^10^]。

| 方案 | 机制 | 代表模型 | 优势 | 代价与注意事项 |
|---|---|---|---|---|
| 辅助均衡损失（aux loss） | 损失项惩罚负载不均，参与反向传播 | GShard / Switch 系 | 实现简单，理论成熟 | 系数过大损害主任务性能（梯度冲突）[^2^]；常配 capacity factor 丢 token |
| aux-loss-free bias | 偏置只进路由不进梯度，按负载每步增减 $\gamma$ | DeepSeek-V3（$\gamma=0.001$）[^2^][^95^] | 消除梯度冲突；专家特化更强 | 仍需极小互补损失（$\alpha=10^{-4}$）兜底；bias 动态调整增加实现复杂度 |
| global-batch 均衡损失 | 损失统计粒度放大到全局 batch | Qwen3-235B-A22B（无 shared expert）[^6^] | 大粒度统计摊薄梯度冲突；敢砍 shared expert | 依赖全局负载统计的通信同步；系数调校敏感 |

**表 2 解读**：三种方案的分歧点不在"要不要均衡"，而在"均衡信号以什么粒度、什么方式进入训练"。aux loss 把均衡写进梯度，简单但与主损失争抢；bias 方案把均衡移出梯度，代价是需要在线维护偏置动态；global-batch 方案则通过放大统计窗口降低单次更新的冲突幅度。值得强调的是，表中两个 2025 年 SOTA 模型（V3 与 Qwen3）恰好站在对立两端，这是本章最典型的"双方均有强证据、无定论"冲突区：实践者应按自己的专家粒度与并行配置做消融，而非二选一照搬。同时注意 shared expert 与 loss-free 不是捆绑项——V3 两者皆用、Qwen3 两者皆弃，自由度比表面看起来更大。

### 6.3 注意力变体

#### 6.3.1 GQA 低风险默认，MLA 压缩激进但推理栈支持滞后

注意力变体的选择本质是 KV cache 经济学。**GQA（Grouped-Query Attention，分组查询注意力）** 是低风险工程默认项：Llama 3-405B 用 128 个 Q head 共享 8 组 KV head，KV cache 降为 MHA 的 1/16，质量损失极小；Qwen3 全系标配[^5^][^6^]。

**MLA（Multi-head Latent Attention，多头潜在注意力）** 由 DeepSeek-V2（2024-05）首创、V3/K2 继承：对 K/V 做联合低秩压缩，推理时只缓存压缩潜向量（V3 中 512 维）与解耦 RoPE key（64 维），每层每 token 缓存 576 个元素[^96^]。DeepSeek 2025 年硬件反思报告给出量化对比：DeepSeek-V3 每 token KV cache 仅 **70KB**，而 Qwen2.5-72B（GQA）为 327KB、Llama-3.1-405B 为 516KB；对应每 token 计算量 250 GFLOPs vs Llama-3.1-405B 的 2,448 GFLOPs[^97^]。MLA 有两个设计要点：(a) RoPE 与低秩压缩冲突，需额外一条所有 head 共享的解耦 RoPE 通路；(b) Q 也做低秩压缩，但目的是省训练激活显存而非 KV cache[^96^]。性能上，V2 消融显示 MLA 持平甚至优于 MHA、明显优于 GQA-2/MQA[^96^]。

代价在推理生态：2026 年 AMD 平台实测研究指出，MLA 模型在 ROCm 上不支持 KV cache offload、要求 block-size=1，V2-Lite 的非对称 head_dim（Q/K 192 vs V 128）还会排除 FlashAttention-2；同平台上 MoE+GQA 的 Qwen3-VL-235B 吞吐是 MoE+MLA 的 Kimi-K2.5 的 6.5 倍（该对比含 AITER/TP 等混杂因素，非纯架构对照）[^94^]。实践含义：稳妥默认 GQA（8 KV head）；超长上下文或高并发场景再考虑 MLA，但必须评估目标推理框架对 MLA 的支持成熟度。

### 6.4 训练目标

#### 6.4.1 NTP 主干 + MTP 叠加；FIM 是代码模型标配但有 rate 边界

标准下一 token 预测（Next-Token Prediction，NTP）仍是所有旗舰的主损失。多 token 预测（Multi-Token Prediction，MTP）有两种形态：(a) Meta 原版（Gloeckle et al., ICML 2024）在主干上加 $n$ 个并行独立输出头同时预测后续 $n$ 个 token，收益集中在代码任务与 7B+ 规模[^98^]；(b) DeepSeek-V3 的**串联式 MTP**——每个 MTP 模块以上一深度的 hidden state 拼接下一真实 token 的 embedding 为输入，保持完整因果链（结构类似 EAGLE），实际只用 $D=1$（多预测 1 个 token），损失权重 $\lambda=0.3$（前 10T tokens）后降为 0.1[^2^]。

收益证据：DeepSeek 在 15.7B 与 228.7B 两个代理 MoE 规模做控制变量消融（MTP 模块推理时丢弃、推理成本相同），228.7B 规模 HumanEval 44.5→53.7（+9.2），但需注意同规模 MMLU 反而微降（67.5→66.6），且消融非 671B 全规模验证[^2^]。推理侧，MTP 模块转作投机解码（speculative decoding）的 draft，第二 token 接受率 85–90%，端到端 TPS 提升 1.8 倍——该数字为 DeepSeek 单流自测口径；SGLang 复现显示 batch size=1 时 1.8×、batch size=32 时降为 1.5×[^2^][^99^]。

FIM（Fill-in-the-Middle，中间填充）把文档切成 prefix/middle/suffix 重排为 PSM/SPM 格式、仍用 NLL 损失训练，使 decoder-only 模型获得代码补全能力，已成代码模型标配（CodeGemma FIM rate 80–90% 等）[^85^][^100^]。但 FIM rate 存在真实分歧——方法论文与工程实践给出的最优值相差近一个数量级（分歧证据详见 5.2.2 节）[^2^][^85^]。分档建议：通用旗舰取低 rate（0.1 档），代码专精模型可取 0.5–0.9，高 rate 下可用 AST 结构感知 FIM 缓解对从左到右（left-to-right，L2R）生成能力的损伤[^101^]。

### 6.5 稳定性架构设计

#### 6.5.1 pre-norm RMSNorm 默认；QK-Norm 与 MLA 不兼容催生 QK-Clip；router z-loss 防溢出

归一化方面，**pre-norm + RMSNorm** 是当前默认（Llama、Qwen、DeepSeek 全系）[^5^][^6^]。OLMo 2 反潮流地把 RMSNorm 挪到 attention/FFN 输出侧（仍在残差内）并配合 QK-Norm，显著降低梯度波动——但论文实验把 norm 重排与 QK-Norm 的效果混在一起，两者各自贡献无法分离[^3^][^102^]。

**QK-Norm**（对 q、k 在 RoPE 前做 RMSNorm）被 Gemma 2/3、OLMo 2、Qwen3 采用以抑制 attention logits 爆炸[^6^][^3^]。但 Kimi K2 揭示了其边界：MLA 推理时 K 矩阵不完整物化，QK-Norm 不适用；logit soft-cap 也无法阻止 capping 前点积的过度增长——K2 的 53B 规模 Muon 实验中 attention logits 会爆到 1000 以上[^10^]。K2 改用 **MuonClip**（Muon 优化器 + QK-Clip）：每步后按 head 监测最大 attention logit，超阈值 $\tau=100$ 时按比例缩放该 head 的 Q/K 投影权重；1.04T 模型全程 15.5T tokens 零 loss spike（厂商自报，归因限制见 9.3.2 节）[^10^]。

损失层的稳定器是 **z-loss**（源自 PaLM/ST-MoE）[^103^][^104^]：惩罚 router/输出 logits 的大幅值，防止大 logit 在 MoE 大规模矩阵乘中数值溢出，开源 MoE 训练（如 OLMoE，z-loss 权重 0.001）仍将其作为标配[^105^]。综合而言，训练稳定性是"架构层（norm/QK 处理）+ 优化器层（QK-Clip）+ 损失层（z-loss）+ 精度层（FP8 分块量化，见工程章节）"的系统工程，不存在单一开关；选型时尤其注意 QK-Norm 与 MLA 的互斥关系——选了 MLA，注意力稳定性就必须转移到优化器侧解决。

## 7. Scaling Law 与超参数方法论

预训练的核心决策——模型多大、数据多少、学习率与 batch size 取何值——在 2020 年代前半段完成了从"经验艺术"到"拟合工程"的转变。本章给出这条转变链条上的三类工具：决定规模/数据配比的 scaling law（尺度定律）、预测最优超参数的幂律拟合与 muP（Maximal Update Parametrization，最大更新参数化），以及学习率与 batch size 的调度方法论。贯穿全章的一条纪律是：**常数不可移植，方法论可以移植**——任何论文给出的具体系数都绑定其 tokenizer、数据分布与训练协议，可直接复用的是其实验设计。

### 7.1 经典定律与 2024+ 修正

#### 7.1.1 Kaplan vs Chinchilla（≈20 tokens/参数）分歧大半是实验协议假象

Kaplan et al.（2020）首次系统给出神经语言模型的幂律尺度行为：测试交叉熵损失对非嵌入参数量 $N$、数据量 $D$、算力 $C$ 均呈幂律（指数 $\alpha_N\approx0.076$、$\alpha_D\approx0.095$），其 compute-optimal（算力最优）分配主张"大模型、少数据"——算力增 10 倍时模型增约 5.5 倍、数据仅增约 1.8 倍（$N_{opt}\propto C^{0.73}$）[^106^]。Chinchilla（Hoffmann et al., 2022）训练 400 余个 70M–16B 模型后推翻该处方：参数与数据应等量增长（$N_{opt}\propto C^{0.5}$，$D_{opt}\propto C^{0.5}$），即著名的约 20 tokens/参数经验法则；70B/1.4T tokens 的 Chinchilla 在同算力下全面超过 280B/300B tokens 的 Gopher，证明此前大模型普遍欠训练（undertrained）[^12^]。需要澄清的是，"20"是 Chinchilla-70B 配置的算术结果，而非论文中拟合出的普适常数。

两组结论的分歧曾困扰业界两年，2024 年的两项工作基本将其消解为实验协议差异：Porian et al.（NeurIPS 2024）与 Pearce & Song 证明，Kaplan 更陡的分配指数主要来自参数计数口径（只数非嵌入参数）、末层 FLOPs 漏计、warmup 过长且优化器超参未随规模重调；统一协议后两组实验收敛到同一指数[^107^][^108^]。Epoch AI 的独立复现总体确认 Chinchilla 估计，点估计为 25.6 tokens/参数，但指出原论文置信区间过窄[^109^]；2025 年的稳健性复评进一步表明 20:1 结论对参数计数的三种口径都成立[^110^]。这一和解的方法论启示大于结论本身：**scaling law 拟合结果对实验协议的敏感度，足以在顶级团队之间制造"定律级"分歧**。

两条后续修正改变了定律的用法。其一，纳入推理成本：Sardana et al.（ICML 2024）指出，当预期推理量较大（约 10 亿次请求量级）时，全生命周期最优是"更小、更久"地训练；其 47 个模型的实验显示 tokens/参数拉高到极端区间（最高 10,000:1）时模型质量仍持续改善，但只用常规比例区间拟合的定律会高估极端区间的边际收益[^111^]。其二，数据受限（data-constrained）情形：Muennighoff et al.（NeurIPS 2023）发现数据重复至多 4 个 epoch 几乎无损，之后重复 token 的价值指数衰减至零，且多余参数的贬值快于重复数据（$r_N<r_D$），处方是"数据受限时优先多跑 epoch 而非加大模型"[^37^]。但该处方存在公开争议：Lovelace et al.（2026）指出 Muennighoff 的函数形式无法建模高重复下的过拟合（测试 loss 回升），给出相反建议——"更大模型 + 更少 epoch"，并把分歧归因于前者的 Chinchilla 基线拟合在他人 isoFLOP 数据上而非自有实验[^112^]。截至本调研时点（2026-10）该冲突未收敛，实务上应在自己的数据分布上做小规模处方验证而非择一照搬。

#### 7.1.2 超量训练实践

修正后的定律迅速被头部实验室转化为"刻意超量训练"（overtraining）实践：旗舰模型贴近 compute-optimal 以控制训练成本，小模型则远超该比例训练以换取推理侧的性价比。下表汇总主要公开配比，注意所有比率均为"训练 tokens 数 / 模型参数量"的口径依赖量。

| 模型/定律 | tokens/参数 | 口径与说明 |
|---|---|---|
| Chinchilla（compute-optimal）| ≈20 [^12^] | 70B/1.4T 配置的算术结果；Epoch AI 复现点估计 25.6 [^109^] |
| MiniCPM（WSD 拟合最优比）| ≈192，修正口径后 70–100 [^113^] | 用 WSD 调度在"模型风洞"实验中拟合 |
| Llama 3 405B | ≈38（15.6T/405B）[^5^] | 旗舰贴近 compute-optimal；scaling law 外推建议 402B/16.55T |
| Llama 3 8B | ≈1875（15T/8B）[^5^] | Meta 明确称同推理预算下优于 compute-optimal 模型 |
| Sardana 极端区间实验 | 至 10,000 [^111^] | 质量仍改善，但收益被常规区间拟合高估 |
| DeepSeek-V3（MoE）| ≈22（总参 671B）/ ≈400（激活 37B）[^2^] | MoE 必须先声明参数口径 |

解读：表中比率横跨近三个数量级，但这不构成"定律失效"的证据，而是目标函数不同——Chinchilla 优化纯训练算力，Llama 3 8B 与 MiniCPM 优化全生命周期成本，DeepSeek-V3 的数字则提醒 MoE 架构下"参数量"本身有歧义。三个系统性影响因素值得记住：tokenizer 不同会使同一文本的 token 数显著漂移；WSD 调度的长稳定期让小模型能"吸收"更多数据（MiniCPM 的 192:1 部分由此而来）；推理成本摊薄越深，最优比率越高。因此任何 tokens/参数数字在引用时都应连同其口径与目标函数一起引用，在自己栈上规划时必须用自己的数据与调度重拟合，禁止搬运常数。

### 7.2 超参数预测的工业化

#### 7.2.1 Qwen2.5/3 范式与 Step Law

2024 年末起，"用小规模网格拟合超参数幂律、再外推到大模型"成为头部团队的标配。Qwen2.5 率先系统化：在 44M–14B 的 dense 模型、44M–1B 激活参数的 MoE、0.8B–600B tokens 的实验网格上，拟合最优学习率 $\mu_{opt}$ 与 batch size $B_{opt}$ 关于 $(N, D)$ 的 scaling law，再将终损建模为架构与数据规模的函数[^14^]。Qwen3 沿用并对三阶段预训练分别拟合，官方称之为"scaling law guided hyperparameter tuning"[^6^]。该范式的方法论在 Qwen3.8-Next 中进一步成熟，暴露了两条关键注意事项：架构或优化器一变，旧配方即失效、必须重拟合；外推可靠性要分维度验证——batch size 预测用"小模型 × 长 token 预算"检验（大 batch 的危害在长训练中放大），学习率预测用"大模型 × 有限 token 预算"检验（不稳定性是主要风险）[^114^]。

StepFun 的 Step Law（2025）给出了迄今最大规模的公开拟合：从头训练 3700 余个模型、约 100T tokens、近 100 万 H800 GPU 小时。其核心发现是固定 $(N,D)$ 时超参地形呈凸性且最优平台很宽，并给出闭式幂律[^115^]：

$$\eta_{opt}(N,D)=1.79\,N^{-0.713}D^{0.307},\qquad B_{opt}(D)=0.58\,D^{0.571}$$

即最优学习率同时依赖模型与数据规模，而最优 batch size 主要由数据量决定、与模型规模基本无关。该公式预测的最优点与穷举搜索的全局最优仅差 0.094% 测试损失，且在中英混合、代码混合等不同数据配方下偏差仅 0.125%–0.25%[^115^]。"宽平台"结论有直接的实务含义：不必追求精确最优点，落在偏差 <0.25% 的盆地内即可，拟合预算可让位于验证预算。对 MoE 架构，蚂蚁 Ling 团队证明跨稀疏度时传统尺度变量不够用，激活率必须作为额外预测维度进入幂律[^116^]。

#### 7.2.2 muP：宽度迁移可靠，其余维度仍需 scaling law

muP（Yang & Hu，Tensor Programs V，NeurIPS 2022）从另一条路径压缩调参成本：在 muP 参数化下，最优学习率、初始化与乘性超参对宽度近似不变，可在小代理模型上调参后零样本迁移（μTransfer）——从 13M 迁移即超过 BERT-large（350M）公开结果，从 40M 迁移超过 GPT-3 6.7B，调参成本仅为一次完整预训练的 7%[^117^]。Cerebras-GPT 全系与 Phi 系列均采用该框架，MiniCPM 亦实证模型扩大 10 倍后最优 base LR 基本不动（约 0.01）[^113^]。

但 muP 的覆盖边界必须讲清：它保证的是**宽度维度**的迁移。深度维度需要 Depth-μP 或残差分支 $1/\sqrt{2L}$ 缩放，且对现代 Transformer 块结构的普适深度定律仍未建立[^118^]；batch size、token 预算维度的超参漂移完全不在其覆盖范围，MoE 稀疏度还需额外处理[^116^]。因此 muP 与 7.2.1 的超参 scaling law 是互补关系：muP 先把宽度维度"折叠"掉以压缩搜索空间，剩下的 $(N, D, C)$ 维度交给幂律拟合，最后在 1–2 个中间规模做外推验证。

### 7.3 学习率调度与 batch size

#### 7.3.1 WSD 取代 cosine

cosine 调度的结构性缺陷在于调度形状与预先承诺的总步数强耦合：中途延长训练、提前取可用 checkpoint、或对同一模型做多预算 scaling 实验都必须重训[^119^]。WSD（Warmup-Stable-Decay，由 MiniCPM 于 2024 年推广）把训练分为预热、长时间恒定峰值、短促衰减（约占最后 10–20% tokens）三段：稳定期 loss 偏高但衰减期骤降，终损可与 cosine 打平甚至更低；其工程优势是可以从一个稳定期 checkpoint 分支多个衰减 run（数学/代码/长上下文特化）而无需重训[^113^]。Hägele et al.（NeurIPS 2024）给出了严格对照：恒定 LR + cooldown 与调优 cosine 在等算力下 loss 基本一致，长训练时 $(1-\sqrt{\cdot})$ 形状的 cooldown 甚至更优；cooldown 收益在约 20% 步数处饱和，超长训练 5% 已足够[^120^]。理论侧，Wen et al. 用"river valley"图景解释其机制——稳定期高 LR 沿"河道"快速前进但在山坡方向振荡（loss 虚高），衰减期压掉振荡、"显影"真实进展[^119^]。到 2024–2026 年，WSD 及其变体已成主流（DeepSeek 全系、MiniCPM、SmolLM3、Kimi K2、Nemotron-3 等），经验配比为 warmup <1%、stable 80–90%、decay 10–20%、峰值/末值 LR 比约 10×[^121^]；反例方面，GLM-4.5 早期实验发现 WSD 训练的模型在部分通用基准（SimpleQA、MMLU）上表现更差（原文归因于稳定期欠拟合迹象，未给出数据），故弃用 WSD 改用 cosine 调度；据此终损优势尚无共识，WSD 的确定性收益在工程灵活性[^121^][^58^]。

退火（decay/annealing）阶段还有一个被反复验证的配方细节：MiniCPM 在衰减期把高质量无标注数据与 SFT 数据混入预训练语料，消融表明这比把同样数据留到 SFT 阶段收益更大——能力专精应从 decay 阶段开始[^113^]。该发现与第 8 章多阶段训练中"退火期上采样高质数据"的行业惯例互为印证。

#### 7.3.2 关键 batch size 与 ramp 惯例

关键 batch size（critical batch size, CBS）指超过它之后增大 batch 的步数收益急剧递减的临界点。McCandlish et al.（2018）提出用梯度噪声尺度 $B_{simple}=\mathrm{tr}(\Sigma)/\|G\|^2$ 估计 CBS：$B\ll B_{noise}$ 时适用 LR 线性缩放规则，$B\gg B_{noise}$ 时增 batch 不再降 loss[^122^]。2024 年后的实证修正了两点认知：其一，Zhang et al.（ICLR 2025）系统测量 85M–1.2B 模型，发现 **CBS 主要随数据规模增长（$\approx D^{0.47}$）而与模型规模基本无关**，与 muP 的无限宽分析一致[^123^]；其二，Merrill et al.（2025）用分支训练直接测量 OLMo-1B/7B，发现梯度噪声尺度低估 CBS 数个数量级、定性趋势也不符，实测 CBS 初始接近零、快速增长后趋平——这为"batch size warmup"提供了依据，其实验以比原训练少 43% 的步数达到更优 loss[^124^]。

CBS 随训练进程增长的性质直接解释了工业界的 batch size ramp（逐步增大）惯例：Llama 3 405B 从 4M tokens（序列长 4096）起步，252M tokens 后翻倍到 8M/8192，2.87T tokens 后再翻倍到 16M，作者称该配方极少 loss spike、无需人工干预[^5^]；DeepSeek-V3 在前 469B tokens 内把 batch 从 3072 逐步增至 15360 个序列（即 12.6M→62.9M tokens）后保持[^2^]。早期用小 batch 换稳定性、后期用大 batch 换吞吐，且因 CBS 初期接近零，小起步几乎不损失 token 效率。最后一个常见错误：调整 batch 时，SGD 的线性 LR 缩放规则不适用于 Adam——Adam/RMSProp 理论上应使用平方根缩放（batch 增 4 倍，LR 增 2 倍），把线性规则照搬到 Adam 是预训练调参中的高频失误[^122^][^125^]。

## 8. 多阶段训练、退火与长上下文扩展

2024–2026 年的旗舰模型几乎全部放弃了"单一配比训到底"的做法，转向"通用预训练 → 高质量退火/中训练（mid-training） → 长上下文扩展"的多阶段课程。2025 年 10 月发表的系统性综述将中训练（介于大规模预训练与监督微调之间）正式定义为独立阶段，并把方法学归纳为三个维度：数据分布调整、学习率调度、长上下文扩展 [^1^]。本章按"退火方法论 → 长上下文扩展"两条线索展开，两者共享同一套工程纪律：阶段切换处的超参联动、数据配比与评估准入标准。

### 8.1 退火（annealing）方法论

退火指在预训练末段将学习率（Learning Rate, LR）衰减至接近零，同时把数据分布切换到高质量、能力定向的语料。两个操作通常同时发生，但它们的贡献并不相同——这正是本节两小节分别处理的归因问题。

#### 8.1.1 Llama 3 末 40M tokens 线性退火+Polyak 平均：8B GSM8K +24% 而 405B 无效（增益不随规模外推）；退火作为低成本数据评估协议（30% 新数据+70% 默认配比）

Llama 3 的退火配方是：在最后 40M tokens 上将 LR 线性退火到 0（保持 128K 上下文长度），同时上采样极高质量数据源，并对退火期间的 checkpoint 做 Polyak 平均（即对参数做滑动平均）产出最终模型 [^5^]。Meta 同时报告了一组揭示规模效应的实验：在退火数据中混入 GSM8K/MATH 训练集，使 8B 模型在两个验证集上分别提升 24.0% 和 6.4%，但同样的操作对 405B 模型的提升"可忽略"（negligible）[^5^]。这一事实的高置信解读是：模型越大、预训练越充分，退火的边际收益越小；对中小模型退火是"补课"，对旗舰模型更多是"收尾稳定"。需要并列指出的是，OLMo 2 在 7B–32B 规模上仍观察到中训练约 +10 分的整体提升 [^3^]——两者不完全可比（Llama 的 +24% 是混入基准同分布训练集的极端情形，OLMo 对比的是整体干预），但"退火增益不随规模线性外推"的警示成立。

Llama 3 的另一项方法论贡献是把退火本身变成数据质量评估工具：取 50% 训练进度的 8B checkpoint，在 40B tokens 上线性退火到 0，配比为 30% 待评估新数据 + 70% 默认配比，即可判断新数据源的价值，成本比逐数据集做 scaling law（尺度定律）实验低约一个数量级 [^5^]。OLMo 2 将这一协议进一步压缩为 microanneal：用约 10B token 的小规模退火独立评估单个数据源，19 次 microanneal 共消耗 130B tokens，不足 3 次完整 50B 退火的成本 [^3^]。这意味着评估新数据源不必等待完整训练，小规模退火已成为头部团队的标准内嵌度量。

#### 8.1.2 OLMo 2 解耦证据：仅 LR 退火不换数据拿到大部分通用增益（OLMES +4.4）但数学 −1.5——领域增益必须靠换数据；归因需固定 token/调度/初始化消融

退火阶段 LR 衰减与换数据同时发生，归因混淆是该领域公开承认的短板。OLMo 2 的对照实验提供了目前最干净的解耦：只衰减 LR、保持预训练原配比（PT Mix 组），就能获得大部分通用增益——OLMES 均分 +4.4、MMLU +2.0；但数学开发集（GSM*）反而下降 1.5 分，只有把数学/指令数据换入配比，GSM* 才从 28.5 升至 52.0 [^3^]。结论可以精确表述为：通用能力的提升大半来自 LR 退火本身（降低梯度方差、稳定收敛），而领域能力的提升必须来自数据分布的改变。OLMo 2 的另一组实验进一步削弱了"高 LR 一定更好"的民间经验：预训练峰值 LR 在 3e-4/6e-4/9e-4 之间变动，只要最终退火到 0，最终训练 loss 与下游分数几乎相同——高 LR 预训练欠下的损失恰好被退火补回 [^3^]。

由此得到的消融纪律是：比较退火数据配方时，必须固定起点 checkpoint、token 数、调度形状与初始化/优化器状态，一次只改一个变量，并且用"仅 LR 退火"的对照组扣除退火自带增益，否则无法区分收益来自数据还是来自调度 [^3^]。

### 8.2 长上下文扩展

长上下文扩展通常单独成段，放在退火之后，只占总算力的约 1–5%——注意力计算随序列长度平方增长，全程长序列训练既不划算，研究也表明从一开始就超长反而损害短上下文能力 [^126^]。

#### 8.2.1 位置编码：YaRN 事实标准（省 10× token）；ABF 取值谱系 250K–1B 无共识（冲突区）

位置编码调整是扩展上下文的第一道工序。早期的线性位置插值（Positional Interpolation, PI）约支持 4 倍扩展；NTK-aware 方案改为缩放 RoPE（Rotary Position Embedding，旋转位置编码）的 base 频率，高频少插值、低频多插值，可免微调扩展到约 8 倍 [^127^]。2024 年后的事实标准是 YaRN：把 RoPE 维度按频率分三段处理（高频不插值、低频线性插值、中频 NTK 式渐变）并加注意力温度校正（$\sqrt{t} = 0.1 \ln s + 1$），相比此前方法省 10 倍 token、2.5 倍训练步数，且能外推超出微调长度；DeepSeek-V3、Kimi K2、Qwen3（推理期）、Llama 3.1、Mistral Large 均采用 [^127^]。

与 YaRN 并行的工业界主力做法是 ABF（Adjusted Base Frequency，直接放大 RoPE base 频率）配合长数据持续预训练，实现最简单 [^128^]。但 ABF 的取值是典型的冲突区：综述整理的谱系从保守到激进跨度三个数量级——Phi-4 用 250K 支撑 16K 上下文，Qwen3 用 1M 支撑 32K，Pangu-Ultra 用 25.6M 支撑 128K，Hunyuan-Large 用 1B 支撑 256K [^129^]。理论与经验均未能收敛：dynamic NTK 公式给出的建议值在 ProLong 的消融中系统性偏小（64K 上下文下把 base 从 4×10⁶ 进一步放大到 8×10⁶ 反而更好），业界的立场是"无强共识，需按任务实测，宁大勿小" [^130^]。双方证据应并列采信：公式值可作下界参考，但最终取值必须通过消融确定。

#### 8.2.2 分阶段配方：Llama 3 六阶段 8K→128K/约800B tokens/双准入标准；DeepSeek-V3 两阶段各 1000 步 batch 1920→480；Kimi K2、Qwen3、Phi-4 配方（LR 降 10 倍、RoPE 250K、30% 新长数据）

#### 8.2.3 长数据从哪来：自然长文长尾稀缺；上采样书/代码 + 语义拼接（ICL +8%）+ 合成任务三策略叠加；Phi-4 证明自然长文优于拼接凑长；数据预算分歧 3 个数量级（冲突区并列）

自然长文档是长尾稀缺资源：网页、问答、社媒文本大多很短，网页等常见来源中超长文档（如超过 32K token）占比极低——此为工程综述的口径，Fu et al. 仅一般性论述长数据稀缺 [^1^][^131^]；书籍、学术论文、代码仓库能提供长连续结构，但总量和领域覆盖有限，仅靠自然长文不足以支撑长上下文训练。前沿配方因此叠加三类策略。第一，上采样长文档源：ProLong 的受控消融证明代码仓库和长书是最好的长数据，但必须混入高质量短数据，只训长数据反而损害长上下文性能 [^130^]。第二，语义拼接与排序优化：In-Context Pretraining 用近邻检索加图遍历把语义相关的短文档排进同一上下文，只改文档排序、不动训练管线，即获上下文学习（ICL）+8%、阅读理解 +15%、上下文忠实度 +16% [^132^]。第三，合成长上下文任务：Qwen2.5-1M、Qwen3 等在预训练中混入强调长程依赖的合成数据（填空、段落重排、检索类）[^6^]。在三类策略内部，Phi-4 的消融给出了一条明确的排序证据："天生长的"数据源（书、学术、代码中超过 8K 的原生长样本）显著优于人工拼接凑长的样本 [^9^]——拼接可作补充，不应为主体。

长上下文训练需要多少数据，是本领域差距最大的冲突区，双方证据并列如下：Fu et al.（ICML 2024）主张 0.5B–5B tokens 的平衡混合即可解锁 128K 检索能力，理由是"长上下文能力已在基座模型中，只需轻量解锁" [^131^]；DeepSeek-V3 的两阶段扩展也仅消耗约 119K H800 GPU 小时 [^2^]。另一端，Llama 3 用了约 800B tokens [^5^]，Phi-4 用 250B [^9^]，Qwen3 用数千亿 [^6^]——预算差距达三个数量级。ProLong 处于中间（40B tokens，仅为 Llama 3.1 长上下文数据量的 5%），且明确批评 Fu 的结论"在更全面的评测下不充分" [^130^]。调和视角是：Fu 与 ProLong 只验证了检索类能力或在 8B 小模型上，而前沿厂商的更大预算针对长文理解与推理等更难能力及 128K 以上的稳定表现；目前无实验在同一设定下直接对比，该分歧未收敛。

#### 8.2.4 评估警示：NIAH 仅作门控——RULER 显示一半 ≥32K 模型撑不住 32K 复合任务；NoLiMa 去字面匹配后 32K 处 10+ 模型跌破 50% 基线

"宣称长度 ≠ 有效长度"是长上下文评估的核心纪律。NIAH（Needle-in-a-Haystack，大海捞针）只适合做阶段性门控：Llama 3 把它用作每阶段"是否适应成功"的硬标准之一 [^5^]，但 RULER（NVIDIA）证明 vanilla NIAH 只测了表层检索——17 个宣称 ≥32K 的模型在 NIAH 上近满分，却只有一半能在 32K 的复合任务（多针检索、多跳追踪、聚合）上保持满意性能 [^133^]。字面匹配的漏洞更为尖锐：NoLiMa 设计了 needle 与 query 几乎无词汇重叠的测试，在 12–13 个宣称 ≥128K 的模型中，10–11 个在 32K 处就跌破各自短文本基线的 50%；GPT-4o 从 99.3% 掉到 69.7% [^134^]。两组证据共同说明：最容易"虚假达标"的恰恰是纯检索能力，这也解释了 8.2.3 节中低预算配方（只验证检索）与高预算配方之间的评价鸿沟。

实践含义有三：NIAH 只作门控、不作结论；上线前必须跑 RULER/HELMET/NoLiMa 类复合基准，并监控短上下文能力是否回归；交付"有效上下文长度"时应注明评测协议——ProLong 的协议（不看困惑度或简单 NIAH，而看 SFT 后的一组下游长上下文任务）可直接复用 [^130^]。

## 9. 大规模训练工程与稳定性

当参数规模与集群规模同时越过阈值，预训练的主要矛盾从算法转向工程：数千至上万张加速卡需要以正确的并行切分协同工作，低精度数值方案决定吞吐上限，而硬件故障与 loss spike（损失尖峰）则决定一次训练能否跑完。本章按"并行→精度→稳定性→成本"的顺序梳理 2024–2026 年旗舰模型的公开工程实践，并特别强调各类对外数字的统计口径——它们是误读的重灾区。

### 9.1 并行策略

大模型训练需要在多个维度上切分计算与状态：数据并行（Data Parallelism, DP）切分批次，张量并行（Tensor Parallelism, TP）在层内切分权重矩阵，流水线并行（Pipeline Parallelism, PP）按层切分模型，专家并行（Expert Parallelism, EP）为 MoE（Mixture of Experts，混合专家）模型切分专家，上下文并行（Context Parallelism, CP）沿序列维切分。通行的排布原则是按带宽/延迟分层：通信最密集的 TP 限制在节点内 NVLink 高带宽域，通信容忍度最高的 DP 放在最外层以吸收跨机房网络延迟[^5^]。

#### 9.1.1 Llama 3 4D 并行（16K 卡，TP8/PP16/DP128）vs DeepSeek-V3 16 路 PP+64 路 EP+DualPipe 双向流水线隐藏跨节点通信、完全免去 TP

Llama 3 405B 与 DeepSeek-V3 代表了两种成熟的并行设计哲学，其配置差异几乎完全由模型结构（dense vs MoE）与网络拓扑决定。

| 维度 | Llama 3 405B（16,384×H100） | DeepSeek-V3（2,048×H800） |
|---|---|---|
| 并行配方 | 4D：TP×CP×PP×DP，主阶段 TP8/CP1/PP16/DP128 [^5^] | 3D：16 路 PP + 跨 8 节点 64 路 EP + ZeRO-1 DP [^2^] |
| 是否用 TP | 用（TP=8，置于节点内） | 完全不用，以精细显存优化替代 [^2^] |
| 长上下文阶段 | 131,072 序列时改为 TP8/CP16/PP16/DP8 [^5^] | 两阶段 YaRN 扩展（4K→32K→128K） |
| 跨节点通信隐藏 | NCCLX 集合通信库 + RoCE 三层 Clos 网络 | DualPipe 双向流水线：微批次从流水线两端同时注入，每个 chunk 拆为 attention/dispatch/MLP/combine 四段，前反向计算-通信互相重叠，实现近零 all-to-all 开销 [^2^] |
| 拓扑适配技巧 | pod 内 3,072 GPU 全二分带宽 | node-limited routing：每 token 最多分发到 4 个节点，仅 20 个 SM 即可打满 IB+NVLink 带宽 [^2^] |
| 报告 MFU | 38–43%（BF16）[^5^] | 第三方反推约 343 TFLOPS/GPU 综合吞吐（含停机）：对官方标称 989 TFLOPS 峰值约 34.6%，该文另按 877 TFLOPS 非标峰值口径计得约 39% [^135^] |

两组配方的对照揭示了三点规律。其一，TP 的取舍是通信成本与显存压力的权衡：Llama 3 用 NVLink 域内的 TP=8 换取显存余量，DeepSeek-V3 则因 MoE 的 EP 已占用跨节点带宽预算，宁可做更激进的显存优化也要免去 TP 的昂贵通信[^2^]。其二，MoE 跨节点 EP 会使计算:通信比恶化到约 1:1，DualPipe 的双向调度本质上是把流水线气泡与 all-to-all 通信互相填充，这是 MoE 大规模训练可行的关键使能技术[^2^]。其三，并行配置不是静态的：Llama 3 在长上下文阶段把 DP 从 128 降到 8、CP 升到 16，MFU 相应从 41% 降至 38%——序列并行引入的额外通信是直接的成本项[^5^]。学习者据此应建立的第一条纪律是：先画出自己的网络拓扑与带宽层级，再决定并行维度的内外排序，而不是照搬任何一家的数字。

### 9.2 精度革命

混合精度训练的长期默认是 BF16（bfloat16）计算 + FP32 主权重与优化器状态。2024–2025 年，FP8（8 位浮点）训练完成了从论文到万亿参数级生产的跨越，成为吞吐提升的最大单点来源。

#### 9.2.1 DeepSeek-V3 首次大规模验证 FP8：1×128/128×128 细粒度量化+每 128 元素提升 FP32 累加（消融 loss 误差 <0.25%，注意该数字仅来自约 1T token 消融）；Ling-1T 全程 FP8 获 15% 端到端加速

DeepSeek-V3 是首个在超大规模上验证 FP8 训练的公开案例：全部 GEMM（通用矩阵乘，含前向 Fprop 与反向 Dgrad/Wgrad）使用 E4M3 格式 FP8，支撑其稳定性的关键技术有三[^2^]：

1. **细粒度量化**：激活按 1×128 tile、权重按 128×128 block 分组缩放，在线计算每组 absmax（绝对值最大值），抑制 outlier（离群值）对全张量单一缩放因子的污染[^2^]；
2. **提升累加精度**：H800 的 FP8 Tensor Core 累加器仅有约 14 位有效尾数，直接累加长链会显著丢精度；方案是每 $N_C=128$ 个元素（约 4 个 WGMMA 指令）就把部分和提升（promote）到 CUDA Core 的 FP32 寄存器做高精度累加[^2^]；
3. **选择性高精度保留**：Embedding、输出头、MoE gating、Normalization 与 Attention 模块保留 BF16/FP32，主权重、梯度与优化器状态保持 FP32[^2^]。

在约 16B 与 230B 两个规模、各约 1T token 的对照消融中，FP8 相对 BF16 基线的 loss 相对误差持续低于 0.25%[^2^]。引用该数字必须注明口径：它来自受控消融，而非 14.8T token 全量 FP8 训练与 BF16 的对比——全量跑并不存在 BF16 基线[^2^]。蚂蚁集团的 Ling-1T（1T 总参/50B 激活）则把 FP8 推到更大规模：全程块级 FP8 训练 20T+ token，配合 QK-Norm 抑制 outlier 与实时监控，报告 15% 端到端加速；其 loss 偏差存在两个口径——技术报告为 900B token 处 ≤0.25%，官方模型卡称 1T token 内 ≤0.1%，引用时应注明来源[^136^][^137^]。两个案例共同确认的边界是：低精度可以覆盖计算主导的 GEMM，但注意力核心、归一化与累加路径保留高精度是不可省略的约束。

### 9.3 稳定性与容错

万卡集群上，故障不是异常而是日常；loss spike 不是会不会发生的问题，而是能否在发生后恢复的问题。

#### 9.3.1 Llama 3 实测：54 天 466 次中断（419 意外、~78% 硬件、Faulty GPU 148 次为最大单一来源、仅 3 次需人工、有效训练时间 >90%）；注意 Llama 3 Table 5 计数自洽性问题，引用计数而非百分比

Llama 3 405B 论文公布了大模型训练领域最详尽的故障实测数据：在 54 天快照期内，16,384 卡集群共经历 466 次作业中断，其中 47 次为计划内（固件升级等），419 次为意外中断，平均约每 3 小时一次；意外中断中约 78% 归因于确认或疑似的硬件问题，GPU 相关类别（Faulty GPU 148 次、HBM3 显存 72 次、SRAM 19 次等）合计为最大来源；全部中断中仅 3 次需要重大人工干预，其余由自动化系统处理，最终有效训练时间超过 90%[^5^]。

引用这组数据有两条注意事项。第一，论文 Table 5 存在内部不一致：表内 17 项意外中断计数相加为 417，与正文的 419 不符；"Faulty GPU 30.1%"的印刷百分比与 148/419≈35.3% 对不上，表中百分比合计仅 94.4%[^138^]。因此稳妥做法是引用**事件计数**（466/47/419、148 次 Faulty GPU）而非百分比，且"78% 硬件"与"GPU 类 58.7%"的分母口径不同，不可混用[^138^]。第二，外部转述口径分歧明显（如 AWS 文档引作 417 次、SemiAnalysis 称 419 次 GPU 服务器故障），应以论文原文"419 unexpected interruptions（含非硬件原因）"为准[^5^]。

#### 9.3.2 loss spike 处置范式：回滚 checkpoint+跳过 200–500 批次+降 LR（PaLM/OPT）；预防：QK-Norm/z-loss/MuonClip（Kimi K2 15.5T 零 spike，厂商自报口径）、GLM-130B EGS、小 batch 起步

spike 的成因谱系包括 outlier 批次、梯度爆炸、低精度溢出与 attention logit 失控等；PaLM 540B 训练中约出现 20 次 spike，且回放触发批次不必然复现，提示其并非单纯的数据问题[^139^]。经典处置范式已经形成标准化流程：从 spike 前约 100 步的 checkpoint 回滚重启，跳过约 200–500 个后续批次，必要时降低学习率——PaLM 与 OPT-175B 均沿用此组合，BLOOM-65B 则因 spike 处置额外消耗约 30 天与 129.3 MWh，稳定性的代价可以直接折算为钱[^139^]。

更具方法论价值的是预防层的收敛。GLM-130B 发现梯度范数尖峰通常先于 loss 崩溃数步出现，根因定位在 embedding 层梯度异常，用 Embedding Gradient Shrink（EGS，缩放系数 α=0.1）消除了大部分 spike，正式训练仅发生 3 次晚期发散[^140^]。Kimi K2 的 MuonClip 在 Muon 优化器上叠加 QK-Clip：每步监测各 head 的最大 attention logit，超过阈值 τ=100 时重缩放对应 Q/K 投影权重，厂商自报在 15.5T token 全程零 loss spike，且约 30% 步数后 clip 自然停止触发[^141^]。MoE 模型的 z-loss（对 router logit 的惩罚项）与 QK-Norm 也是常见防线[^136^]；Llama 3 则靠小 batch 起步（4M→8M→16M token 两阶段爬坡）实现"极少 spike 且无需干预"[^5^]。必须声明的归因限制是：Kimi K2 与 DeepSeek-V3 的"零 spike"均为厂商自报且无公开对照实验剥离单一因素贡献，宜视为"该整体配方在此规模可行"的证据，而非某单项技术的因果证明[^141^]。

### 9.4 成本与效率指标

#### 9.4.1 DeepSeek-V3 全程 2.788M H800 小时（$5.576M 仅含正式训练，不含前期研发）；Llama 3 405B 为 30.84M H100 小时；MFU 基准 PaLM 46%、Llama 3 38–43%（注意 MFU 分母口径差异）

DeepSeek-V3 报告全程训练消耗 2.788M H800 GPU 小时（预训练 2.664M + 长上下文扩展 119K + 后训练 5K），按每 GPU 小时 \$2 的租金假设折算为 \$5.576M[^2^]。这个数字的传播中常被省略的限定是：它仅含正式训练，不含前期研究、消融实验、数据、人力与集群资本开支——论文原文明确声明了这一点[^2^][^142^]。作为对照，Llama 3 405B 官方模型卡披露训练累计 30.84M H100 GPU 小时[^4^]，约为前者的 11 倍，但 dense 与 MoE 架构、H100 与 H800（出口受限版）的 GPU 小时不可直接比价，这一倍数只有量级参考意义。

效率侧的标准指标是 MFU（Model FLOPs Utilization，模型算力利用率）：PaLM 540B 约 46%，Llama 3 405B 报告 38–43% BF16 MFU（8K 卡 43%、16K 卡 41%、128K 长上下文阶段降至 38%）[^5^][^143^]。使用 MFU 比较时有三个口径陷阱：其一，MFU 不计故障重放的损失，长跑训练必须结合 goodput（有效吞吐，Llama 3 的有效训练时间 >90%）评估[^144^]；其二，分母是硬件峰值算力，而峰值口径本身就可能存在分歧：NVIDIA 官方 datasheet 中 H800 SXM 与 H100 的标称 AI 算力相同（BF16 稠密峰值均为 989 TFLOPS），H800 相对 H100 削减的是 NVLink 互联带宽（900→400 GB/s）与 FP64，而非 AI 算力；但有第三方审计文章在核算 DeepSeek-V3 时采用了"H800 峰值 877 TFLOPS"这一未经官方确认的口径——对同一实测吞吐（约 343 TFLOPS/GPU），除以官方 989 TFLOPS 得约 34.6%，除以该文的 877 TFLOPS 则得约 39%，相差 4–5 个百分点[^135^]。这正说明 MFU 比较的第一步永远是确认分母口径；其三，MoE+FP8 训练的 MFU 通常低于 dense BF16 训练，跨架构比较意义有限[^143^]。

本章所有数字共享一条总纪律：前沿预训练的对外数字都是"带口径的数字"。GPU 小时要先问是否含研发与失败实验、是哪一代硬件；成本折算要问租金假设；MFU 要问峰值分母与是否计重放；稳定性指标要问是自报还是有第三方复现。跨模型比较的第一步永远是统一口径，否则比较无效——这既是阅读本章的方式，也是撰写任何训练报告时应有的自我要求。

## 10. 评估、消融与实验方法论

预训练配方无法通过理论推导获得，只能靠受控实验逼近。本章依次回答：消融如何设计才可信（10.1）、如何用退火协议低成本评估数据（10.2）、评估信号何时失效（10.3）、如何基于学习曲线选择 checkpoint 并规范报告（10.4）。

### 10.1 消融实验设计规范

#### 10.1.1 控制变量、多尺度多 seed 与分级验证阶梯

消融的第一原则是**一次只改一个因素，其余全部冻结**。DeepSeek-V3 的技术报告明确声明消融时"保持训练数据与其他架构不变"，并在 15.7B MoE（1.33T tokens）与 228.7B（540B tokens）两个规模上分别复跑同一组消融以验证结论一致性[^2^]；DCLM 则把整个公开基准建立在"固定训练配方、只更换数据"的设计之上，标准化数据加载、超参与评估任务，使不同提交之间严格可比[^17^]。对数据消融而言，tokenizer 必须保持一致——既因为不同 tokenizer 下 token 数与 loss 口径不可比，也因为 RegMix 类方法的配比权重只在共享 tokenizer 的 proxy 与目标模型之间可迁移[^49^]。

第二个原则是**结论必须跨规模、跨训练时长复核**。OLMo 2 的学习率实验显示，较高学习率在训练早期取得更低 loss，但在约 200B tokens 之后被较低学习率反超——原文明言"更短的超参实验可能得出错误结论"[^3^]；只在一个时点打分的消融，结论可能恰好落在交叉点之前。第三个原则是**多 seed 复跑**：DataDecide 在 1050 个模型（25 种配方 × 14 个规模 × 3 个 seed）上测得，1B 规模下同配方不同 seed 的下游分数标准差最高可达约 2 个百分点[^54^]，故单 seed 下小于 2 个百分点的差异不应作为结论，关键消融应跑不少于 3 个 seed 并报告均值与标准差。

在工程组织上，头部团队收敛到一个**三级验证阶梯**：小 proxy 筛选 → 中等规模复核 → 目标 checkpoint 上 continued-training 或退火验证。Llama 3 的数据配比流程即"小模型 scaling law（尺度定律）实验选出候选配比 → 更大模型训练并在关键 benchmark 上复核"，且迭代多轮[^5^]；SmolLM3 的方法论手册则主张数据消融直接在目标 3B 规模上跑 50B–100B token 短训，理由是很小的模型存在容量饱和失真（如吃不下多语言配比），"在过小的规模上做数据消融有得出错误结论的风险"[^126^]。两种策略的分歧本质是预算与失真风险的权衡，下表汇总了各级协议的代表性做法。

| 协议 | 代表工作 | 规模与成本 | 输出信号 | 主要局限 |
|---|---|---|---|---|
| 极小 proxy 回归 | RegMix：512 个 1M 模型各训 1B tokens，约合一次 1B 训练 FLOPs 的 2% [^49^] | 极低，可完全并行 | 配比排序 | 排序不变性仅验证到 1B；需已知域划分与共享 tokenizer [^49^] |
| 单规模排序 | DataDecide：150M 排序预测 1B 最优配方，连续似然指标下用 0.01% 算力达 >80% 决策正确率 [^54^] | 低 | 数据源/配方排序 | 只给排序不给数值；涉及容量饱和的决策失效 [^54^][^126^] |
| 目标规模短训 | SmolLM3：3B 模型跑 50B–100B tokens [^126^] | 中 | 接近真实的配比结论 | 仍可能未越过训练时长交叉点 [^3^] |
| 退火评估 | Llama 3：50% 训练进度的 8B checkpoint 线性退火 40B tokens，30% 新数据 + 70% 默认配比 [^5^] | 中低，比逐数据集 scaling law 实验便宜约一个数量级 [^5^] | 单个数据源价值 | 单点估计，不含数据效用随 token 数的变化 [^145^] |
| 高效验证 | OpenBMB/MiniCPM 系：1.1T tokens 基座 + 10B tokens 二阶段退火，约 110 GPU 小时（对照：100B 从头训练约 1200 GPU 小时）[^146^] | 低 | 数据源价值，μP 保证超参可迁移 | 依赖 stable 阶段 checkpoint 质量 [^146^] |
| microanneal | OLMo 2：19 次数据源级短退火合计 130B tokens，成本低于 3 次完整 50B 退火 [^3^] | 低 | 数据源粒度信号（<10B tokens 即可见） | 需扣除退火本身的增益 [^3^] |

表中的规律是：proxy 越小，单位算力覆盖的候选越多，但结论适用边界越窄——RegMix 的排序不变性只验证到 1B，DataDecide 的 80% 正确率只覆盖"数据源两两比较"。协议越接近目标配置，信号越真，但成本上升且仍留有陷阱：OLMo 2 的交叉点教训表明，即便在目标规模短训，未覆盖足够训练时长照样会被误导。实务含义是把预算按"筛子—漏斗"分配：大量小实验做排序筛选，少量大实验做数值复核，任何一步都不承担超出其证据强度的决策。

### 10.2 退火评估法与 checkpoint 平均

#### 10.2.1 microanneal、差分 U(D) 法与 checkpoint souping

退火评估法的标准配方（50% 进度 checkpoint 线性退火、30% 新数据 + 70% 默认配比）由 Llama 3 确立，标准配方见 8.1.1 节，此处只展开增量内容。两个细节决定该方法的有效性：其一，退火数据必须剔除常用 benchmark 的训练集，否则测的是记忆而非泛化能力[^5^]；其二，退火窗口长度有下限——MiniCPM 的实验表明占总步数 10% 的衰减窗口足以达到甚至超过 cosine 调度的效果，而 2.5% 不足[^113^]。

退火协议有两个必须控制的混淆因素。第一是**退火本身的增益**：OLMo 2 测得仅做学习率退火、不换数据，OLMES 平均分就能提升 4.4 分，因此比较两个数据源时必须跑"有/无该数据"的对照退火并做差，而非直接比较退火终点分数[^3^]。第二是**单点估计的盲区**：Llama 3 式单窗口退火无法刻画数据效用随 token 数的变化，后续工作（arXiv 2507.22250）将其扩展为变时长退火（210M–7.5B tokens）、固定 10% 上采样率，并定义差分效用 $U(D) = S_{base} - S_D$（无该数据源与有该数据源的退火分数之差）以隔离"多训了 token"的混淆，进而拟合数据源级的 scaling law[^145^]。还需强调退火结论不跨规模外推：Llama 3 在 8B 上退火混入 GSM8K/MATH 训练集带来 +24.0%/+6.4% 的验证集提升，但同样操作在 405B 上的增益"可忽略"[^5^]——小模型的退火增益幅度不能作为大模型的预测值。

在 checkpoint 层面，头部实践已从"选单点最优"转向"退火末端平均"。Llama 3 对最终退火阶段的 checkpoint 做 Polyak 平均得到发布模型[^5^]；OLMo 2 的 checkpoint souping 更激进——对同一配比的 3 个不同数据顺序各跑一次退火，再对三个终点权重取平均，在 6 个候选配比上一致取得等于或优于任一单个 checkpoint 的成绩[^3^]。由于多个退火 run 的权重处于同一损失盆地，平均操作近乎免费地消除了数据顺序噪声。

### 10.3 评估可信度

#### 10.3.1 loss 与 benchmark 之争、小模型排序翻转风险

验证集 loss 能否代表下游能力，是评估方法论中证据直接对撞的冲突区。正方的代表性结果是 Gadre et al. 提出的幂律：下游 top-1 error 可表示为预训练困惑度的幂函数，用 20–300 倍更少的算力即可从中小规模实验预测大模型的平均下游 error[^147^]。反方的代表性结果是 EMNLP 2025 Findings 的系统性实验：loss 到下游的映射随验证集、任务、预训练语料三者交互而变化，选错验证语料可以完全翻转 scaling 趋势——甚至出现"预训练语料 A 验证 loss 更差、下游却更好"的情形[^148^]。补充证据还有：Smol 手册指出 Wikipedia 类数据的 loss 系统性虚低、跨 tokenizer 的 loss 不可比、数学推理能力在平均 loss 上显现得极晚[^126^]；以及 perplexity 排名与下游排名的相关性在 base 模型上 Kendall τ≈0.78，在 instruction-tuned 模型上仅 0.51[^149^]。综合双方证据可得一个可操作结论：loss-下游映射只在**同一数据分布、同一评估协议**内部成立，跨语料或跨训练阶段的比较必须使用下游 benchmark。

小模型排序能否外推到大模型，同样证据并存。正面：DataDecide 证明 150M 单规模排序能以约 80% 的正确率预测 1B 规模的最优数据配方，且 8 种 scaling law 外推基线均未超过这一"单规模排序"基线[^54^]。反面：Goyal et al. 证明数据过滤决策不是算力无关的——低算力下最优的激进过滤（只保留 top 10%），在数据重复超过约 35 个 epoch 后被"完全不过滤"反超[^150^]；微软 MAI-Thinking-1 报告据二手转述给出了 23B 规模上两种配比曲线在 20T tokens 训练中段交叉的反例（未核原文，置信度中）[^151^]；SmolLM3 手册则警告涉及容量饱和的决策（如多语言配比）在小模型上结构性失真[^126^]。调和图景是：排序对"数据源两两比较"大体可靠，对涉及数据耗尽、超长预算、容量饱和的决策不可靠；且排序可迁移不等于数值可迁移——最优配比的具体百分比必须按目标规模重新标定。

#### 10.3.2 去污染、LLM-as-a-judge 校准与切片化评估

**去污染是一切评估的前提**。Inference-Time Decontamination（ITD）实验量化显示，去除污染后模型在 GSM8K 上的分数虚高幅度达 22.9%、MMLU 达 19.0%，Phi-3 与 Mistral 在 MMLU 上分别下降 6.7 与 3.6 个百分点——虚高幅度足以翻转模型间排名[^44^]。流程化的应对包括：DCLM 不直接对数据池去污染，而是发布工具并要求所有提交披露去污染报告[^17^]；OLMo 是首个对困惑度评估做显式去污染的模型（删除与 Paloma 评估段落重叠的预训练文档）[^152^]；OLMo 2 确立了开发集与留出集分离的标准实践——开发决策只用 dev 套件（如 GSM8K 只抽 200 题构成 GSM\*，其余 1119 题留到最终评估），并公开声明开发期监控了哪些任务[^3^]。

对生成类任务常用的 LLM-as-a-judge 范式，偏差已被量化且校准手段成熟。MT-Bench 论文确认三类系统性偏差：位置偏差（GPT-4 交换答案顺序后一致性仅约 65%）、冗长偏差（"重复列表"攻击可骗过所有受测 judge）、自我增强偏差[^153^]。对应的校准纪律是：成对评估必须双顺序各跑一次、结果不一致判平局；few-shot 提示可将顺序一致性从 65% 提升到 77.5%（但引入新偏差且成本增至 4 倍）；GPT-4 judge 与人类的 agreement 超过 80%，已达人际一致水平[^153^]。工程综述进一步建议：judge 与被评模型分属不同家族以防 echo-chamber，评分 rubric 显式要求长度中立，每次更换 judge 模型都用人工标注集重新校准[^154^]。

最后，评估应当**切片化而非单一总分**。HELM 的模板是对 16 个核心场景各测 7 个指标（accuracy、calibration、robustness、fairness、bias、toxicity、efficiency），另设 26 个 targeted 场景专项分析记忆/版权、推理与虚假信息[^155^]；OLMo 用 Paloma（585 个文本域的分层样本）做细粒度困惑度评估[^152^]；"The Fine Line"研究证明不同下游能力的训练动态不同步——某一能力的曲线平台不代表其他能力也饱和，需按能力分别跟踪（结论在 67B 内跨规模成立）[^156^]。对小规模消融而言，benchmark 本身需要筛选：FineWeb 的四条标准是不同随机数据样本间方差小、分数近单调上升、早期即高于随机基线、排序在后期稳定——SIQA 因噪声过大被其剔除[^16^]；指标上优先用连续似然（如按字符归一的正确续写概率 Correct Prob）而非离散 accuracy，前者显著提升了小规模决策正确率[^54^]。

### 10.4 checkpoint 选择与学习曲线

#### 10.4.1 看曲线而非单点、final 与 best 的选择、成本与保留率的报告规范

第一条规范是**用学习曲线而非终点快照做决策**。OLMo 2 的学习率交叉点（200B tokens 之外）说明任何单时点比较都可能落在交叉前区间[^3^]；训练中在线评估是标准配置——OLMo 每 1000 步（约 4B tokens）跑一次下游任务以指导架构、优化器与配比决策，Llama 3 亦在训练中多次根据 benchmark 表现动态调整配比[^152^][^5^]。聚合指标的设计也服务于降噪：DCLM 用 centered accuracy（0 为随机、1 为完美）聚合 22 个低方差 Core 任务，使小模型规模的信号可用[^17^]。

第二条规范是**明确区分 final 与 best checkpoint 并优先报告平均化结果**。预训练中不存在传统意义的"按验证集早停"：WSD 调度的价值之一正是可从 stable 阶段任意 checkpoint 衰减出新终点，不必预先承诺总步数[^113^]。但 Power Scheduler 的实测修正了这一叙事——最优学习率仍与总 token 数耦合，偏离原计划时续训出的中间 checkpoint 是次优的[^157^]。在终点选择上，如 10.2 所述，退火末端的多 run 平均（Polyak 平均 / model soup）一致优于任一单点 best[^3^][^5^]，因此规范做法是同时报告 final（平均后）与 best（单点最优）两者及各自口径。

第三条规范是**成本与保留率随结论同步报告**。评估方法论类工作的核心产出应是"算力—决策正确率"前沿而非单一数字：DataDecide 以该前沿为主图[^54^]，OpenBMB 报告每个验证策略的 GPU 小时（高效验证约 110 小时 vs 100B 从头训练约 1200 小时）[^146^]，DCLM 对每个规模标注 H100 小时[^17^]。数据管线类工作还应报告过滤保留率（如 C4 约 11%、FineWeb 约 17%、DCLM 约 1.6%），否则读者无法评估复现所需原始数据量与目标算力下数据耗尽的风险[^158^]。

## 11. 跨维度洞察、常见误区与开训清单

前 10 章按维度分别展开；本章把各维度报告交叉比对后浮现的八条结构性规律（依据跨维度调研材料的综合提炼）、学习者最高频的十个误区，以及一份可直接执行的开训前检查清单汇总于此，作为全书的收束。

### 11.1 跨维度洞察

#### 11.1.1 预训练已演变为课程化多阶段系统工程

2024–2026 年的旗舰模型几乎全部放弃"单一配比训到底"，转向"通用预训练（约 90% FLOPs）→ 知识密集中训练（mid-training）/退火（5–10% FLOPs）→ 长上下文扩展（1–5% 算力）"的三段式课程；Qwen3、Llama 3、DeepSeek-V3、Phi-4 等六家配方呈同一骨架，2025 年首个系统性综述将中训练正式定义为独立阶段，标志范式固化[^1^][^5^][^6^]。同期各家配比百分比几乎绝迹而阶段结构均被披露，说明竞争力已迁移到"何时切换、切换时换什么数据"。**启示**：学"阶段设计"而非背配比表——每个阶段明确目标函数（广度/深度/长度）与切换判据（如 Llama 3 的"短上下文恢复 + NIAH 满分"双准入），并为退火预留 10–20% token 预算（详见第 1、4、8 章）。

#### 11.1.2 数据工程从"过滤"转向"生产"（合成/改写/OCR 提取）

2023 年前的主线是"从 Common Crawl 筛掉坏的"，2024–2026 年变成"用模型生产新的好 token"：Qwen3 用 Qwen2.5-VL 从 PDF 提取数万亿 token 并合成数万亿 token，Nemotron-CC 含 1.9T 合成改写 token，Kimi K2 改写管线以"10× 改写 1 epoch"优于"原文 10 epochs"（SimpleQA 28.94% vs 23.76%）[^6^][^18^][^10^]。过滤路线的极限已被量化：FineWeb-Edu/DCLM 约 80% 为近重复（唯一 token 仅约 0.2T/1T），撑不起 15T 级长程训练[^18^]。但边界同样清晰：Phi-4 消融显示纯合成数据损害知识基准（TQA −14.8）并增加幻觉[^9^]。**启示**：数据预算编制要改问"现有 1T 能改写/提取/翻译出多少唯一 token"，守住三条安全绳——真实数据做种子与知识锚点、优先改写将被丢弃的中质量文档、生成后必须再过质量过滤（详见第 2、4 章）。

#### 11.1.3 稳定性设计成为隐形竞争点

旗舰训练的公开叙事是 benchmark 分数，实际拉开差距的是"15T token 零不可恢复 loss spike"这类指标：DeepSeek-V3（FP8 体系）与 Kimi K2（MuonClip）均自报全程零不可恢复 spike，背后是归一化设计、优化器约束、数值精度、运维容错四层防线的系统组合[^10^][^2^]。Llama 3 曾以"最大化训练稳定性"为由拒绝 MoE，不到一年后 Llama 4 全面转向 MoE，说明稳定性被视为可解决的工程成熟度问题而非架构本质缺陷[^5^]。注意归因强度限制：零 spike 均为厂商自报（归因限制见 9.3.2 节）。**启示**：按架构层（QK-Norm，注意与 MLA 不兼容）、优化器层（Muon 需配 QK-Clip）、精度层（FP8 细粒度量化 + FP32 累加）、运维层（梯度尖峰先行指标 + checkpoint 纪律）分层建工具箱，不指望任何单一"银弹"（详见第 6、9 章）。

#### 11.1.4 评估可信度危机与退火评估法兴起

危机侧证据充分：仅在改写版测试题上训练即可让 13B 模型刷到 GPT-4 水平且 n-gram 去污染完全失效（F1≈0）[^43^]；实测去污染后 GSM8K 分数虚高 22.9%、MMLU 19.0%[^44^]。应对侧多家实验室独立收敛到小预算退火评估协议这一形态——在退火段混入待评估数据的小规模评估（Llama 3 的"30% 新数据 + 70% 默认配比"为原型，OLMo 2 microanneal、OpenBMB、NVIDIA 各自复用该形态），把评估内化为训练管线的一环[^5^][^3^]。**启示**：不轻信任何单一 benchmark 数字；做数据决策时用退火评估自建内部度量，并遵守纪律——剔除 benchmark 训练集、跑有/无对照以扣除仅 LR 退火自带的增益（OLMo 2 测得 +4.4 OLMES）、dev/held-out 分离、多 seed[^3^]（详见第 3、8、10 章）。

#### 11.1.5 排序可迁移≠数值可迁移的方法论含义

跨维度证据收敛到一个精确划分：小模型实验给出的**排序**大体可信——DataDecide 用 150M 单尺度排序以约 80% 正确率预测 1B 最优数据，DCLM 的 400M 数据排序与 7B 相关 r≈0.89–0.92[^54^][^17^]；但**数值**不可外推——AutoScale 证明最优配比绝对值随规模漂移[^56^]，退火增益从 8B 的 +24% 到 405B 的可忽略[^5^]。涉及容量饱和的决策（多语言配比、长训练 horizon），小模型结构性失真。**启示**：实验预算按"筛子→漏斗"分配——大量小实验做排序筛选，少量大实验做数值复核；凡依赖绝对数值的结论（配比百分比、tokens/参数、LR 常数）必须在自己的数据/tokenizer/规模上重拟合，禁止搬运论文常数（详见第 4、7、10 章）。

#### 11.1.6 成本账本口径陷阱

预训练报告的硬数字存在系统性口径问题：DeepSeek-V3 的 557.6 万美元仅是正式训练的 GPU 租赁折算，报告自己声明不含前期研究与消融实验，而消融成本参照 Step Law 实践与之同数量级[^2^]；"14.8T tokens"是"in our tokenizer"口径，同一文本在不同 tokenizer 下的 token 数可相差近一倍（工程实测口径）[^2^][^126^]；tokens/参数比率按总参与激活参计数可差一个数量级。**启示**：引用任何训练数字前先核对四件事——tokenizer 冻结了吗、参数怎么数、成本含不含研发与失败实验、效率指标的分母是什么；做竞品分析先建口径换算表再比较（详见第 1、5、7、9 章）。

#### 11.1.7 scaling law（尺度定律）常数不可移植但方法论已工业化

没有任何论文的常数可以跨栈搬运：Kaplan–Chinchilla 分歧大半被证明是参数计数与 warmup 未调优等实验协议假象[^107^]；tokens/参数实测常数从约 20 到 1875 悬殊分布[^115^][^113^]。但"小规模网格拟合幂律 → 外推 → 分级验证"的方法论已被 Qwen、StepFun（3700+ 模型、近 100 万 H800 小时）、MiniCPM 各自独立工业化，成为头部团队的标配基础设施[^115^][^113^]。**启示**：与其收藏论文数字，不如复制其实验设计——拟合网格怎么选、外推怎么分级验证、何时必须重拟合（换架构/优化器/tokenizer/数据分布）；最优超参地形是"宽平台"，不必追求精确最优点（详见第 7 章）。

#### 11.1.8 宣称上下文长度≠有效长度

厂商宣称的 128K–1M 上下文与生产可用的有效长度之间存在系统性差距：RULER 显示 17 个 NIAH 近满分模型只有一半撑住 32K 复合任务[^133^]；NoLiMa 去除字面匹配后 GPT-4o 从 99.3% 跌至 69.7%[^134^]。解锁预算的分歧同时达 3 个数量级（0.5B vs 约 800B tokens）——调和视角是低预算研究只验证了检索类能力，而检索恰是最易"虚假达标"的能力[^131^][^130^]。**启示**：NIAH 只作门控不作结论，必须跑 RULER/HELMET/NoLiMa 类复合基准并监控短上下文回归；训练时遵循"训长于评测长度"原则；对外交付"有效上下文长度"时标注评测协议（详见第 8 章）。

### 11.2 常见误区 Top 10

1. **"Chinchilla 的 20 tokens/参数是铁律。"** 该常数依赖 tokenizer、数据质量、LR 调度与参数计数口径，实测谱系从约 20（Chinchilla）到 1875（Llama 3 8B 刻意超量训练）[^5^][^12^]。正解：tokens/参数是需在自己栈上重拟合的变量，摊入推理成本后还应"更小更久"。
2. **"全局去重越彻底越好。"** FineWeb 消融发现跨快照全局去重系统性保留老快照的低质幸存内容、误删新近高质量重爬，收益反不如逐快照去重[^16^]；Nemotron-CC 的全局去重是为 15T 长程训练的唯一 token 量服务的[^18^]。正解：先定 token 预算与 epoch 数，再联合决定去重粒度。
3. **"NIAH 满分 = 长上下文能力达标。"** 检索类任务最易"虚假达标"，多数 NIAH 满分模型撑不住复合任务[^133^][^134^]。正解：NIAH 仅作门控，结论以 RULER/NoLiMa 类复合基准为准。
4. **"预训练占 90% 成本是普适常数。"** 该比例依赖阶段划分口径，且公开成本普遍不含研发、消融与失败实验[^2^]。正解：成本数字必须连同分母与范围声明一起引用。
5. **"小模型实验结论可直接外推到大模型。"** 排序大体可迁移，数值不可外推；过滤阈值最优点甚至会随算力翻转[^54^][^56^]。正解：小模型做筛子、大模型做复核，分级漏斗而非一次外推。
6. **"合成数据可以替代真实数据。"** 纯合成训练损害知识基准（TQA −14.8）并增加幻觉[^9^]；替换式递归训练导致模型坍缩，累积式"真实 + 合成"才可避免[^61^][^63^]。正解：真实数据做种子与知识锚点，合成数据做增量且须经验证过滤。
7. **"loss 更低 = 下游更强。"** loss→下游映射随验证集、任务、语料三者交互而变，跨语料与跨 tokenizer 比较不可靠[^148^]。正解：同分布内用 loss 做敏感监测，跨配置决策用下游 benchmark。
8. **"WSD 一定优于 cosine。"** 等算力下恒定 LR + cooldown 与调优 cosine 打平[^120^]；GLM-4.5 早期实验发现 WSD 在部分通用基准（SimpleQA、MMLU）上略逊（未给出数据），故弃用 WSD 改用 cosine 调度[^58^]。正解：WSD 的真实优势在工程灵活性（随时分叉衰减），终损优势无共识。
9. **"自动配比搜索必然优于人工配比。"** Aioli 实测 DoReMi、ODM 等此前方法无一稳定跑赢分层抽样基线[^53^]。正解：先立强静态基线，自动方法跑赢基线再采信。
10. **"训练了 X T tokens 可以跨模型直接比较。"** token 计数依赖 tokenizer，同一文本的 token 数可相差近一倍（工程实测口径）[^126^]。正解：冻结 tokenizer 后统一口径，跨模型比较改用 bits-per-byte。

### 11.3 开训前检查清单

下表汇总 14 项开训前检查项，按数据管线顺序排列；每项附验收要点与依据出处，可作为项目评审的 QA gate 逐条核对。

| # | 检查项 | 验收要点 |
|---|---|---|
| 1 | 目标、权利与冻结评测集 | 明确目标能力画像与失败标准；核查语料 license、robots.txt 与删除请求响应机制；dev/held-out 评测集在数据处理前冻结并声明划分 [^13^][^3^] |
| 2 | 不可变 raw lake 与谱系 | 保留 WARC 原始快照的不可变副本与一一映射，记录每步转换的代码版本与参数，支持事后审计与复现 [^16^] |
| 3 | 完整性与 Unicode 规范化 | Unicode NFC 规范化（勿无条件 NFKC 以免破坏数学/东亚文本）、URL 规范化；raw 与 canonical 双份落盘 [^16^] |
| 4 | 专用抽取 | 不用 Common Crawl 官方 WET 文本；trafilatura/resiliparse/justext 自行从 WARC 提取并做小规模消融（可换 2.5+ 分，该数字出自 DCLM 消融中 resiliparse/trafilatura 自提取相对官方 WET 文本的 Core 分收益） [^17^][^16^] |
| 5 | 语言/领域路由 | 用大覆盖语言识别（fastText-176/GlotLID）；过滤阈值按语言标定，警惕困惑度过滤误伤低资源语言 [^5^][^26^] |
| 6 | 规则过滤留 reason codes | 每条启发式记录触发原因码、删除量与样本示例直方图；用高/低质量对照分布定阈值，不照搬 C4 旧阈值 [^16^] |
| 7 | 学习式质量评分级联 | LLM 标注 → 蒸馏小打分器 → 多分类器集成取最大分；对分类器判为高质量的内容跳过后续启发式（避免误删 18% 好数据） [^17^][^18^] |
| 8 | 分层去重、建簇选代表 | URL → exact hash → MinHash/LSH →（必要时）子串去重；每个重复簇保留一篇代表；去重粒度与 epoch 预算联合决策 [^16^][^18^] |
| 9 | 隐私、安全、许可分离处理 | URL 黑名单做域名级粗滤、毒性分类器做句子级删除、正则做 PII 掩码；高阈值防误删非正式文本 [^13^] |
| 10 | 反复去污染 | 对每个要报告的基准做 n-gram + embedding 检查并记录匹配跨度与处置动作；基准更新时重跑，不留一次性心态 [^43^][^44^] |
| 11 | 合成数据 lineage | 记录生成模型、prompt 模板、种子文档与过滤轮次；真实种子做知识锚点；禁止替换式递归生成 [^9^][^61^] |
| 12 | 受约束代理实验优化配比 | 单变量消融 + 多 seed（<2pp 差异单 seed 不可信）；小 proxy 排序 → 大模型复核的分级漏斗，结论只取排序 [^54^][^56^] |
| 13 | 代表性混合上训练并审计 tokenizer | tokenizer 训练语料与预训练配比分布一致；冻结后审计各语言/领域 fertility、bytes-per-token、UNK 率与稀有 token 频次 [^126^] |
| 14 | packing/shuffle/QA gate 与 manifest | Best-fit Packing 减少截断；序列级确定性 shuffle、每 epoch 换 seed、shard 状态入 checkpoint；全部 QA gate 通过后写入数据 manifest 方可开训 [^83^][^126^] |

**解读**：这张清单的结构本身就是本章前三条洞察的工程化映射——第 2–9 项对应"数据工程从过滤转向生产"中的存量治理，第 10–11 项对应评估可信度危机的前置防御，第 12–14 项对应"排序可迁移、数值不可迁移"的分级验证纪律。两个易被忽视的要点值得强调：其一，清单的多数项目（reason codes、谱系、lineage、manifest）不产生任何直接的 benchmark 收益，它们购买的是**出错时的可审计性与可回滚性**——RedPajama 复现 LLaMA-1 仍有差距的案例表明，公开配方缺失的往往正是这些隐性环节[^11^]；其二，清单应按"一次性建设、每轮训练复用"的基础设施来投资，而非逐项目重做——FineWeb 为每个处理步骤跑 1.71B 消融、DCLM 公开全部去污染报告，正是把这种纪律制度化后的产物[^16^][^17^]。

## 12. 延伸阅读

本章按"技术报告—数据集—方法论"三层组织入门与进阶读物，所列为本书论证过程中反复引用、且经交叉核实的一手文献；每条附一句话导读，标明该文献最值得精读的部分。

### 12.1 必读技术报告

- **Llama 3（The Llama 3 Herd of Models）**：全书式技术报告，§3 预训练部分对数据配比退火实验、batch size 三段式调度与"全程极少 loss spike"的稳定性工程记录尤为稀缺 [^5^]。
- **DeepSeek-V3**：长上下文扩展精读报告 §4.3 的两阶段 YaRN 参数表；无辅助损失负载均衡的工程实现见报告架构部分（§2）。两者均为 MoE 大规模训练的标杆性披露 [^2^]。
- **Qwen3**：三阶段预训练（30T 通用→5T 高质量加速衰减→长上下文）的数据组织与 ABF/YaRN 组合策略写得最完整 [^6^]。
- **Kimi K2**：万亿参数级 MoE 用 MuonClip 优化器实现零训练崩溃的实录，§2 训练基础设施与 WSD 日程值得细读 [^10^]。
- **OLMo 2（2 OLMo 2 Furious）**：完全开放数据（Dolmino Mix 1124）、代码与中间 checkpoint，是复现预训练全流程的唯一"全透明"参照系 [^3^]。
- **Phi-4**：合成数据占 40% 配比的设计依据与"纯合成数据损害知识型基准"的负面结论，是合成数据章节的必读一手证据 [^9^]。
- **MiniCPM**：用小模型"模型风洞"外推大模型配置的方法论示范，WSD 调度与衰减阶段混入高质量数据的消融尤为经典 [^113^]。
- **GLM-4.5**：面向智能体、推理与代码（ARC）的统一训练报告，长上下文与强化学习衔接的中训练（mid-training）设计披露较细 [^58^]。

### 12.2 数据集论文

- **FineWeb**：15T token 英文网页数据集，其"以消融实验驱动过滤策略选型"的评估范式已成为数据工程论文的模板 [^16^]。
- **DCLM（DataComp-LM）**：提供受控基准平台，证明分类器式质量过滤在固定算力下的收益上限，适合作为数据筛选实验的基线 [^17^]。
- **Nemotron-CC**：NVIDIA 对 Common Crawl 的长周期精炼管线，重述（rephrase）合成与多阶段去重的组合值得借鉴 [^18^]。
- **Dolma**：AI2 的 3T token 开放语料，论文对逐条过滤规则的消融与风险（毒性、隐私）披露是数据治理写作的范本 [^13^]。

### 12.3 方法论文献

- **Chinchilla**：确立计算最优（compute-optimal）下模型规模与 token 数近似等比扩展的标度律，是训练量规划的理论起点 [^12^]。
- **DoReMi**：用小代理模型学习域权重的开山之作，奠定了"小模型定配比、大模型受益"的研究路线 [^47^]。
- **RegMix**：将数据配比建模为回归问题，用数百次小实验拟合后外推最优混合比例，工程可操作性优于 DoReMi [^49^]。
- **YaRN**：以 10 倍更少的 token 与 2.5 倍更少的步数完成 RoPE 模型的上下文扩展，已成为主流长上下文续训方案 [^127^]。
- **muP（Tensor Programs V）**：最大更新参数化使最优超参（如学习率）在宽度维度近似不变，实现小模型向大模型的零成本调参迁移 [^117^]。
- **MiniCPM（WSD 调度）**：同一篇报告中的 WSD（Warmup-Stable-Decay）学习率调度分析，论证了稳定期长度可灵活裁剪、衰减阶段决定终态质量的机制 [^113^]。
- **Best-fit Packing**：ICML 2024 论文，用最优装箱替代随机拼接截断，在几乎零成本下消除跨文档注意力污染与截断损失 [^83^]。
