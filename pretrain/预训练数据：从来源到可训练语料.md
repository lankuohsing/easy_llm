# 预训练数据：从来源到可训练语料

## 1. 本章范围与核心问题

本章以文本和代码的自回归语言模型为例，讨论如何把网页、论文、书籍、代码库等材料变成用于下一 token 预测的训练语料。图像、音频和视频还涉及各自的解析与质量标准，不在本章展开。这里的“高质量”不是文本天然具有的标签，而是指：在明确的模型目标、训练预算和评测方式下，某种数据选择能带来更好的泛化表现，同时满足来源、隐私等约束。

本仓库已经记录了 [Pile-uncopyrighted 的文件结构、来源和下载方式](./pile-uncopyrighted.md)。下载得到的 `.jsonl.zst` 是**该数据集发布版的原始文件**，并非各网站或论文在被收集前的原始材料；上游可能已经做过抽取或筛选。文件能正常解压，也不等于其中每条文本都适合自己的训练目标。分词算法本身见 [Tokenization 教程](<../tokenization/大语言模型 Tokenization：方法、演进与实践.md>)；本章重点是分词之前和之后的数据决策。

先区分三个常被混用的计量单位：**记录数**是 JSONL 行数，**字节数**取决于编码与压缩方式，**token 数**取决于最终 tokenizer。三者不能直接换算。一条记录可能是很短的问答，也可能是一整篇论文。预训练数据通常也没有统一的“指令—回答”字段，不能按 SFT 数据的格式预设处理规则。

一条便于理解的主线是：确定目标与准入条件 → 确定评估方案并锁定已有划分 → 获取并固化原始版本 → 解析和清洗 → 去重与质量、隐私筛选 → 构造划分或检查跨集重叠、评测污染 → 设计来源配比 → 分词、打包和审计。实际工程会反复调整这些环节；如果数据集已经给出训练、验证、测试划分，应从一开始就锁定划分，不要等所有处理结束后再把文件混合重分。

## 2. 数据搜集：先决定需要什么，再决定抓取什么

### 2.1 来源与覆盖面

搜集的目标不是把能找到的文本全部装进训练集，而是围绕模型预期用途确定语言、领域、时间范围、内容形态和训练预算。广泛的网页文本有助于覆盖话题，专业语料有助于补充代码、数学或特定领域；每类来源也带来不同的偏差和处理成本。The Pile 用多来源组合构建语料；Dolma、FineWeb 则公开了更细的数据处理与筛选选择，可用来比较不同路线 [2][3][4]。

| 来源类型 | 可以提供什么 | 入库前重点核查 |
| --- | --- | --- |
| 网页抓取，如 Common Crawl | 大规模、主题广泛、更新快 | 网页正文抽取、导航和广告残留、重复页面、语言、站点规则与来源记录 |
| 百科、论文、图书、问答等整理语料 | 较稳定的知识文本、长文或专业内容 | 版本和授权范围、PDF 或标记语言解析、引用与公式、领域偏向 |
| 开源代码及技术文档 | 程序语言、API 用法、代码与解释的对应关系 | 仓库和文件许可、密钥、自动生成文件、重复 fork、过期依赖 |
| 自有或获准使用的领域语料 | 贴近目标用户与任务的内容 | 使用权限、个人信息、内部机密、时间和领域代表性 |
| 合成语料（模型或程序生成） | 有针对性地补充教程、代码或练习等稀缺形式 | 生成方法、事实与答案核验、重复、偏差和评测泄漏；详见第 8 节 |

以 Common Crawl 为例，WARC 保存抓取到的网页响应，WET 提供抽取后的纯文本，WAT 提供元数据；选择 WET 意味着接受其上游文本抽取结果，选择 WARC 则需要自己解析网页 [1]。FineWeb 的实验也表明，网页正文抽取方式会改变最终训练语料的效果，不能把“抓取成功”当作“正文已正确取得” [4]。

来源准入应有一份可复查的记录：数据集或网站名称、具体版本或抓取日期、获取地址、许可和使用条款、是否允许再分发、适用语言和领域、可能的个人信息及删除要求。**公开可访问不等于可任意训练或再分发**；也不能仅凭 `uncopyrighted` 之类的数据集名称判断每条记录的权利状态。已有数据集的说明页和各子来源仍需分别核查；Common Crawl 的使用条款也明确要求使用者尊重抓取内容涉及的第三方权利 [12][14]。

### 2.2 固化原始层与来源信息

下载后先保留一份不可随清洗脚本原地覆盖的原始快照。每个分片至少记录：来源与版本、原始 URL、获取时间、split、文件路径、压缩字节数、SHA-256，以及处理脚本版本。校验和只能证明文件与记录的版本一致，不能证明内容质量或使用权限。

处理后的每条文档还需要能够追溯到原始分片和记录位置，例如保留 `source`、`raw_file`、`line_number`、稳定的文档 ID、处理版本、删除原因和最终 token 数。对 Pile-uncopyrighted，`meta.pile_set_name` 是有用的来源标签，但它不等于逐条许可、语言或质量标签。若最终训练格式只剩一条扁平 token 流，应在旁边保存不含敏感正文的审计清单，否则很难解释某类内容为何进入或离开训练集。

## 3. 解析与清洗：先保证文本可用

**解析**把压缩文件、HTML、PDF、代码仓库等变成结构化记录；**清洗**解决编码错误、正文抽取失败、页面模板或格式噪声等问题。它们与“这篇文本是否值得训练”的质量判断有关，但不是同一件事。例如删掉网页导航栏属于清洗；决定一篇完整文章是否符合教育质量标准属于质量筛选。

对已下载的 Pile JSONL，可从流式解压开始，逐行检查 JSON 是否有效、`text` 是否为非空字符串，并记录解析失败数量。对自己抓取的网页，还应确认正文边界，去掉导航、页脚、Cookie 提示、脚本和重复模板。对 PDF 或论文文本，应检查分栏错序、页眉页脚、公式和参考文献是否被误拼接。处理结果要能抽样回看原文，避免一个过于激进的规则把有用内容也删掉。

清洗规则应按来源定制：代码缩进和换行可能承载语义；数学表达式中的符号不能按普通网页噪声删除；聊天、邮件和论坛中的引用链需要识别，但时间戳或角色标记有时也有用。Unicode 规范化、空白折叠、大小写转换等操作要有明确目的，并记录版本。不要为了追求整齐，统一删除非英文字符、所有标点或所有短文本；这会直接改变语言和领域覆盖。

## 4. 去重：减少重复曝光，但保留应有的多样性

同一内容可能以重复 URL、转载页面、代码 fork、论文镜像或稍改标题的形式出现。重复过多会浪费训练预算，并可能增加记忆训练文本的风险。研究发现，对语言模型训练集去重可以改善部分评测和记忆问题 [5]。但“去得越多越好”不是通用结论；FineWeb 对不同去重范围的比较就显示，跨所有抓取批次做更强的近重复去重并未带来更好的结果 [4]。

| 方式 | 典型做法 | 能发现什么 | 主要盲点 |
| --- | --- | --- | --- |
| 精确去重 | 在明确的文本规范化后计算哈希 | 字节相同或规范化后相同的文档 | 标题、空格或少量内容变化即可逃过 |
| 近重复去重 | 用文本片段特征、MinHash/LSH 等寻找高相似文档 | 转载、轻度改写、模板差异 | 阈值太宽会误删同主题但内容不同的文档 |
| 段落或片段去重 | 比较文档内部及文档之间重复的片段 | 大量重复页脚、引用、拼接内容 | 可能误伤常见定义、法律条款或代码模板 |

先做基础解析与规范化，再在训练来源之间查精确和近重复，是常见的起点。具体算法、片段大小、阈值及“保留哪一份”都应通过人工抽样和小规模训练消融校准。记录各来源的删除比例尤其重要：如果某个小语种或小领域被大量删掉，整体重复率下降也可能伴随覆盖损失。已有 `train/val/test` 时，不能为方便去重而重新混合它们；应以保留评估集为原则，从训练集中排除与评估集冲突的内容。

## 5. 质量筛选、隐私与安全

质量筛选回答的是“在有限 token 预算下，哪些可解析文本更值得训练”。公开语料通常把多种信号组合使用，如长度、语言识别、重复行比例、异常字符比例、网页噪声、统计模型或质量分类器；Gopher、Dolma、FineWeb 和 DataComp-LM 给出了不同的规则与实验 [3][4][6][11]。任何单一信号都不是普适的真值。

| 信号 | 适合发现 | 容易误伤或遗漏 |
| --- | --- | --- |
| 长度、字符和重复规则 | 空页、乱码、模板堆叠、机械重复 | 短而有价值的定义、代码、表格和非拉丁文字 |
| 语言识别 | 目标语言覆盖和混合比例 | 短文、混合语言、代码与低资源语言 |
| 困惑度或压缩、统计分数 | 与参照语料差异很大的文本 | 新知识、专业术语或少见语言；低困惑度也可能只是套话 |
| 训练出的质量分类器或模型评分 | 更复杂的结构、教育性等信号 | 继承标注者或教师模型的偏好，且跨领域可能失准 |
| 人工分层审阅 | 发现规则未预见的系统性错误 | 成本较高，必须说明抽样方式和判定标准 |

筛选阈值应按目标和来源校准，而不是全语料共用一个任意常数。可比较保留 30%、50%、70% 等不同强度，但这些数字只是实验设置，不能脱离数据和训练预算当作建议阈值。固定模型、训练 token 数和评测集做对照，并看不同语言、领域的保留率，才能判断筛选是否真正有益。Dolma 特别强调“质量”与有害性定义中的主观选择，并用训练实验检验处理决策 [3]。

隐私和安全是另一条独立检查线。应按来源和用途处理个人信息、邮箱与电话、访问令牌和密码、内部文档、恶意或有害内容；可选删除整条、遮盖片段或限制来源。规则和模型都会漏检与误检，因此要做分层人工抽样，并避免在普通日志中复制敏感正文。即使某些内容公开，也不意味着它适合保留在训练语料里。Dolma 公布了其个人信息和内容过滤策略，可作为可审计做法的例子，而不是所有项目都必须照搬的阈值 [3]。

## 6. 划分、评测去污染与时间边界

**去重**主要处理训练语料本身的重复；**评测去污染**检查训练语料是否含有验证集、测试集或公开基准题目及答案。两者目标不同：训练集内部没有重复，并不能证明模型没有见过评测答案。GPT-3 论文专门检查过公开评测集与训练语料的重叠，说明这一问题在大规模预训练时不能忽略 [7]。

如果从零建立数据集，应在构造评估集时把相同或近似文档作为一组分配，避免同一内容跨 split。如果像 Pile-uncopyrighted 一样已有划分，就保留它的 `train/val/test` 文件边界：从训练集样本拟定清洗与筛选规则，用固定验证集比较候选规则和阈值，把测试集留作最终评估。必要的解析与分词应按事先确定的方式用于各 split，不能选择性删除验证、测试集中的难样本来提高指标。还应检查训练集与验证、测试集之间的精确和近似重叠，并从训练侧处理冲突；自己训练 tokenizer 时，也应避免用测试文本学习词表。

公开基准还需要额外对照题干、答案、代码测试和常见改写。单纯文档哈希查不到部分复制或格式变化；片段匹配与人工复核又要处理常见短句造成的误报。记录基准版本、匹配方法和处置数量，并对所有来源检查，包括代码仓库和合成语料。若要评估新近知识，还应说明训练材料的时间截止点以及评估题目的时间范围；文件下载时间并不等于内容写作时间。

## 7. 来源配比、分词与打包

通过筛选的文档仍需决定如何混合。先用目标模型的 tokenizer 统计各来源可用的 token 数、文档长度分布，再设定训练时的抽样权重；如果 tokenizer 也要从零训练，应先用获准使用的训练语料子样本训练并固定其版本。假设来源 A 有 100 篇、每篇 100 token，来源 B 有 10 篇、每篇 10,000 token：A 占文档数约 91%，却只占 token 数约 9%。因此不能用验证集的记录占比、压缩文件字节数或原始来源数量直接设训练配比。

提高稀缺来源的抽样权重可以增加它的训练曝光，但若独立文档很少，也会让同一文本被反复看见。要同时记录**去重后语料的 token 总量（每篇保留文档计一次）**、**训练中实际读取的 token 总量**和文档重复曝光次数，并用目标能力的评测与通用能力的回归检查配比。DataComp-LM 等工作展示了筛选与混合选择需要在相同训练设置下比较 [6]。

分词后应明确：使用哪个 tokenizer 版本、如何处理文档过长和过短、文档结束符是什么、是否允许多个文档拼进一个训练窗口。把文档串联并插入 EOT 可以告诉模型边界，但**仅有 EOT 并不会自动阻止模型注意到前一篇文档**；如果实验需要严格隔离，还要使用与模型实现一致的 attention mask 或打包策略。不同 tokenizer 得到的 token 数和切分方式不同，所以最终计数应在目标 tokenizer 下完成。

## 8. 合成数据：何时值得加入预训练

合成语料既可以由模型生成，也可以由程序按规则构造。你已下载的 Pile 来源中，`DM Mathematics` 就来自程序生成的数学题与答案；原数据论文说明了先采样答案、再构造题目等方法 [2][13]。TinyStories 用 GPT-3.5/GPT-4 按受控词汇生成短故事，研究小模型的语言能力；phi-1 在预训练中加入模型生成的教科书式代码内容，其另行生成的练习用于后续微调，不能把两部分混算成预训练语料 [8][9]。这些例子说明合成数据可以补足某种内容形态，但不能推出“所有训练语料都应合成”。

还要区分“生成训练文本”与“生成筛选标签”：FineWeb-Edu 用模型提供的教育质量评分训练筛选器，最终被选中的正文仍来自真实网页，并非模型写出的整篇文章 [4]。

较可靠的做法是：先指出真实数据的具体缺口，再写生成规范并保存教师模型、提示词、采样参数和时间，核对生成服务条款与所用材料的权利状态；对可验证任务运行编译、单元测试或答案检查，对事实性内容做来源核查或人工抽样；之后让合成文本经过与真实文本相同的去重、隐私和评测去污染流程，单独标记来源和 token 占比。最后在固定模型与计算预算下比较“无合成”“少量合成”“较多合成”的效果，并检查多样性和原有能力是否回退。

风险包括生成错误被重复学习、教师模型偏好被放大、同质化、生成内容复述受限材料，以及教师已见过基准题导致的间接泄漏。关于递归使用生成数据的研究提出了分布尾部丢失等风险；它不是“任何合成数据都有害”的证明，而是提醒我们保留真实来源、核验与消融 [10]。

“合成”描述内容来源，不直接决定训练阶段。把合成故事或代码作为连续文本做下一 token 训练，属于预训练数据设计；把明确的提问和目标回答组织成监督样本、按回答计算损失，通常属于 SFT。两者的样本组织和评测目的需要分别说明。

## 9. 用已下载的 Pile 设计可审计实验

下面是一份研究路线，不要求先处理完整数据集，也不把已有发布版当作“完全未经处理的网页”。具体文件布局和来源标签见 [Pile-uncopyrighted 笔记](./pile-uncopyrighted.md)。

1. **固定输入**：保留已下载的 `train/`、`val/`、`test/` 原始压缩分片，另行保存数据集版本、每个分片的校验值和本次实验的脚本版本；不要把清洗结果写回原分片。当前下载脚本会校验文件，但不会生成长期保留的清单。
2. **从训练集分层抽样**：按 `meta.pile_set_name`、文本长度和可能的语言抽查原文，记录空文本、格式残留、重复、隐私和领域适配问题。已有笔记中的 17 个来源计数来自验证集，不能当作训练集 token 配比。
3. **建立最小基线**：只做有效 JSON 与非空 `text` 检查、固定 tokenizer 和 EOT，得到可以跑通训练链路的样本；为审计另存原始行与输出 token 区间的映射。该基线不代表已完成质量筛选。
4. **逐项加入处理**：先比较解析与来源特定清洗，再比较精确/近重复去重、质量和隐私筛选；每次只改变一组规则，并保存删除原因。跨 split 冲突从训练侧处理。
5. **制作数据卡和小规模训练对照**：按来源记录保留前后的记录数、按保留文档计的 token 总量、语言与长度分布、各原因删除率、人工抽检误删率及评测重叠数；固定模型、训练 token 预算和验证指标，比较基线与处理后的差异。

你参考的 `train-llm-from-scratch` 项目中，`scripts/data_preprocess.py` 可以读取这种 `train/`、`val/` 分目录的 `.jsonl.zst`，默认每文件最多处理 1,000 条，`--all_data` 才取消该上限。它主要检查记录格式与非空文本，然后用 `r50k_base` 分词、添加 EOT 并写 HDF5；没有实现本章的去重、质量、隐私或基准去污染，也没有保留来源、行号与 token 区间的映射。它适合用作第 3 步的分词基线，但若要满足追溯要求，需扩展脚本或另写旁路清单。项目里的 `scripts/prepare_pretrain_data.py` 则按平铺的原始文件布局自行下载，不能把本仓库下载脚本生成的分目录根路径直接当作其缓存目录。

## 10. 自测问题与参考答案

**问题 1：文件通过 SHA-256 校验，是否说明数据已经“干净”？**

不是。SHA-256 证明当前文件与所核对版本一致；正文抽取是否正确、是否有重复、隐私、许可或评测泄漏，都需要单独检查。

**问题 2：清洗、质量筛选、去重和评测去污染分别解决什么？**

清洗让文本结构可用；质量筛选按训练目标选择内容；去重减少同一或近似内容的重复曝光；评测去污染避免训练文本与留出评测内容重叠。同一条文本可能同时触发多个环节，但原因要分别记录。

**问题 3：近重复阈值越严格、剩下的数据越少，模型就一定越好吗？**

不一定。强去重可能减少无效重复，也可能误删少数语言、专业文本或不同版本。应抽查误删样本，并在相同训练预算下比较模型结果；FineWeb 提供了去重范围影响结果的具体反例 [4]。

**问题 4：为什么不能用验证集的来源记录数决定训练配比？**

验证集可能不是训练集的同分布样本；即使记录比例相同，各来源文档长度也不同。配比至少要以训练集清洗后的 token 数和实际抽样曝光为依据。

**问题 5：低困惑度文本是否必然更适合预训练？**

不是。低困惑度可能表示通顺，也可能是重复模板；高困惑度可能表示乱码，也可能是专业术语、代码或低资源语言。统计分数要和分层审阅、下游评测一起判断。

**问题 6：合成数据只要答案正确，就可以大量加入吗？**

不能只查答案。还要查题目和表述的多样性、与原始材料的重复、教师模型是否见过评测题、不同领域的覆盖和多次曝光。最终用固定预算的消融实验决定比例。

**问题 7：两个文档之间放了 EOT，训练时就完全隔离了吗？**

没有。EOT 是可学习的边界标记；普通因果注意力仍可能访问窗口内前一个文档。需要严格隔离时，必须由数据打包和模型 attention mask 一起实现。
