# 面试准备与项目建设

本专题面向核心大模型团队的**大模型算法工程师（训练与后训练）**岗位。以文本与代码大模型为主，从模型与数据设计、预训练、中训练延伸到 SFT、偏好优化、RL、蒸馏、评测和推理。训练系统与推理问题用于检验算法方案能否落地；各方向的深入程度按目标岗位选择。

本项目有两个相互支持的目标：学习笔记负责把知识讲清楚，面试题负责检验能否解释、验证和运用这些知识。题库是长期建设的选题依据；一个候选人可以有明确主方向，各方向不必同时达到负责人水平。

## 1. 题库与考察方式

[核心大模型团队面试题库](./01_核心大模型团队面试题库.md) 包含 130 道主干题。预训练部分衔接已有的 [61 道专项题](../pretrain/04_预训练面试问题清单.md)，保留原题号与正文。当前只提供问题，不提供答案或逐题评分标准。

主干题按知识主题组织，每题标记一种主要考察层次：

| 标记 | 主要考察能力 | 适合沉淀的学习材料 |
| --- | --- | --- |
| 基础 | 解释问题、机制、概念差别和适用条件 | 背景、概念图景、例子、边界 |
| 推导/验证 | 推导目标、手算、分析张量与数据语义、验证实现 | 公式推导、手算、最小代码与数值检查 |
| 场景 | 提出假设、收集证据、设计对照、诊断异常、权衡预算 | 实验方案、失败分析、评测与决策记录 |

这些标记表示考察方式，不直接对应职级。基础题也可能追问很深；场景题中的资源和数据是面试假设，不是本项目已执行的实验。

问题采用固定题号，例如 `SFT-01`、`RL-01`。现有预训练题在跨专题引用时写作 `PRE-Q01`，对应原文件的 `Q01`。利用编辑器或 GitHub 的大纲浏览主题，利用搜索定位题号。

## 2. 面试官如何选题

一场面试应选择少量问题深入追问。建议从定义与假设出发，再要求推导或验证，最后改变约束，考察结论是否仍成立。场景题可以追问：“还缺什么信息？”“哪个实验最先做？”“什么结果会推翻你的判断？”“预算减半后怎样取舍？”

以下是一次完整模拟面试的四轮安排，每轮约 60 分钟；可以拆开练习。每轮预留约 5 分钟介绍和 5 分钟交流，其余时间只深入讨论选出的题目。

| 轮次 | 选题范围与示例 | 主要目的 |
| --- | --- | --- |
| 第一轮：共同基础 | 从 MATH、ARCH、TOK 选 2 道基础题，再选 1 道推导题和 1 道 CODE 题；如 MATH-03、ARCH-03、TOK-03、CODE-02 | 判断概念是否准确，能否连接数学和实现 |
| 第二轮：主方向 | 后训练方向选 SFT-02、PREF-02、RL-04、RL-07；预训练方向选 PRE-Q02、PRE-Q33、PRE-Q37、PRE-Q46 | 对一个方向持续追问，检验专业深度 |
| 第三轮：实验与诊断 | 选 1 道 EVAL 题与 1 道主方向场景题，最后选 1 道 TRAIN 或 INFER 题；如 EVAL-02、REWARD-04、TRAIN-05 | 判断证据质量、归因能力与工程取舍 |
| 第四轮：项目与综合设计 | 从 PROJ 选 2 道，围绕一个实际项目追问；再从 DESIGN 选 1 道 | 判断个人贡献、结论边界与方案完整性 |

针对预训练算法岗位，加强数据、tokenizer、规模规律和训练稳定性；针对后训练算法岗位，加强监督信号、偏好数据、采样与优化、奖励设计和行为评测。训练系统、推理、多轮工具使用可按岗位职责选做深入题。

## 4. 按当前重点推进

先沿 [RL 学习入口](../rl/00_readme.md) 学习，用 RL-01–RL-09、CODE-04、CODE-05 自检原理与实现；再结合 RL-10–RL-12、REWARD、EVAL-01–EVAL-04 检查训练诊断与评价方式。此时只需补齐用到的数学与 SFT 前置知识。

随后回到 SFT 和 DPO，把“输入如何组织、loss 如何定义、更新怎样改变行为、收益如何验证”串起来；优先补一个带独立评测的最小后训练闭环，并明确哪些结论仍停留在数值核验或规划层面。

评测随每个实验一起建设。之后逐步拓展架构、预训练、中训练和推理专题；蒸馏与 Agentic RL 随实际材料加入。题库不要求在开始做实验前把所有方向读完。

## 5. 用题目维护学习笔记

每次选一个小主题，关联 3–5 道题即可。正文先解释知识，再补自检、例子和验证；详细答案将来放在对应主题中，题库维护题号与材料链接。发现一道题依赖多个主题时，保留其主要归属并关联其他章节。

个人练习记录可采用下列结构，记录真实进度，不必为整套题库预先填表：

| 题号 | 关联正文 | 当前证据 | 下一步 |
| --- | --- | --- | --- |
| 待填写 | 待填写 | 未学习 / 能解释 / 已推导 / 已数值核验 / 已训练验证 | 待补概念、例子、实验或反例 |

记录中的“能解释”与“已验证”可以分别标记。训练验证应补配置、数据与代码版本、指标、对照和失败样本；一个小例子的核验只支持它覆盖的实现语义。后续更新问题时保持题号稳定，并同步更新受影响的索引。
