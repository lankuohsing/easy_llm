# 面试准备与项目建设

本专题面向核心大模型团队的**大模型算法工程师（训练与后训练）**岗位。以文本与代码大模型为主，从模型与数据设计、预训练、中训练延伸到 SFT、偏好优化、RL、蒸馏、评测和推理。训练系统与推理问题用于检验算法方案能否落地；各方向的深入程度按目标岗位选择。

本项目有两个相互支持的目标：学习笔记负责把知识讲清楚，面试题负责检验能否解释、验证和运用这些知识。题库是长期建设的选题依据；一个候选人可以有明确主方向，各方向不必同时达到负责人水平。

## 1. 题库与考察方式

[核心大模型团队面试题库](./01_核心大模型团队面试题库.md) 包含 130 道主干题。预训练部分衔接已有的 [61 道专项题](../pretrain/04_预训练面试问题清单.md)，保留原题号与正文。当前只提供问题，不提供答案或逐题评分标准。

主干题按知识主题组织，每题标记一种主要考察方式：

| 标记 | 主要考察能力 | 适合沉淀的学习材料 |
| --- | --- | --- |
| 基础 | 解释问题、机制、概念差别和适用条件 | 背景、概念图景、例子、边界 |
| 推导/验证 | 推导目标、手算、分析张量与数据语义、验证实现 | 公式推导、手算、最小代码与数值检查 |
| 场景 | 提出假设、收集证据、设计对照、诊断异常、权衡预算 | 实验方案、失败分析、评测与决策记录 |

这些标记表示考察方式。候选人层次另用 L1–L4 标记，见下一节；基础题也可以用于资深候选人的深入核查。场景题中的资源和数据是面试假设，不是本项目已执行的实验。

问题采用固定题号，例如 `SFT-01`、`RL-01`。现有预训练题在跨专题引用时写作 `PRE-Q01`，对应原文件的 `Q01`。利用编辑器或 GitHub 的大纲浏览主题，利用搜索定位题号。

## 2. 候选人层次与回答深度

按承担工作的范围分为四档，不用工作年限、论文数量或参与过的 GPU 规模直接代替能力判断。这是本题库的练习与选题约定，具体招聘职级应结合团队职责。

| 层次 | 候选人定位 | 主要要求 |
| --- | --- | --- |
| L1 | 校招 / 初级 | 概念与假设准确；能完成核心手算或小实现，设计基本检查；说清课程、论文复现或小实验中的个人贡献 |
| L2 | 独立算法工程师 | 能独立完成一个边界明确的训练任务，串起数据、基线、训练、排错、评测与复现；根据对照结果调整方案 |
| L3 | 资深算法工程师 | 能处理跨数据、算法、系统和评测的复杂问题，比较竞争假设、识别混杂、安排实验优先级，说明方法的推广边界 |
| L4 | 技术负责人 | 能把模糊目标转为可执行路线，拆分团队工作与依赖，分配资源，设置阶段决策、风险处置和独立验收，并承担最终取舍 |

主干题和预训练专项题均标记建议起问档：`[L1+]` 表示适合从 L1 起考察，也用于更高层次；`[L2+]`、`[L3+]` 同理；`[L4]` 表示主要用于技术负责人面试。起问档用于筛选题目，实际分层还要看回答深度。主方向以外的题目按岗位职责选择。

### 2.1 各层次的建议选题

每次从下列题目中选 3–4 道深入练习；高层次候选人仍需抽查低档的原理与实现题。以下是代表选题，不是每档的全部考察范围。

| 层次 | 训练与后训练主干选题 | 预训练专项选题 |
| --- | --- | --- |
| L1 | MATH-01、SFT-02、RL-01、RL-04、RL-07、CODE-02、PROJ-01 | PRE-Q02、PRE-Q08、PRE-Q22、PRE-Q40 |
| L2 | SFT-06、PREF-02、RL-09、EVAL-02、CODE-05、PROJ-02 | PRE-Q04、PRE-Q25、PRE-Q42、PRE-Q46 |
| L3 | FLOW-04、SFT-07、RL-10、RL-11、REWARD-04、EVAL-08、DESIGN-01 | PRE-Q24、PRE-Q35、PRE-Q37、PRE-Q56 |
| L4 | FLOW-06、MID-06、DESIGN-02、DESIGN-04 | PRE-Q58、PRE-Q59、PRE-Q60、PRE-Q61 |

### 2.2 同一道题怎样逐层深入

以 SFT-07“领域任务提高、通用能力下降”为例，可按以下方式追问。这里仅调整问题范围，不给出解决方案。

| 层次 | 追问方式 |
| --- | --- |
| L1 | 先描述现象和可能原因。你会查看什么样本、指标或训练配置？怎样验证其中一个判断？ |
| L2 | 你会先做哪项最小对照？固定哪些变量，如何划分数据并复现结果？得到相反结果后怎样调整？ |
| L3 | 如果不同任务切片、检查点和随机种子给出冲突证据，你怎样区分多个解释？剩余预算只够两项实验时怎样排序？ |
| L4 | 这项退化如何影响整个项目的交付？你怎样协调数据、算法与评测工作，调整优先级，并决定继续投入、回滚或验收？ |

SFT-07 的完整题干建议从 L2 起问；对 L1 缩小问题范围，对 L3/L4 增加证据冲突和团队决策约束。其他题也可以这样逐层展开，尤其适合把学习笔记从概念与例子逐步补到实验和综合决策。

L4 选题要继续追问团队执行：每阶段交付哪些证据才进入下一阶段？数据、算法、系统与评测如何分工，接口和关键依赖是什么？团队对结论有分歧时怎样选择下一项实验？谁准备验收证据、谁决定发布、停止或回滚？模型规模较小也可以考察这些责任。

## 3. 面试官如何选题

一场面试应选择少量问题深入追问。建议从定义与假设出发，再要求推导或验证，最后改变约束，考察结论是否仍成立。场景题可以追问：“还缺什么信息？”“哪个实验最先做？”“什么结果会推翻你的判断？”“预算减半后怎样取舍？”

以下四轮是模拟面试结构，表中完整场景选题偏 L3，每轮约 60 分钟；可以拆开练习。L2 按上一节替换为对应起问档的场景题，考察独立闭环；L1 重点讨论原理、小实现和本人项目；L4 保留原理与实现抽查，主方向和综合设计轮加强路线、团队执行与阶段决策。每轮预留约 5 分钟介绍和 5 分钟交流，其余时间只深入讨论选出的题目。

| 轮次 | 选题范围与示例 | 主要目的 |
| --- | --- | --- |
| 第一轮：共同基础 | 从 MATH、ARCH、TOK 选 2 道基础题，再选 1 道推导题和 1 道 CODE 题；如 MATH-03、ARCH-03、TOK-03、CODE-02 | 判断概念是否准确，能否连接数学和实现 |
| 第二轮：主方向 | 后训练方向选 SFT-02、PREF-02、RL-04、RL-07；预训练方向选 PRE-Q02、PRE-Q33、PRE-Q37、PRE-Q46 | 对一个方向持续追问，检验专业深度 |
| 第三轮：实验与诊断 | 选 1 道 EVAL 题与 1 道主方向场景题，最后选 1 道 TRAIN 或 INFER 题；如 EVAL-02、REWARD-04、TRAIN-05 | 判断证据质量、归因能力与工程取舍 |
| 第四轮：项目与综合设计 | 从 PROJ 选 2 道，围绕一个实际项目追问；再从 DESIGN 选 1 道 | 判断个人贡献、结论边界与方案完整性 |

针对预训练算法岗位，加强数据、tokenizer、规模规律和训练稳定性；针对后训练算法岗位，加强监督信号、偏好数据、采样与优化、奖励设计和行为评测。训练系统、推理、多轮工具使用可按岗位职责选做深入题。

## 5. 按当前重点推进

先沿 [RL 学习入口](../rl/00_readme.md) 学习，用 RL-01–RL-09、CODE-04、CODE-05 自检原理与实现；再结合 RL-10–RL-12、REWARD、EVAL-01–EVAL-04 检查训练诊断与评价方式。此时只需补齐用到的数学与 SFT 前置知识。

随后回到 SFT 和 DPO，把“输入如何组织、loss 如何定义、更新怎样改变行为、收益如何验证”串起来；优先补一个带独立评测的最小后训练闭环，并明确哪些结论仍停留在数值核验或规划层面。

评测随每个实验一起建设。之后逐步拓展架构、预训练、中训练和推理专题；蒸馏与 Agentic RL 随实际材料加入。题库不要求在开始做实验前把所有方向读完。

## 6. 用题目维护学习笔记

每次选一个小主题，关联 3–5 道题即可。正文先解释知识，再补自检、例子和验证；详细答案将来放在对应主题中，题库维护题号与材料链接。涉及不同候选人层次时，用少量递进追问说明回答深度，不必将正文复制为四套。发现一道题依赖多个主题时，保留其主要归属并关联其他章节。

个人练习记录可采用下列结构，记录真实进度，不必为整套题库预先填表：

| 题号 | 关联正文 | 当前证据 | 下一步 |
| --- | --- | --- | --- |
| 待填写 | 待填写 | 未学习 / 能解释 / 已推导 / 已数值核验 / 已训练验证 | 待补概念、例子、实验或反例 |

记录中的“能解释”与“已验证”可以分别标记。训练验证应补配置、数据与代码版本、指标、对照和失败样本；一个小例子的核验只支持它覆盖的实现语义。后续更新问题时保持题号稳定，并同步更新受影响的索引。
