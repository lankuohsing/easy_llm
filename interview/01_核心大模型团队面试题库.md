# 核心大模型团队面试题库

面向**大模型算法工程师（训练与后训练）**，以文本与代码模型为主。本文件提供跨专题主干问题；预训练专项复用已有清单。题目的主要考察方式标为“基础”“推导/验证”或“场景”，含义与使用方式见 [面试准备入口](./00_readme.md)。现阶段不提供答案。

题号固定，按主题查阅即可。场景中缺少的信息可以由候选人主动询问或提出假设；估算题应先给出口径。任何关于方法效果的判断，都应说明它依赖哪些条件以及怎样验证。

## 1. 全流程判断与任务定义（FLOW）

- **FLOW-01 [基础]** 预训练、继续预训练或中训练、SFT、偏好优化、RL 和蒸馏分别改变什么？同一训练任务在不同团队被划入不同阶段时，你依据什么描述它？
- **FLOW-02 [场景]** 基模在领域问答上失败，你怎样区分知识缺失、已有知识调用失败、指令遵循不足和外部信息缺失？什么证据支持继续预训练、SFT、RL 或检索方案？
- **FLOW-03 [场景]** 团队只说“让模型推理更强”。你会把目标拆成哪些可测能力，并怎样约定输入、输出、推理预算、评测分布和验收标准？
- **FLOW-04 [场景]** 同一个基模分别经过 SFT、DPO、RL 与组合流程。你怎样设计预算公平的比较，并区分训练算法、数据质量和生成预算带来的收益？
- **FLOW-05 [场景]** 领域继续训练、SFT 和 RL 后，中文能力逐步下降。你怎样定位退化发生在哪一阶段，并选择回滚、数据回放或修改训练目标？
- **FLOW-06 [场景]** 在从头训练、使用现有基模继续训练、蒸馏三个方案之间做选择，你需要哪些质量、数据、算力和部署信息？哪些结果会使你放弃原方案？

## 2. 数学、优化与实验基础（MATH）

- **MATH-01 [推导/验证]** 从自回归序列概率和最大似然出发，推导 token 级交叉熵目标；padding、监督 mask 和变长序列怎样影响归一化及不同样本的权重？
- **MATH-02 [推导/验证]** 给出目标 token 的 softmax 概率，推导交叉熵对 logits 的梯度。使用极端 logits 时，怎样验证实现的数值稳定性？
- **MATH-03 [基础]** 交叉熵、KL 散度和熵分别衡量什么？比较两个分布时，KL 的方向为什么需要明确？训练中哪些估计量容易被误称为 KL 或熵？
- **MATH-04 [推导/验证]** 把一批变长样本拆为多个微批并进行梯度累积时，怎样使更新与整批计算一致？分别考虑 loss reduction、有效 token 数、dropout 与梯度裁剪时机。
- **MATH-05 [基础]** SGD、Adam 和 AdamW 的更新规则有何差别？学习率、权重衰减、梯度裁剪和 batch 大小分别影响哪些量，为什么不能只看最终 loss？
- **MATH-06 [基础]** BF16、FP16、FP32 与 FP8 在表示范围、精度和计算成本上有哪些差别？混合精度训练中哪些张量和累加过程需要单独确认？
- **MATH-07 [推导/验证]** 从目标分布上的期望推导重要性采样估计，需要哪些支持集条件？有限样本、极端权重、归一化或裁剪分别怎样影响偏差与方差？
- **MATH-08 [场景]** 新方法平均提升 1.5 分，训练随机性和采样评测波动均接近 1 分。你怎样安排配对比较、重复实验和结果汇报，区分统计证据与实际价值？

## 3. 模型架构与关键组件（ARCH）

- **ARCH-01 [推导/验证]** 给定 batch、序列长度、隐藏维度和头数，写出 decoder-only Transformer 一层中注意力与 FFN 的主要张量形状，并估算参数量和计算量。
- **ARCH-02 [推导/验证]** 写出 scaled dot-product attention，说明缩放、causal mask 和 padding mask 的作用；构造一个最小例子验证模型没有读取未来 token。
- **ARCH-03 [基础]** MHA、MQA 和 GQA 怎样组织 Q、K、V？它们对参数、训练计算、KV cache 和生成质量的影响如何比较？
- **ARCH-04 [基础]** 绝对位置表示与 RoPE 怎样进入注意力计算？训练长度、位置索引和有效长上下文能力之间是什么关系？怎样检验某种长度扩展方案？
- **ARCH-05 [基础]** 残差连接、Pre-Norm、Post-Norm、RMSNorm 和门控 FFN 分别解决什么问题？更换组件时应固定哪些条件，才能比较稳定性和收益？
- **ARCH-06 [推导/验证]** FlashAttention 改变了哪些计算与访存过程？你怎样验证它与基准注意力实现的输出和梯度一致，并衡量长序列上的时间与显存收益？
- **ARCH-07 [基础]** MoE 的总参数与激活参数分别表示什么？路由、专家负载、容量约束和专家间通信怎样影响训练与部署成本？
- **ARCH-08 [场景]** 同训练预算的 MoE 在评测上更好，但出现专家负载失衡和部署吞吐下降。你怎样组织架构、路由、系统实现与服务负载的对照实验？

## 4. Tokenizer 与数据语义（TOK）

- **TOK-01 [基础]** BPE、WordPiece 和 Unigram 在词表学习与编码选择上有什么差别？字节级表示、规范化和 byte fallback 分别解决什么问题？
- **TOK-02 [推导/验证]** 给定一个小语料、基础符号和若干合并规则，手工执行 BPE 训练与编码。遇到多个可合并位置或未见过的字符串时，怎样确定结果？
- **TOK-03 [推导/验证]** 两个 tokenizer 的解码文本相同，为什么仍需要比较输入 ID、特殊 token、规范化和边界处理？你会构造哪些诊断文本？
- **TOK-04 [场景]** 扩大词表减少了中文 token 数，却增大 embedding 和输出层。你怎样在同训练或服务预算下比较它的质量、吞吐与显存收益？
- **TOK-05 [基础]** EOS、EOT、PAD 和角色标记各自有什么语义？文本中出现标记的可见字符串、tokenizer 识别到特殊 ID、模型生成后停止，分别由哪些环节决定？
- **TOK-06 [场景]** 网页、代码、论文与多语言语料混合时，你怎样制定清洗、去重和采样规则，并检查它们是否改变了目标分布或删除了重要长尾内容？
- **TOK-07 [推导/验证]** 多篇文档或多轮对话被 packing 到同一序列时，怎样定义 attention mask、position IDs、labels 和 loss mask？如何验证边界行为符合任务定义？
- **TOK-08 [场景]** 合成数学或代码数据大量通过格式检查，却使真实任务表现下降。你怎样审计生成、筛选、去污染、重复曝光及难度分布？

## 6. 中训练与继续预训练（MID）

- **MID-01 [基础]** 如何用数据、目标函数、训练位置和产物描述中训练、领域继续预训练与 SFT？面向领域任务时，各阶段的收益分别怎样验证？
- **MID-02 [场景]** 加入医学文献后，领域验证 loss 下降，医学问答没有改善，通用能力下降。你怎样区分数据、学习率、训练目标和评测分布的影响？
- **MID-03 [场景]** 领域语料只有一亿 token，可以重复采样，也可以补充通用或合成数据。你怎样比较配比、曝光次数与遗忘，并确定停止训练的条件？
- **MID-04 [场景]** 将模型上下文从 4K 扩到 32K，你怎样安排位置表示、长度分布、数据组织和训练调度？怎样同时验证短上下文能力和长文档推理？
- **MID-05 [场景]** 两个模型在相同 SFT 后表现不同，你怎样分离中训练数据、训练 token 数、检查点选择和 SFT 超参数适配带来的影响？
- **MID-06 [场景]** 在长上下文扩展、代码强化和领域知识更新之间分配固定继续训练预算，你怎样设计小规模试验、阶段检查点与优先级调整规则？

## 7. 监督微调（SFT）

- **SFT-01 [基础]** SFT 的监督信号与预训练有什么联系和差别？它怎样影响知识、指令遵循、回答格式与推理行为，哪些能力变化需要实验才能判断？
- **SFT-02 [推导/验证]** 给定 system、user、assistant、多轮历史和工具返回，明确哪些 token 参与监督、怎样处理 EOS 与截断，并推导该样本的训练损失。
- **SFT-03 [推导/验证]** “先对每个回答求平均，再对样本平均”和“对全部有效回答 token 平均”怎样改变长短回答的权重？请构造两个变长样本进行手算。
- **SFT-04 [基础]** 全参数微调、LoRA 与 QLoRA 分别训练和保存哪些参数？LoRA 的秩、作用模块及量化配置怎样影响容量、显存与部署？
- **SFT-05 [场景]** 可用数据由少量人工优质回答、大量教师生成回答和用户交互记录组成。你怎样制定来源配比、质量检查、去重与留出策略？
- **SFT-06 [场景]** SFT loss 下降，但模型重复用户输入、提前终止或输出错误角色标记。你按什么顺序检查 chat template、监督区域、EOS 和推理配置？
- **SFT-07 [场景]** 领域 SFT 后任务分数上升，中文写作与通用问答下降。你怎样判断遗忘、数据失衡或评价方式的影响，并设计最小修复实验？
- **SFT-08 [场景]** 在相同预算下比较只监督最终答案与监督完整推理过程，你怎样控制正确率、长度、教师来源和任务难度，并检查泛化与成本？
- **SFT-09 [场景]** 使用拒绝采样选出的正确回答继续 SFT，整体表现提高但回答多样性下降。你怎样调查筛选规则、样本覆盖和训练曝光的作用？
- **SFT-10 [场景]** 一个小模型训练 loss 很低，却在新问题和多轮交互上失败。你怎样区分过拟合、格式迁移失败、基础能力不足和训练实现问题？

## 8. 偏好数据与 DPO（PREF）

- **PREF-01 [基础]** 成对偏好数据、标量奖励与监督示范分别提供什么信息？chosen/rejected、平局、标注冲突和偏好强度应怎样定义与记录？
- **PREF-02 [推导/验证]** 从带参考策略 KL 约束的奖励最大化目标推导 DPO 的成对偏好目标。奖励模型、最优策略表达和偏好似然分别依赖哪些假设？
- **PREF-03 [推导/验证]** 给定 chosen/rejected 在策略与参考模型下的序列 log probability，写出 DPO loss，分析梯度及 beta 的作用；序列长度和 mask 怎样进入实现？
- **PREF-04 [基础]** 当前策略、参考策略和偏好数据生成策略各扮演什么角色？离线数据的覆盖不足、数据过旧或偏好噪声会怎样限制学习？
- **PREF-05 [场景]** chosen 普遍比 rejected 更长，并偏好固定措辞。你怎样构造长度、风格、正确性与内容质量的对照，判断模型实际学到了什么？
- **PREF-06 [场景]** DPO loss 持续下降，偏好对上的相对优势增加，但 chosen 的绝对概率下降。你怎样判断结果是否有益，并检查真实生成行为？
- **PREF-07 [场景]** DPO 后拒答率明显上升，人工偏好胜率也上升。你怎样区分安全收益、过度拒答、任务混合变化与裁判偏差？
- **PREF-08 [场景]** 比较 SFT、DPO 与在线奖励优化时，你怎样固定或核算示范、偏好、奖励标注和生成成本？什么证据支持切换方法？

## 9. 强化学习、PPO 与 GRPO（RL）

- **RL-01 [基础]** 将语言生成写成强化学习问题，明确状态、动作、轨迹、终止条件、奖励与回报。序列级奖励和 token 级决策怎样联系？
- **RL-02 [推导/验证]** 从期望回报推导策略梯度，说明 log-derivative 的使用条件；引入状态相关 baseline 时，需要什么条件才能保持所需梯度期望？
- **RL-03 [推导/验证]** 区分状态价值、动作价值、优势、Monte Carlo 回报与 TD 估计，推导 GAE 的递推；真正终止与达到长度上限的截断应怎样处理？
- **RL-04 [推导/验证]** 写出 PPO 裁剪代理目标，在正、负优势下分别手算概率比为 0.7、1.0、1.3，裁剪范围为 0.8–1.2 的情况，并分析梯度。
- **RL-05 [基础]** PPO 中当前策略、旧策略、参考策略、奖励模型与价值模型分别用于什么？哪些参数冻结，哪些状态必须保存，哪些量需要 detach？
- **RL-06 [推导/验证]** 参考策略 KL、PPO 新旧策略概率比与 entropy bonus 分别约束什么？KL 放入奖励或显式 loss 时，怎样确认实际优化目标与实现一致？
- **RL-07 [推导/验证]** 给定同一 prompt 的奖励为 0、0、1、1，写出你采用的 GRPO 组相对优势定义并手算结果。标准差约定、epsilon 与 detach 应怎样说明？
- **RL-08 [推导/验证]** 同组奖励全部相同，或者一组全部正确、另一组全部错误时，GRPO 的奖励优势项怎样表现？其他损失项是否仍可能产生更新，怎样验证？
- **RL-09 [基础]** PPO 与 GRPO 在优势估计、模型数量、采样组织、显存和计算成本上有哪些差别？什么条件下组内比较能提供有效学习信号？
- **RL-10 [场景]** rollout 使用 temperature、top-p 或 token 屏蔽，训练重新计算 log probability。你怎样定义行为分布和目标策略，检查概率比、支持集及实现记账？
- **RL-11 [场景]** 异步 rollout 导致样本来自旧版本策略，训练奖励快速上升、独立评测停滞。你怎样检查策略滞后、样本复用、概率记账和奖励投机，并设回滚条件？
- **RL-12 [场景]** 增加每个 prompt 的采样数、增加 prompt 数量、增加每批更新次数都能花掉额外预算。你怎样在相同生成与训练成本下比较学习效率？

## 10. 奖励、探索与训练诊断（REWARD）

- **REWARD-01 [基础]** 结果奖励、过程奖励、学习到的奖励模型和 rubric 评分分别适合哪些任务？怎样检查信号噪声、可验证性和训练目标的一致性？
- **REWARD-02 [场景]** 为代码任务设计奖励，只有有限测试用例且执行成本高。你怎样处理部分正确、超时、异常、测试泄漏和投机行为，并维护独立验收？
- **REWARD-03 [场景]** 开放问答包含正确性、完整性、引用、风格和安全要求。你怎样制定 rubric、权重与人工复核方案，检查这些目标之间的冲突？
- **REWARD-04 [场景]** 训练奖励、回答长度同时上升，人工质量下降。你怎样排查长度偏好、格式投机、验证器漏洞和奖励模型分布外误判？
- **REWARD-05 [推导/验证]** 完整词表上的策略熵、采样后的经验多样性和采样 token 的负 log probability 分别是什么？改变温度后怎样保持训练监控口径可比较？
- **REWARD-06 [场景]** 熵持续下降、pass@1 上升、pass@k 停滞。你怎样判断正常收敛和探索不足，并设计控制生成预算与任务难度的干预实验？
- **REWARD-07 [场景]** 提高熵奖励后，回答更随机、更长且正确率下降。你怎样定位奖励尺度、损失归一化、更新幅度与采样配置的作用？
- **REWARD-08 [场景]** GRPO 训练出现大量零奖励方差组。你怎样判断题目过易、过难、奖励粗糙或策略过于集中，并核算筛选与补采样的成本？

## 11. 蒸馏与在线策略蒸馏（DISTILL）

- **DISTILL-01 [基础]** 使用教师生成答案做 SFT、拟合教师 token 分布、使用教师评价以及在线策略蒸馏分别提供什么信号？请先明确你所讨论的 OPD 定义。
- **DISTILL-02 [推导/验证]** 写出教师与学生 token 分布的蒸馏目标，说明 KL 方向、温度、词表支持和监督位置。只有教师采样文本时，哪些信息可以估计？
- **DISTILL-03 [基础]** 教师轨迹与学生自己访问到的前缀分布有何区别？为什么离线教师数据上的拟合程度需要结合学生真实生成行为评价？
- **DISTILL-04 [场景]** 学生和教师使用不同 tokenizer，你怎样设计可实现的蒸馏信号，并确认序列、文本和逐 token 对齐各自支持什么比较？

- **DISTILL-06 [场景]** 比较离线蒸馏、OPD 和学生直接 RL 时，你怎样核算教师调用、学生 rollout、筛选和训练成本，并判断相同预算下的实际收益？

- **EVAL-04 [场景]** LLM judge 偏爱长回答，交换答案顺序后胜率变化。你怎样校准顺序、风格与模型自偏好，检查与人工判断的一致性？

- **EVAL-08 [场景]** 一个数据改动提升数学、损害中文与拒答行为。你怎样设计单因素或多因素实验，确定交互效应，并避免用一个平均分掩盖退化？
- **EVAL-09 [场景]** 公榜领先，真实用户任务成功率下降。你怎样检查任务分布、提示词、工具链、服务截断与评价规则，并建设可持续的回归集？

## 16. 小代码与数值核验（CODE）

以下题目要求写出小型实现和有判别力的检查，允许使用 PyTorch 或基础 Python。目的在于验证训练语义；无需在面试中搭建完整训练框架。

- **CODE-01 [推导/验证]** 实现一个教学版 BPE 的训练、编码与解码，明确合并优先级和基础符号；设计能区分“按规则合并”与“词表最长匹配”的样本。
- **CODE-02 [推导/验证]** 实现带回答 mask 的自回归交叉熵，检查标签移位、padding 和无有效监督 token 的样本；用两条变长序列核对数值与梯度。
- **CODE-03 [推导/验证]** 实现单头 causal attention，分别构造未来 token 改动和 padding 改动，验证哪些位置的输出应保持一致，并与基准实现比较梯度。
- **CODE-04 [推导/验证]** 实现有限轨迹的 GAE，分别处理真正终止与截断；构造两种边界例子和 lambda 端点，核对递推与直接计算。
- **CODE-05 [推导/验证]** 实现 PPO 的裁剪目标与 GRPO 组相对优势，检查正负优势、零奖励方差、变长 mask 和梯度方向；怎样发现分组错误或误 detach？
- **CODE-06 [推导/验证]** 根据策略与参考模型的 chosen/rejected log probability 实现 DPO loss，检查符号、beta、求和范围以及参考模型无梯度。
- **CODE-07 [推导/验证]** 读取带数据源标记的 JSONL 小数据，完成确定性的划分、精确去重和统计；设计重复文档与跨划分重叠样本验证结果。
- **CODE-08 [推导/验证]** 实现一个小型评测汇总器，按题目记录正确性、采样次数、长度和耗时；检查失败请求、分任务切片和配对比较，避免重复计数。
